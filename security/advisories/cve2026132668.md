# CVE-2026-132668 - PEM send\_webhook() lets any PEM user send payloads through any configured webhook

First Published: 2026/11/19

Last Updated: 2026/11/19

## Summary

Any PEM user can run the pem.send\_webhook() function, which runs with elevated privileges and queues a payload for any configured webhook. The PEM agent then delivers it with that webhook's stored headers, OAuth token or client certificate, so a user can send forged notifications to endpoints they could not otherwise authenticate to.

## Vulnerability details

CVE-ID: [CVE-2026-132668](https://nvd.nist.gov/vuln/detail/CVE-2026-132668)

CVSS Base Score: 2.3 Low

CVSS Temporal Score: Undefined

CVSS Environmental Score: Undefined

CVSS Vector: CVSS:4.0/AV:N/AC:L/AT:P/PR:L/UI:N/VC:N/VI:N/VA:N/SC:N/SI:L/SA:N

## Affected products and versions

- Affected Product: Postgres Enterprise Manager (PEM)
- Affected Versions: PEM 8.0.0 and later versions prior to PEM 10.6.1

## Remediation/fixes

Impacted users must upgrade to PEM 10.6.1 or later. From PEM 10.6.1, no PEM login role can call this function directly. PEM still sends webhook notifications through its own internal paths.

| Product | VRMF                                             | Remediation/First Fix         |
| ------- | ------------------------------------------------ | ----------------------------- |
| PEM     | PEM 8.0.0 and later versions prior to PEM 10.6.1 | Update to PEM 10.6.1 or later |

PEM 9.8 is end of life and will not receive a fix. PEM 9.x users must upgrade to PEM 10.6.1 or later.

## Mitigation

Until you can upgrade, reduce exposure as follows:

- Treat PEM webhook notifications as untrusted until you upgrade, especially for endpoints that rely on OAuth or client certificates.
