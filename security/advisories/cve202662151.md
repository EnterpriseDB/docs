# CVE-2026-62151 - mysql\_fdw SQL injection through a multi-byte character set escaping bypass

First Published: 2026/11/25

Last Updated: 2026/11/25

## Summary

mysql\_fdw builds string literals for queries sent to the remote MySQL server with an escaping routine that is not character-set aware. When the connection uses a multi-byte character set such as GBK, SJIS or Big5 and MySQL's default backslash escaping is in effect, a crafted value whose trailing byte is 0x5C absorbs the escaping backslash and leaves the following quote unescaped. The routine handles every pushed-down string constant, including ordinary WHERE-clause literals, so an authenticated user with only SELECT on a foreign table can break out of the literal and run arbitrary SQL on the remote MySQL server with the credentials of the user mapping.

## Affected products and versions

- Affected Product: MySQL Foreign Data Wrapper (mysql\_fdw)
- Affected Versions: mysql\_fdw 2.9.3 and earlier, on all supported PostgreSQL and EDB Postgres Advanced Server versions

## Remediation/fixes

Impacted users must upgrade to mysql\_fdw 2.10.0 or later. From mysql\_fdw 2.10.0, mysql\_fdw forces NO\_BACKSLASH\_ESCAPES into the session sql\_mode and escapes string literals by doubling single quotes.

| Product    | VRMF              | Remediation/First Fix                |
| ---------- | ----------------- | ------------------------------------ |
| mysql\_fdw | 2.9.3 and earlier | Update to mysql\_fdw 2.10.0 or later |

## Mitigation

Until you can upgrade, reduce exposure as follows:

- Avoid GBK, SJIS and Big5 as the character set for mysql\_fdw connections.
- Grant the MySQL account used in user mappings only the privileges the foreign tables need.
