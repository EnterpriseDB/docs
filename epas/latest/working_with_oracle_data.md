# Working with Oracle data

EDB Postgres Advanced Server makes Postgres look, feel, and operate more like Oracle. So when you migrate, there's less code to rewrite, and you can be up and running quickly. The Oracle compatibility features allow you to run many applications written for Oracle in EDB Postgres Advanced Server with minimal to no changes.

- [Enhanced compatibility features](https://www.enterprisedb.com/docs/epas/latest/working_with_oracle_data/02_enhanced_compatibility_features/): Provides an overview of the compatability features included in EDB Postgres Advanced Server that support migrating Oracle applications
- [Querying an Oracle server](https://www.enterprisedb.com/docs/epas/latest/working_with_oracle_data/06_dblink_ora/): How to use the dblink\_ora utility to query a remote Oracle server
- [Using Open Client Library](https://www.enterprisedb.com/docs/epas/latest/working_with_oracle_data/07_open_client_library/): Introduces the EDB OCL Connector, used to compile Oracle Call Interface applications to interact with an EDB Postgres Advanced Server database
- [Including embedded SQL commands](https://www.enterprisedb.com/docs/epas/latest/working_with_oracle_data/embedded_sql_commands/): Overview of using the ECPGPlus utility to embed SQL commands in C applications
- [Loading bulk data](https://www.enterprisedb.com/docs/epas/latest/working_with_oracle_data/loading_bulk_data/): Overview of loading bulk data with EDB\*Loader
- [Protecting proprietary code](https://www.enterprisedb.com/docs/epas/latest/working_with_oracle_data/proprietary_source_code/): Overview of the EDB\*Wrap utility, which you use to protect proprietary source code and programs
