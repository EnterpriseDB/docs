# Postgres Analytics Accelerator (PGAA)

Postgres Analytics Accelerator (PGAA) is a high-performance extension that enables Postgres to query large-scale data stored in open table formats like Delta Lake, Apache Iceberg, and Parquet. By offloading heavy analytical queries to a vectorized execution engine, PGAA bridges the gap between operational databases and data lakes.

### Get started

- [Compatibility](https://www.enterprisedb.com/docs/pgaa/1.9/overview/compatibility/): Check supported PostgreSQL versions, operating systems, and other requirements.

- [Architecture](https://www.enterprisedb.com/docs/pgaa/1.9/overview/architecture/): Understand the core architecture and how the vectorized engine works.

- [Core concepts](https://www.enterprisedb.com/docs/pgaa/1.9/overview/concepts/): Understand the fundamental principles of vectorized execution, data lake integration, and DirectScan.

- [Quickstart guide](https://www.enterprisedb.com/docs/pgaa/1.9/overview/quick_start/): Install PGAA, create a storage location and read table from our sample benchmark datasets.

### Using PGAA

- [Installation](https://www.enterprisedb.com/docs/pgaa/1.9/installing/): Step-by-step instructions for installing the extension and enabling the Seafowl background worker.

- [Read from object storage](https://www.enterprisedb.com/docs/pgaa/1.9/read_no_catalog/): Connect directly to S3, GCS, or Azure Blob Storage to query Parquet, Delta, or Iceberg files using a PGFS storage location.

- [Read using Iceberg catalogs](https://www.enterprisedb.com/docs/pgaa/1.9/catalog/): Integrate with external Iceberg REST catalogs to manage table metadata.

- [Write to object storage using CTAS](https://www.enterprisedb.com/docs/pgaa/1.9/ctas/): Use `CREATE TABLE AS SELECT` (CTAS) to export Postgres data into optimized lakehouse formats in your object store.

### Replicating with PGD

- [Replicating with PGD:](https://www.enterprisedb.com/docs/pgaa/1.9/pgd/) Combine PGD and PGAA to manage the complete data lifecycle, from automated partition offloading and real-time replication to surgical archival of cold data in object storage.

### Performance & optimization

- [Accelerate with Spark](https://www.enterprisedb.com/docs/pgaa/1.9/spark/): Offload massive datasets and complex distributed joins to a remote Spark cluster via Spark Connect. PGAA offers two integration modes depending on your performance requirements:

  - [Standard Spark integration:](https://www.enterprisedb.com/docs/pgaa/1.9/spark/spark-only/) Leverage a remote Spark cluster for high-concurrency analytical queries and distributed processing.

  - [GPU-Accelerated Spark](https://www.enterprisedb.com/docs/pgaa/1.9/spark/spark-rapids/): Integrate with the NVIDIA RAPIDS Accelerator for Apache Spark to leverage GPU acceleration.

- [Monitor and maintain your analytical tables](https://www.enterprisedb.com/docs/pgaa/1.9/monitoring/): Audit storage utilization, monitor table health, and perform table maintenance tasks for PGAA-managed tables.

- [Optimize query performance](https://www.enterprisedb.com/docs/pgaa/1.9/optimize_performance/): Maximize query speeds by managing DirectScan execution, configuring compute pushdowns, and troubleshooting path fallbacks.

### Operations

- [Backing up and restoring](https://www.enterprisedb.com/docs/pgaa/1.9/backup_restore/): Back up and restore PGAA analytical tables using Barman, with restore procedures for standalone Postgres and PGD deployments.

- [Functions](https://www.enterprisedb.com/docs/pgaa/1.9/reference/functions/): PGAA introduces a suite of SQL functions for administrative tasks, such as mapping new tables, monitoring storage health, and launching maintenance background jobs.

- [Table options](https://www.enterprisedb.com/docs/pgaa/1.9/reference/table_options/): When mapping or creating analytical tables, specific options allow you to define how data is read from or written to your object store.

- [Data types](https://www.enterprisedb.com/docs/pgaa/1.9/reference/data_types/): PGAA maps native Postgres data types to optimized columnar formats in the data lake.
