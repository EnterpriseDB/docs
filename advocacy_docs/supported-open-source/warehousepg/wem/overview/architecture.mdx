The WarehousePG Enterprise Manager (WEM) architecture is built upon a streamlined telemetry pipeline: an internal data collection layer, ClickHouse-backed storage, and the unified WEM application. Starting with WEM 1.3, a host agent component enables privileged operations on WarehousePG coordinator hosts through WEM's internal job-execution engine. Starting with WEM 1.4, every connection between a host agent and WEM authenticates with mutual TLS (mTLS), and host agents register themselves with WEM automatically instead of requiring manual enrollment.

## Components

### OTel Collector

The OTel Collector (`edb-otelcol`) is an OpenTelemetry (OTel) Collector service that runs alongside the host agent on the WarehousePG (WHPG) coordinator, standby, and segments. Each node's collector gathers host metrics and tails the WHPG log files, then forwards this telemetry to a gateway collector, which writes it into ClickHouse.

By default, WEM designates the standby coordinator as the primary gateway and the coordinator as its failover, and dispatches the collector's configuration to each host agent as it registers. If ClickHouse and WEM run on a dedicated host instead, outside the cluster, that host is the gateway, set explicitly through `OTEL_GATEWAY_ENDPOINT`. See [Installing ClickHouse](../installing/observability-stack) for both topologies.

### Host agent

The host agent (`acp-host-agent`) is a background service that runs on the WarehousePG coordinator host and executes privileged operations, such as editing `pg_hba.conf` and starting the OTel Collector, on behalf of WEM. WEM dispatches these operations through its internal job-execution engine, which ensures they're reliable and recoverable even when connectivity is interrupted.

The host agent is installed on every WarehousePG node, coordinator, standby, and segments alike. On first connection, an agent registers itself with WEM and waits in a pending state until an Admin approves it from the **Host Agents** tab. Every connection between an approved agent and WEM authenticates with mutual TLS: WEM's internal certificate authority issues each agent a short-lived certificate and renews it automatically, with a 24-hour grace window that lets an agent that was briefly offline recover its certificate without Admin intervention. WEM doesn't use host agent features unless both the host agent and WEM's internal job-execution engine are running and connected. See [Installing the host agent](../installing/host-agent).

### WEM

WEM is the central management and visualization service.

WEM performs the following core functions:

- **Database extraction:** An integrated engine runs SQL queries against heap and catalog tables to capture real-time database metrics, independent of ClickHouse.
- **Metrics and log queries:** WEM queries ClickHouse for host metrics, SQL and cluster metrics, and WHPG logs collected by the OTel Collector, and uses the same data to evaluate alert rules.
- **Unified visualization:** Aggregates live data directly from the internal database extraction engine and historical data from ClickHouse into a single dashboard.

### Storage: ClickHouse

WEM queries ClickHouse for all historical metrics and log data. ClickHouse isn't bundled with WEM, and configuring it is entirely up to you. Deploy it on the same host as WEM, either the standby coordinator or a dedicated monitoring host outside the cluster, or point WEM at an existing instance you already manage elsewhere. See [Installing ClickHouse](../installing/observability-stack).

!!! Note
    While WEM can function as a standalone tool, its capabilities are limited to real-time cluster status and SQL execution data. Historical trends, host-level metrics, and log search require ClickHouse.

## WEM operational workflow

The system processes telemetry across four distinct phases:

1. **Collection:** The OTel Collector on every node harvests raw OS metrics and tails WHPG log files.

2. **Export and routing:**
    - **System metrics and logs:** Each node's OTel Collector forwards its telemetry to the gateway collector, which writes it into ClickHouse.
    - **Database metrics:** WEM's internal database extraction engine probes the WHPG engine directly to capture the real-time state of queries, transactions, and resource usage, independent of the ClickHouse pipeline.
    - **Privileged host operations:** When WEM triggers a host-level action, such as updating `pg_hba.conf` or starting the OTel Collector service, WEM dispatches the request to the host agent through its internal job-execution engine, which tracks the operation and retries automatically if the connection is interrupted.

3. **Storage:** Metrics and logs are indexed and stored in ClickHouse. This ensures that even if the database cluster faces downtime, its historical metrics and logs remain available for root-cause analysis.

4. **Visualization:** WEM assembles the operational picture by pulling from two sources:
    - **ClickHouse:** For hardware performance, historical SQL trends, and searchable log files across the cluster.
    - **Database extraction engine:** For the real-time view of active sessions and current cluster status.
