Use the **FlowServer** panel on the left sidebar to manage the jobs that load streaming data from Kafka or RabbitMQ into WarehousePG (WHPG) tables. Create a job from a FlowServer job configuration file, start it with the offset you want, watch its progress, and stop or remove it, without running `flowcli` on the coordinator host. WEM runs each action through the host agent on the coordinator.

For how FlowServer works, how to build a job configuration file, and how to use `flowcli` instead, see [Loading data with FlowServer](../flowserver/loading/).

## Before you begin

- FlowServer is installed and running on the coordinator host. WEM supports `whpg7-flow-server` 1.1.1 and `whpg6-flow-server` 1.1.0. Run one FlowServer per cluster, on the coordinator, and install the package on every host, because the segments need it to load data. WEM can't manage a FlowServer that runs on another host, such as the standby or a dedicated host. See [Installing FlowServer](../flowserver/installing).
- Your Kafka or RabbitMQ source, the target database, and the target table already exist. WEM doesn't create them.
- The target table exists, and the role the job uses has the privileges it needs. See [Creating the target table and configuring role privileges](../flowserver/loading/target_table).
- The host agent on the coordinator is a version that supports FlowServer (`acp-host-agent` 1.2.0 or later). If it isn't, the **Jobs** tab shows a warning asking you to upgrade it. See [Installing the host agent](installing/host-agent).
- The FlowServer address in WEM matches where FlowServer listens, as seen from the coordinator. The default is `localhost:6060`. See [Configuring the FlowServer connection](#configuring-the-flowserver-connection).

!!! Note
    WEM manages jobs through FlowServer's own interface and shows what FlowServer reports. It doesn't replace the FlowServer configuration file, which you still write yourself.

    The host agent talks to FlowServer over plain-text gRPC, because FlowServer 1.1.1 has no TLS or authentication. Keep the FlowServer port reachable only from the coordinator host.

### Permissions

Access to the **FlowServer** panel follows the WEM role-based access control model. By default, Admin and Operator users can view jobs and perform every action. Viewers can view jobs and their activity, but can never create, start, stop, or remove a job. You can change these defaults for Admin and Operator profiles in **Management** > **Permissions**. See [Defining role-based access control](system-access/management#defining-role-based-access-control).

| Action | Description | Viewer |
|--------|-------------|--------|
| Create Job | Validate and submit a job | Not allowed |
| Start Job | Start a job | Not allowed |
| Stop Job | Stop a running job | Not allowed |
| Remove Job | Remove a job | Not allowed |

An action that you don't have permission for is disabled, and its tooltip names the permission it needs.

## Reviewing jobs

The **Jobs** tab lists every job FlowServer knows about and refreshes automatically. WEM polls faster while a job you just started is running.

- Filter the list with the search box, or with the **All Sources**, **All Statuses**, and **All Target Tables** dropdowns.
- Review each job's **Job Name**, **Source** (the Kafka topic or RabbitMQ queue), **Status**, **Target** table, and **Status Changed** time. A job that writes to several tables shows the first one and the rest in a tooltip. Use the column selector to show or hide columns.
- The **Status** column shows the status FlowServer reports: **Submitted**, **Running**, **Stopped**, **Error**, **Done**, or **Unknown**. A job that is starting shows **Preparing** while FlowServer checks its configuration and the target table.
- Open the **Actions** menu for a job to **Start**, **View Details**, **Stop**, or **Remove Job**. Menu items that don't apply to the job's current state are disabled, and a tooltip explains why.

If WEM can't reach FlowServer, or the host agent on the coordinator is offline or too old, a warning at the top of the tab says so and the list is empty. Check that FlowServer is running, that the [FlowServer address](#configuring-the-flowserver-connection) is correct, and that the host agent on the coordinator is registered and running. See [Managing host agent registrations](system-access/management#managing-host-agent-registrations).

## Creating a job

1. On the **Jobs** tab, select **Create Job**.
1. In **Job YAML**, paste the FlowServer job configuration, or select **Load File** to load a `.yaml` or `.yml` file. The configuration can't be empty or larger than 256 KB.
1. In **Job Name**, enter a name. When you load a file, the name defaults to the file name without its extension. A name can have up to 63 letters, digits, underscores, periods, or hyphens, and must start with a letter or digit.
1. Select **Validate** to check the configuration before you create the job. WEM also validates when you select **Create**.

    - If the configuration has problems, WEM lists them under **Fix these problems before creating the job**, with line numbers where it can. Correct the YAML and validate again.
    - If a job with the same source and target already exists, WEM warns you that FlowServer removes that job when you create this one. If that job is running, WEM reports an error instead, and you must stop the existing job first.
    - If the configuration is valid, WEM shows **The job configuration is valid** with the job's source and target.

1. Select **Create**.

Creating a job doesn't start it. Start it from the **Actions** menu.

!!! Note
    WEM masks passwords and other credentials in the job configuration it shows, such as `password` values, `sasl.jaas.config` passwords, and credentials in RabbitMQ server URLs. WEM hides the whole configuration if it can't verify that the credentials are masked.

## Starting a job

1. In the **Actions** menu for the job, select **Start**.
1. For a Kafka job, choose where the job starts reading under **Offset**:

    | Option | Behavior |
    |--------|----------|
    | **Continue from where this topic and table left off** (default) | The first start reads every message still in the topic. Later starts continue from where the job stopped. |
    | **Earliest offset in the topic** | Loads every message still in the topic again. Rows that were already loaded are inserted again unless you empty the table first or the job uses merge mode. |
    | **Latest offset (new messages only)** | Skips the messages already waiting in the topic. |
    | **From a point in time** | Loads the messages produced at or after a time you choose. Pick a time in the past, in the server's time zone. Messages after that time that were already loaded are loaded again. |

    Offset options apply to Kafka jobs only. A RabbitMQ job reads the next messages in its queue, and the options are disabled.
1. Optionally, select either of these options:

    - **Stop at End of Data:** Stops the job when no new messages arrive for about 3 seconds (`eof.after.idle` in the job file). Use it to load a fixed set of messages and finish.
    - **Skip Explain:** Skips the SQL check at start so the job starts faster. Configuration errors, such as a missing table or column, then show only after the job starts.

1. Select **Start Job**.

WEM shows the job as **Preparing** while FlowServer validates it, then **Running**. If the start fails, WEM shows a notification with the reason and, where it recognizes the error, a hint.

## Monitoring a job

Select **View Details** in a job's **Actions** menu to open **Job Details**.

- **General Information** shows the job's name, status, when the status changed, and FlowServer's status message.
- **Source and Target** shows the source type (Kafka or RabbitMQ), the topic or queue, the database server, the database, the target table or tables, and the error limit.
- **Progress** shows the messages in the last batch, the rows affected since the job was submitted, the rows rejected since the last start, and when WEM last received progress. While the job runs, the dialog refreshes every few seconds.
- **Configuration** is collapsed by default. Expand it to read the job configuration with credentials masked, or select the copy icon to copy it.

!!! Note
    FlowServer reports progress only at the moment a batch finishes and keeps no history. WEM shows the batches that finish while it's watching, so a job you haven't watched shows **No progress yet** until its next batch.

When a job fails, **Job Details** shows **The job failed**, or **The last start failed** if the start was rejected, with FlowServer's error message. Where WEM recognizes the cause, it adds a hint:

| Error | What to do |
|-------|------------|
| Segment reject limit reached | The `error_limit` applies to each segment. WEM rolled back the whole batch, and the bad messages are still in the queue or topic. Raise `error_limit` or remove the bad messages. For Kafka, starting from the latest offset skips them, but also skips the good messages behind them. |
| `gpfdist` connection refused | Segments couldn't reach the FlowServer `gpfdist` port. Check the `gpfdist` host in the FlowServer configuration. |
| RabbitMQ channel or connection isn't open | Check the RabbitMQ user, password, and vhost. |
| Host not found or connection refused | Check the broker address in the job file, and that the coordinator can reach it. |
| Unknown topic or partition | The topic doesn't exist. FlowServer doesn't create topics. |
| No queue | The RabbitMQ queue doesn't exist. FlowServer doesn't create queues. |
| Unknown member ID | The Kafka broker restarted recently. Wait about a minute, then start the job again. |
| Failed to parse offset reset timestamp | Use a timestamp with milliseconds, such as `2026-10-19T07:30:00.000Z`. |
| Relation or column doesn't exist | Check that the target table and the mapped columns exist. |

After you fix the cause, start the job again.

## Stopping and removing a job

- To stop a running job, select **Stop** in its **Actions** menu and confirm with **Stop Job**. FlowServer stops reading from the source, and you can start the job again later. You can't stop a job while it's preparing.
- To remove a job, select **Remove Job** and confirm. You can only remove a job that isn't running, so stop it first. For a Kafka job, FlowServer also removes its consumer group. The load position stays in the target database, so a new job for the same topic and table continues from where this one stopped. Removing a job can't be undone.

## Reviewing job activity

Use the **Activities** tab to trace every create, start, stop, and remove action requested through WEM.

- Review each action's **Action**, **Status**, **Job**, **Description**, **Requested** time, **Requested By** user, and **Duration**. Use the column selector to show or hide columns.
- Expand a row to see when the action completed, the start options you chose, FlowServer's message, and the error if the action failed.

WEM keeps finished actions for 168 hours (one week) by default. See the [FlowServer settings](#configuring-the-flowserver-connection).

## Configuring the FlowServer connection

Set the FlowServer connection in **Management** > **Settings**, in the **FlowServer** group of the runtime settings. Changes apply when you save them, with no WEM restart.

| Setting | Default | Description |
|---------|---------|-------------|
| **FlowServer Address** | `localhost:6060` | The `host:port` where FlowServer listens, as seen from the coordinator. |
| **Activity Retention** | `168` hours | How long WEM keeps finished actions in the **Activities** tab. |

See [Configuring WEM](configuring) and [Runtime settings](reference/configuration#runtime-settings).
