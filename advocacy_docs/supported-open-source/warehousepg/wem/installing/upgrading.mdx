Upgrade to WEM 1.4 from 1.3, or directly from 1.2. WEM 1.4 replaces Prometheus and Loki with ClickHouse as the metrics and log pipeline. See the [1.4 release notes](../release_notes/1.4_rel_notes) for the full list of changes.

## Before you upgrade

- Export or archive any historical metrics and logs you need to keep from Prometheus and Loki. Switching to ClickHouse doesn't carry over existing telemetry, so they become unavailable in WEM once you complete the upgrade. See Prometheus's [TSDB admin API](https://prometheus.io/docs/prometheus/latest/querying/api/#tsdb-admin-apis) for taking a snapshot, and Loki's [storage documentation](https://grafana.com/docs/loki/latest/operations/storage/) for backing up the underlying chunk and index store, Loki itself has no separate export feature.

- If you're upgrading from 1.2, shut down any separately installed Alertmanager configured through the now-removed `ALERTMANAGER_URL` parameter. Since 1.3, WEM bundles its own instance of Alertmanager, and leaving an existing one running on the same host can block it from starting.

- If you're upgrading from 1.2, note down any custom alert rules from WEM's previous Prometheus rule files, they're lost once those files are removed, and recreate them through the **Rules** tab after upgrading. See the [1.3 release notes](../release_notes/1.3_rel_notes) for the full list of changes 1.3 introduced.

- Note down any **User** alert rules from the **Rules** tab before upgrading. Upgrading removes Prometheus, where these rules are stored, so they're deleted rather than migrated. Recreate them afterward. **System** rules and alert history aren't affected. See [Creating and managing alert rules](../monitoring/alerts#creating-and-managing-alert-rules).

## Installing ClickHouse and the gateway collector

Install ClickHouse and, if your deployment needs one, the gateway collector, before you upgrade WEM. See [Installing ClickHouse](observability-stack) and [Installing the gateway collector](collector) for the placement options and when each component is required.

## Upgrading WEM

Upgrade WEM from the host where it's installed, either inside your WHPG cluster or on a dedicated host.

1. Configure the EDB repository:

    ```bash
    export EDB_SUBSCRIPTION_TOKEN=<your-token>
    export EDB_REPO=gpsupp
    curl -1sSLf "https://downloads.enterprisedb.com/$EDB_SUBSCRIPTION_TOKEN/$EDB_REPO/setup.rpm.sh" | sudo -E bash
    ```

1. Upgrade the WEM package:

    ```bash
    sudo dnf upgrade whpg-enterprise-manager
    ```

1. The upgrade preserves your existing `wem.conf` and creates a new `wem.conf.rpmnew` file matching the 1.4 schema. Make that new file your configuration, keeping the old one for reference:

    ```bash
    cp /etc/wem/wem.conf /etc/wem/wem.conf.old
    cp /etc/wem/wem.conf.rpmnew /etc/wem/wem.conf
    ```

    Open the new `/etc/wem/wem.conf` and replace, as a minimum, the following variables with your values from `wem.conf.old`:

    - `WHPG_HOST`, `WHPG_PORT`, `WHPG_DATABASE`, `WHPG_USER`, `WHPG_PASSWORD`
    - `WEM_HOST`, `WEM_PORT`, `WEM_DATABASE`, `WEM_USER`, `WEM_PASSWORD`
    - `WEM_COOKIE_SECRET`
    - `WEM_INSECURE_COOKIES`, if you don't serve WEM over HTTPS
    - `CLICKHOUSE_URL`
    - `OTEL_GATEWAY_ENDPOINT`, if your deployment needs a [dedicated gateway collector](#installing-clickhouse-and-the-gateway-collector).

    See [Configuring WEM](wem/#configuring-wem) for the complete list of configuration parameters and what each one does.

    If the app-state database was repointed or restored, WEM also requires `WEM_ADMIN_PASSWORD` or `WEM_ADMIN_PASSWORD_FILE` to complete setup non-interactively. See [Installing WEM](wem#setting-the-administrator-password).

1. Restart the WEM service to apply the update:

    ```bash
    sudo systemctl restart wem
    ```

1. Verify the installed version:

    ```bash
    rpm -q whpg-enterprise-manager
    ```

1. Clear your browser cache or open WEM in a new browser session. After an upgrade, stale session data can cause a CSRF token error on first login.

## Upgrading the host agent

From WEM 1.4, the host agent (`acp-host-agent`) runs on every cluster node in your WarehousePG (WHPG) cluster. It depends on `edb-otelcol`, the OTel Collector, which replaces the Alloy-based WHPG Collector. Segment hosts are always a fresh install, since they never ran the host agent before 1.4 either way. The coordinator (and standby, if you have one) is either an upgrade, if you're coming from 1.3, or a fresh install, if you're coming from 1.2.

1. On the coordinator, download the host agent package and its `edb-otelcol` dependency from the EDB repository:

    ```bash
    export EDB_SUBSCRIPTION_TOKEN=<your-token>
    export EDB_REPO=gpsupp
    curl -1sSLf "https://downloads.enterprisedb.com/$EDB_SUBSCRIPTION_TOKEN/$EDB_REPO/setup.rpm.sh" | sudo -E bash
    sudo dnf download edb-acp-host-agent edb-otelcol
    ```

1. From the coordinator, transfer both packages to every host in the cluster:

    <TabContainer syncKey="whpg-version">
    <Tab title="WHPG 7">

    ```bash
    gpsync -f all_hosts edb-acp-host-agent-*.rpm edb-otelcol-*.rpm =:/tmp
    ```

    </Tab>
    <Tab title="WHPG 6">

    ```bash
    gpscp -f all_hosts edb-acp-host-agent-*.rpm edb-otelcol-*.rpm =:/tmp
    ```

    </Tab>
    </TabContainer>

1. From the coordinator, install both packages on every host. Installing the local `.rpm` files upgrades the existing installation wherever the host agent is already present (the coordinator and standby coordinator, coming from 1.3) and installs fresh everywhere else:

    ```bash
    gpssh -f all_hosts -u gpadmin -e "sudo dnf install -y /tmp/edb-acp-host-agent-*.rpm /tmp/edb-otelcol-*.rpm"
    ```

1. Set `WEM_CONNECT_ADDRESS` in `/etc/edb/acp-host-agent/acp-host-agent.conf` to WEM's IPv4 address and listen port plus 1 (default 8081) on every freshly installed host, segment hosts always, and the coordinator and standby coordinator if you're coming from 1.2:

    ```bash
    WEM_HOST=<wem-host-ipv4>
    gpssh -f all_hosts -u gpadmin -e \
      "sudo sed -i 's/^WEM_CONNECT_ADDRESS=.*/WEM_CONNECT_ADDRESS=${WEM_HOST}:8081/' \
        /etc/edb/acp-host-agent/acp-host-agent.conf"
    ```

1. Restart the service on every host so it reconnects using the self-registration and mTLS flow:

    ```bash
    gpssh -f all_hosts -u gpadmin -e "sudo systemctl restart acp-host-agent"
    ```

1. In WEM, go to **Management > Host Agents** and approve any agent that appears in a pending state.

## Migrating the Prometheus metrics endpoint

Prometheus scraping now splits across two endpoints instead of one combined feed:

- **WEM metrics:** Prometheus continues to scrape WEM's own metrics from `/prom/metrics`, unchanged.
- **WHPG, SQL, and system metrics:** Configure `OTEL_PROMETHEUS_SCRAPE_ENDPOINT=<host:port>` in `wem.conf` instead, so the OTel Collector exposes these metrics for Prometheus to scrape directly.

If your existing Prometheus configuration scrapes `/prom/metrics` for WHPG, SQL, or system metrics, update it to scrape the new `OTEL_PROMETHEUS_SCRAPE_ENDPOINT` address instead. See [Metrics reference](../reference/metrics) for the full list of available metrics.

## After you upgrade

- To list, restore, report on, or delete backups from the **Backups** panel, upgrade `whpg-backup` to 1.34 or later on every cluster node. Older versions can still take and schedule backups. See [Installing WarehousePG Backup and Restore](https://www.enterprisedb.com/docs/supported-open-source/warehousepg/whpg-backup/installing/#upgrading).
- Stop and disable the old WHPG Collector (the `alloy` service) on every cluster node, along with any Prometheus or Loki instances you ran solely for WEM:

    ```bash
    gpssh -f all_hosts -u gpadmin -e "sudo systemctl disable --now alloy"
    ```

## Next steps

Your upgrade is complete. See [Getting started with WEM](../get-started).
