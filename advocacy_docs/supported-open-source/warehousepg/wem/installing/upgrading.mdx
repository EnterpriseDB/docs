Review the section for the version you're upgrading to before running any upgrade commands. Some of these changes need action on your part beforehand, not just awareness.

## Before you upgrade

### Upgrading to 1.4

WEM 1.4 fully migrates the metrics and log pipeline from Prometheus and Loki to ClickHouse, and the WHPG Collector is replaced by an OTel Collector that runs as part of the host agent on every cluster node. Complete these steps before upgrading:

1. Install ClickHouse. See [Installing ClickHouse](observability-stack). If you're consolidating telemetry from multiple clusters onto one ClickHouse instance, also install the [gateway collector](collector).

1. In `/etc/wem/wem.conf`, plan to add `CLICKHOUSE_URL`, required in 1.4, and remove `PROMETHEUS_URL`, `LOKI_URL`, `LOKI_TENANT_ID`, `METRICS_BACKEND`, every `WEM_EXPORTER_*` parameter, and every `WEM_REMOTE_WRITE_RECEIVER_*` parameter, all of which no longer exist in 1.4. If you set `OTEL_GATEWAY_ENDPOINT` for a dedicated or shared ClickHouse deployment, add that too. See [Configuration reference](../reference/configuration).

1. The host agent (`acp-host-agent`) now installs on every cluster node, coordinator, standby coordinator, and segment hosts alike, instead of only the coordinator and standby coordinator. Plan to install it on every segment host as part of this upgrade. See [Installing the host agent](host-agent).

1. Every host agent connection now authenticates with mutual TLS (mTLS), and agents self-register with WEM instead of relying only on a manually configured task queue. After upgrading the host agent package, check the **Host Agents** tab in **Management** and approve any agent that appears pending.

1. PXF management moves from the **External Tables** tab to its own **PXF** tab in **Data Analysis**, and dispatches through the host agent on the coordinator instead of running locally on the WEM host. If you set `WHPG_PXF_BIN`, `WHPG_PXF_BASE`, or `WHPG_OS_USER` in `wem.conf`, remove them, since none of these parameters exist in 1.4. Install the host agent on the coordinator if it isn't already, and PXF management works regardless of where WEM itself runs. See [Managing PXF](../performance/data-analysis#managing-pxf).

1. To take, restore, or schedule backups from the **Backups** panel, upgrade `whpg-backup` to 1.34 or later on every cluster node. An older `whpg-backup` still works for reviewing existing backup history, but taking or restoring a backup from WEM fails with `gpbackup not found under /usr/edb/*/bin` until you upgrade it. See [Installing WarehousePG Backup and Restore](https://www.enterprisedb.com/docs/supported-open-source/warehousepg/whpg-backup/installing/#upgrading).

1. Once you confirm metrics and logs are flowing through ClickHouse, decommission any Prometheus, Loki, or WHPG Collector instances you ran solely for WEM.

### Upgrading to 1.3

WEM requires a PostgreSQL database for its own application state, either your WHPG cluster's own database or a dedicated instance.

WEM 1.3 introduces the `acp-host-agent` service for privileged host operations. See [Installing the host agent](host-agent).

WEM 1.3 bundles Alertmanager and runs its own instance on `127.0.0.1:9093`, and the `ALERTMANAGER_URL` parameter is removed from `/etc/wem/wem.conf`. If you had a separately installed Alertmanager configured through it, WEM stops using it after the upgrade. If that separate instance is still running on the same host, it might block WEM's bundled instance from starting. Before upgrading, shut it down if it existed only to serve WEM, or move it to a different port first if you still need it.

Before upgrading, check whether you hand-added any custom alert rules to WEM's previous Prometheus rule files (`config/prometheus/alerts/*.rules.yml`). Alert rules move into WEM's own database in 1.3, so any custom rules from 1.2 are lost once the old rule files are removed. Note down their PromQL expressions and thresholds beforehand, and recreate them through the **Rules** tab after upgrading. See [Creating and managing alert rules](../monitoring/alerts#creating-and-managing-alert-rules).

The RPM preserves your existing `wem.conf` and places a reference copy of the updated configuration at `wem.conf.rpmnew`, including new parameters such as `WEM_AGENT_CALLBACK_BASE_URL`. WEM 1.3 introduces many new and changed parameters beyond this one example. After upgrading, review `wem.conf.rpmnew` alongside the full [Configuration reference](../reference/configuration) and copy any new parameters you need into your existing `wem.conf`.

### Upgrading to 1.2

WEM 1.2 changes the service identity from `root` to `gpadmin`. The upgrade handles both common cases automatically:

- **`gpadmin` exists on the WEM host** (typical when WEM is co-located with WHPG): The upgrade adjusts file ownership so the `gpadmin`-run service can write logs. The service user change takes effect on `systemctl restart wem`.

- **`gpadmin` is missing** (older standalone WEM host that ran as `root`): The upgrade automatically sets `WHPG_ALLOW_ROOT=1` in `wem.conf` so the service continues running as root, with instructions written to the service configuration for switching to `gpadmin` later.

If you have a custom service configuration override that sets `User=root`, the service refuses to start after the upgrade. Either remove the override or set `WHPG_ALLOW_ROOT=1` in `/etc/wem/wem.conf`.

## Upgrading WEM

Run these commands on the WEM host.

1. Install ClickHouse if you haven't already, and update `/etc/wem/wem.conf` as described in [Before you upgrade](#before-you-upgrade) for the version you're upgrading to.

1. Configure the EDB repository:

    ```bash
    export EDB_SUBSCRIPTION_TOKEN=<your-token>
    export EDB_REPO=gpsupp
    curl -1sSLf "https://downloads.enterprisedb.com/$EDB_SUBSCRIPTION_TOKEN/$EDB_REPO/setup.rpm.sh" | sudo -E bash
    ```

1. Upgrade the WEM package:

    ```bash
    sudo dnf upgrade whpg-enterprise-manager
    ```

1. Restart the WEM service to apply the update:

    ```bash
    systemctl restart wem
    ```

1. Clear your browser cache or open WEM in a new browser session. After an upgrade, stale session data can cause a CSRF token error on first login.

Upgrading `whpg-enterprise-manager` also upgrades its bundled dependencies.

## Upgrading and installing the host agent

Run these commands on every cluster node that already has the host agent installed (the coordinator and standby coordinator, if you're upgrading from 1.3), then install it fresh on every segment host that doesn't have it yet. See [Installing the host agent](host-agent) for the full procedure, including the hostfile-based `gpssh` commands that target every node at once.

1. Configure the EDB repository on each node, if you haven't already:

    ```bash
    export EDB_SUBSCRIPTION_TOKEN=<your-token>
    export EDB_REPO=gpsupp
    curl -1sSLf "https://downloads.enterprisedb.com/$EDB_SUBSCRIPTION_TOKEN/$EDB_REPO/setup.rpm.sh" | sudo -E bash
    ```

1. Upgrade or install the host agent package:

    ```bash
    sudo dnf upgrade -y edb-acp-host-agent || sudo dnf install -y edb-acp-host-agent
    ```

1. Restart the service so it reconnects using the self-registration and mTLS flow:

    ```bash
    sudo systemctl restart acp-host-agent
    ```

1. In WEM, go to **Management > Host Agents** and approve any agent that appears in a pending state.

## Next steps

Your upgrade is complete. See [Getting started with WEM](../get-started).
