WEM requires ClickHouse to store the historical metrics and log data forwarded by the OTel Collector running on every cluster node, and a PostgreSQL database for its own configuration and application state.

ClickHouse isn't bundled with WEM, and configuring it is entirely up to you. The steps on this page cover one convenient path to a working instance using EDB's ClickHouse packages, but you can also point WEM at an existing ClickHouse instance you already manage, on any host reachable from every cluster node's OTel Collector or gateway collector. See ClickHouse's own [documentation](https://clickhouse.com/docs) for sizing, replication, and other production configuration this page doesn't cover.

Install ClickHouse before WEM, since WEM's configuration depends on knowing its address. If you're installing it yourself using the steps below, deploy it in one of these ways:

- **On the standby coordinator:** WEM auto-provisions the gateway collector on the standby coordinator internally, and you don't need to set `OTEL_GATEWAY_ENDPOINT` in `wem.conf`. If your cluster has no standby coordinator, WEM auto-provisions the gateway on the coordinator instead.
- **On a dedicated monitoring host:** Set `OTEL_GATEWAY_ENDPOINT=<dedicated-host>:4317` in `wem.conf`. Every observability component then runs on the dedicated host, outside the cluster.

Bringing your own ClickHouse instance instead works the same way. WEM only needs `CLICKHOUSE_URL` set to a reachable address, and `OTEL_GATEWAY_ENDPOINT` set if that instance isn't reachable from the standby coordinator's auto-provisioned gateway.

## Installing ClickHouse

ClickHouse stores the metrics and logs that the OTel Collector on every cluster node forwards through the gateway collector. Install it on the coordinator, the standby coordinator, or a dedicated monitoring host, depending on the deployment you chose above.

1. Configure the EDB repository, then install the ClickHouse packages:

    ```bash
    export EDB_SUBSCRIPTION_TOKEN=<your-token>
    export EDB_REPO=gpsupp
    curl -1sSLf "https://downloads.enterprisedb.com/$EDB_SUBSCRIPTION_TOKEN/$EDB_REPO/setup.rpm.sh" | sudo -E bash
    sudo yum install -y edb-clickhouse-server edb-clickhouse-client
    ```

1. `/etc/clickhouse-server/config.xml` ships with every setting commented out for reference. Rather than editing that generated file, add your own settings as a drop-in file under `config.d/`, which ClickHouse merges in automatically, the same way `users.d/` works for the password in the next step. Fragments are only merged at startup, so this setting has no effect until you restart ClickHouse, in a later step.

    This step covers four parameters:

    - **Listen address** (`listen_host`): the network interface ClickHouse binds to. Required, since ClickHouse listens on `localhost` only by default and needs to accept connections from the gateway collector and from WEM.
    - **HTTP port** (`http_port`): the port the gateway collector uses for OTLP ingest over HTTP. Already `8123` by default, ClickHouse's own default and the value WEM expects, so no change is needed unless you want a different port.
    - **TCP port** (`tcp_port`): the port for ClickHouse's native protocol, used by `clickhouse-client` and by WEM. Already `9000` by default, so likewise no change is needed unless you want a different port.
    - **Logger**: log level and destination. Optional, the defaults already write to the same log paths, just at a more verbose level than set here.

    Set all four in a single drop-in file. Running the `tee` command below more than once, against this same path, is safe and expected if you come back to change any of these values later — it overwrites this one file only, not any other configuration:

    ```bash
    sudo mkdir -p /etc/clickhouse-server/config.d
    sudo tee /etc/clickhouse-server/config.d/observability.xml << 'EOF'
    <clickhouse>
        <!-- Listen on all interfaces, or restrict to the WEM host IP address -->
        <listen_host>0.0.0.0</listen_host>

        <!-- Already ClickHouse's own default and the value WEM expects.
             Uncomment only to override it. -->
        <!-- <http_port>8123</http_port> -->

        <!-- Already ClickHouse's own default and the value WEM expects.
             Uncomment only to override it. -->
        <!-- <tcp_port>9000</tcp_port> -->

        <logger>
            <level>information</level>
        </logger>
    </clickhouse>
    EOF
    ```

    !!! Note
        `config.d/` and `users.d/` fragments are merged once, at startup, into `/var/lib/clickhouse/preprocessed_configs/config.xml`. Adding or editing a fragment has no effect until you start ClickHouse, in the next step. If you come back to change one of these settings later, on an already-running instance, run `clickhouse stop` before `clickhouse start`. Starting an already-running ClickHouse is a no-op and doesn't pick up the change.

1. Set a password for the default ClickHouse user. This example uses ClickHouse's built-in `default` user, but any ClickHouse user works, as long as you use the same username consistently in the gateway collector and WEM configuration:

    ```bash
    sudo tee /etc/clickhouse-server/users.d/default-password.xml << 'EOF'
    <clickhouse>
        <users>
            <default>
                <password><your-password></password>
            </default>
        </users>
    </clickhouse>
    EOF
    ```

1. Start ClickHouse:

    ```bash
    sudo systemctl daemon-reload
    sudo clickhouse start
    sudo clickhouse status
    ```

1. Verify ClickHouse is accepting connections:

    ```bash
    clickhouse-client --password "<your-password>" --query "SELECT 1"
    ```

    That confirms ClickHouse itself is up, but not that `listen_host` took effect. Confirm the setting actually merged into the effective config, and that ClickHouse is listening on all interfaces rather than only `localhost`:

    ```bash
    grep -A1 listen_host /var/lib/clickhouse/preprocessed_configs/config.xml
    ss -tlnp | grep -E ':8123|:9000'
    ```

    Then test the connection you actually need, from another cluster node rather than from ClickHouse's own host:

    ```bash
    curl "http://<clickhouse-host>:8123/?query=SELECT%201"
    ```
