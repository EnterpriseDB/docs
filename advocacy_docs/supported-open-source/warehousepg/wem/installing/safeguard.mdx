Safeguard provides disaster recovery (DR) for WarehousePG through [WarehousePG Disaster Recovery](/supported-open-source/warehousepg/whpg-dr/) (`whpg-dr`). Install Safeguard when you want WEM to configure, deploy, and monitor `whpg-dr` between a primary WarehousePG cluster and a DR standby, and to drive backups, restores, and promotion from the WEM interface.

!!! Note
    Safeguard requires you install the [host agent](host-agent) on both the primary and DR coordinators, plus the `edb-whpg-dr` package on every host, coordinator and segments, in both clusters. It also requires a storage repository, reachable by both clusters, for `whpg-dr` to archive WAL and base backups to. Set one up by following [Setting up the storage repository](/supported-open-source/warehousepg/whpg-dr/setting-up-primary/storage/) before configuring Safeguard.

## Installing WarehousePG Disaster Recovery

Install `edb-whpg-dr` on the primary cluster by following [Installing the package](/supported-open-source/warehousepg/whpg-dr/setting-up-primary/configuring-primary/#installing-the-package), which installs the RPM on the coordinator and every segment host. Install it on the DR cluster the same way, following [Installing whpg-dr](/supported-open-source/warehousepg/whpg-dr/configuring-dr/#installing-whpg-dr).

Once installed, configure it through Safeguard's **Configuration** tab in WEM, which generates a `whpg-dr` configuration for you from a set of form fields and deploys it through the host agent. See [Configuring Safeguard](../protecting-data/safeguard#configuring-safeguard) for that workflow. If you already maintain `whpg-dr` configuration files outside WEM, point Safeguard at their paths instead. Either way, deploying still runs through the host agent on each coordinator.

## Configuring the host agent for Safeguard

Configure the value of `WEM_TASK_QUEUES` on each coordinator, since WEM can't derive a DR standby's queue automatically the way it does for a cluster's own coordinator. See [Host agent configuration](../reference/host-agent-config#wem-connection) for the full variable reference.

1. On the primary coordinator, edit `/etc/edb/acp-host-agent/acp-host-agent.conf` and set:

    ```ini
    WEM_TASK_QUEUES=coordinator-tasks
    ```

1. On the DR coordinator, edit `/etc/edb/acp-host-agent/acp-host-agent.conf` and set:

    ```ini
    WEM_TASK_QUEUES=dr-standby-tasks
    ```

1. If you haven't done it before, start and enable the host agent on both coordinators:

    ```bash
    sudo systemctl enable --now acp-host-agent
    sudo systemctl status acp-host-agent
    ```

1. Verify the service is running and connected to WEM:

    ```bash
    tail -f /var/log/edb/acp-host-agent/acp-host-agent.log
    ```

!!! Note
    Restoring and promoting the DR cluster from WEM also require the DR coordinator's host agent connected. If you'd rather not connect one, set the DR connection mode to **None** on the Configuration tab, and run the equivalent `whpg-dr restore` and `whpg-dr promote` commands directly on the DR coordinator instead. See [Restoring and promoting the DR cluster](../protecting-data/safeguard#restoring-and-promoting-the-dr-cluster).
