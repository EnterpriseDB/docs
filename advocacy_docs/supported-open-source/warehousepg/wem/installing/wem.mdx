Install the WarehousePG Enterprise Manager (WEM) package on your designated host.

## Downloading and installing WEM 

1. Configure the EDB repository on your host:

    ```bash
    export EDB_SUBSCRIPTION_TOKEN=<your-token>
    export EDB_REPO=gpsupp
    curl -1sSLf "https://downloads.enterprisedb.com/$EDB_SUBSCRIPTION_TOKEN/$EDB_REPO/setup.rpm.sh" | sudo -E bash
    ```

1. Install the WEM package:

    ```bash 
    sudo dnf install -y whpg-enterprise-manager
    ```

1. To run WEM management commands (such as `setup`, `doctor`, or `setup --verify`) from any location in your terminal, add the WEM binary directory to your system `PATH`. Update your current session:

    ```bash
    export PATH=/usr/local/greenplum-db/wem:$PATH
    ```

    To make this change persistent, add the command above to your `~/.bashrc` or `~/.bash_profile` file.

!!! note
    Starting from WarehousePG 7.4 and 6.27.4, the default WHPG installation directory is `/usr/edb/whpg7`. For backward compatibility, a symlink is provided at `/usr/local/greenplum-db`. The WEM binary path above resolves through this symlink, so no changes are required on WarehousePG 7.4 or later systems.

## Configuring WEM

Configure the WEM service by editing `/etc/wem/wem.conf`. For a complete list of all supported parameters, defaults, and types, see the [Configuration reference](../reference/configuration).

### Target cluster

Set the values of `WHPG_HOST`, `WHPG_PORT`, `WHPG_DATABASE`, `WHPG_USER`, and `WHPG_PASSWORD` as per your WHPG cluster. For example:

```ini
WHPG_HOST=whpg-coordinator-host
WHPG_PORT=5432
WHPG_DATABASE=postgres
WHPG_USER=gpadmin
WHPG_PASSWORD=postgres
```

!!! Note
    You can specify any database on your WHPG cluster. However, `WHPG_USER` must be a superuser. To use a non-default SSL mode for this connection, set `WHPG_SSLMODE`. See [Configuration reference](../reference/configuration#target-cluster) for valid values.

    During setup, WEM automatically creates a dedicated `WHPG_WEM_USER` role and uses it for its runtime connection instead of reusing `WHPG_USER` for every query. `WHPG_USER` remains required as the superuser for setup tasks. See [Configuration reference](../reference/configuration#target-cluster).

### ClickHouse

Set the ClickHouse connection URL for the instance you're using, whether that's one you installed in [Installing ClickHouse](observability-stack) or an existing instance you already manage. Use `localhost` only if that instance runs on the same host as WEM. For example:

```ini
CLICKHOUSE_URL=clickhouse://username:password@localhost:9000
```

If you're running WEM and ClickHouse on a dedicated host, outside the cluster, also set `OTEL_GATEWAY_ENDPOINT` to that host's own hostname or IP address, as it's reachable from every WHPG cluster node, and install the [gateway collector](collector) on it. For example, if this host is reachable as `wem-host`:

```ini
OTEL_GATEWAY_ENDPOINT=wem-host:4317
```

Leave `OTEL_GATEWAY_ENDPOINT` unset if you're running WEM and ClickHouse on the standby coordinator instead. WEM manages the gateway internally there, with the coordinator as failover. See [Configuration reference](../reference/configuration#clickhouse) and [Configuration reference](../reference/configuration#otel-collector) for the complete list of ClickHouse and OTel Collector parameters.

### Application state

WEM stores its internal state in a dedicated `wem` database rather than reusing `WHPG_DATABASE`. This database can live on any Postgres instance reachable from the WEM host, it doesn't have to be the WHPG cluster you're monitoring. Configure the following parameters to point WEM at the host and role that own this database. For example:

```ini
WEM_HOST=wem-db-hostname
WEM_PORT=5432
WEM_DATABASE=wem
WEM_USER=wem_admin
WEM_PASSWORD=<your-password>
```

`WEM_USER` must already exist and hold both the `CREATEDB` and superuser privileges. WEM creates the `WEM_DATABASE` database itself on first start if it doesn't already exist, but it doesn't create the role. For example, on the WHPG cluster:

```sql
CREATE ROLE wem_admin WITH LOGIN PASSWORD '<your-password>' CREATEDB SUPERUSER;
```

Leaving `WEM_HOST` unset doesn't fall back to `WHPG_HOST`. It defaults to `localhost`, so leave it unset only when a Postgres instance for this database is reachable at `localhost` from the WEM host itself.

A common, practical choice is reusing your WHPG cluster's own Postgres server for this database too, setting `WEM_HOST`, `WEM_PORT`, and `WEM_USER` to the same values as `WHPG_HOST`, `WHPG_PORT`, and `WHPG_USER`, so `WEM_DATABASE` becomes just another database on that same server rather than a separate instance to run and maintain. Avoid pointing it at the monitored database itself, though. If that database goes down, WEM goes down with it, since it can no longer reach its own operational state. For higher resilience, host this database on a separate Postgres instance entirely.

### AI Assistant

To enable the AI Assistant for query writing and optimization, manually add the `ANTHROPIC_API_KEY` parameter (requires an active Anthropic account).

```ini
ANTHROPIC_API_KEY=YOUR_API_KEY_HERE
```

### Advanced tuning

Optionally, adjust these parameters to fine-tune performance and data intervals: extend timeouts for large clusters (`HIGH_LOAD_MODE`), flag long-running queries in the interface (`LONG_RUNNING_THRESHOLD`, in minutes), adjust WHPG's own statement logging (`LOG_MIN_DURATION_STATEMENT`), tune how often WEM evaluates alert rules (`ALERT_EVALUATION_INTERVAL`) or scans the coordinator's log (`LOG_SCAN_INTERVAL`), or disable either feature entirely (`ALERT_EVALUATOR_ENABLED`, `LOG_SCAN_ENABLED`). See [Configuration reference](../reference/configuration) for the complete list, defaults, and valid formats.

### WEM portal access

By default, the WEM web portal listens on port 8080. To use a different port, set the `PORT` parameter. For example:

```ini
PORT=8082
```

### Session security

To start, WEM requires `WEM_COOKIE_SECRET` to be set. It returns an error with setup instructions if it's missing.

- Generate a unique 32-byte key using `openssl rand -base64 32` and set it as the `WEM_COOKIE_SECRET`.
- If you aren't using HTTPS, you must also set `WEM_INSECURE_COOKIES` to `1`.

```ini
WEM_COOKIE_SECRET=your-generated-secret-key
WEM_INSECURE_COOKIES=1
```

### Setting the administrator password

Before initializing WEM, you must establish the initial administrative credentials. The initial administrator username is always `admin`, it isn't configurable. Choose one of the following methods to set its password:

- **Interactive setup:** Skip editing the configuration file and provide the password directly when running `wem setup` in the following section.

- **Static configuration:** Define the password in the WEM configuration file. This parameter is auto-generated if empty at install.

    ```ini
    WEM_ADMIN_PASSWORD=your-secure-password
    ```

- **File-based configuration:** For enhanced security in automated deployments, point WEM to an external password file.

    1. Create a file containing your password:

        ```bash
       echo "your-secure-password" > /etc/wem/admin.pw
        ```

    1. Manually add the following parameter to the WEM configuration file:
        
        ```ini
        WEM_ADMIN_PASSWORD_FILE=/etc/wem/admin.pw
        ```

!!! Note
    After you initialize the WEM portal and log in for the first time, perform all user management, such as adding users and modifying roles, through the WEM interface.

## Initializing WEM

Enable and start the WEM service. On first start, WEM automatically initializes the monitoring schema in your WHPG database:

```bash
sudo systemctl enable --now wem
```

If setup fails, the service stays in `activating (auto-restart)`. The most common causes are WHPG being unreachable or an incorrect `WHPG_PASSWORD`. Tail the log to diagnose:

```bash
sudo tail -f /var/log/wem/wem.log
```

!!! Note
    Every `systemctl restart wem` rotates this file to a timestamped copy and starts a fresh `wem.log`, so a `tail -f` you left running stops receiving new lines after a restart, without any error, it's just watching the old, now-static file. Exit and rerun `tail -f` after each restart, or use `sudo journalctl -u wem.service -n 500 -f` instead, which follows across restarts without needing to be restarted itself.

For manual troubleshooting, run `wem setup` with your connection details passed as flags. The command doesn't read `wem.conf`. Run it as the `wem` service user, and add `--check --debug` to test the connection and print verbose SQL and connection output without making changes. For example:

```bash
sudo -u wem /usr/local/greenplum-db/wem/wem setup --host whpg-coordinator-host --port 5432 --user gpadmin --password postgres --database postgres --check --debug
```

See [wem setup](../reference/commands#wem-setup) for available flags.

## Verifying the installation

Verify that the service is active:

```bash
sudo systemctl status wem
```

Use the following diagnostic tools to ensure all components are communicating correctly and the environment is healthy.

- Validate your configuration settings:

    ```bash
    wem setup --verify
    ```
    See [wem setup command reference](../reference/commands#wem-setup) for details.

- Perform a comprehensive check for configuration errors, missing dependencies, or connectivity issues:

    ```bash
    wem doctor
    ```

    See [wem doctor command reference](../reference/commands#wem-doctor) for details.


!!! Note Post-installation changes: 
    To modify your environment after the initial setup, see [Configuring WEM](../configuring).
