## WEM 1.6.0

Released: 24 Nov 2026

WEM 1.6.0 includes new features, enhancements, and bug fixes.

!!! Note
    The host agent (`acp-host-agent`) is installed separately from WEM, and it installs the EDB OpenTelemetry (OTel) Collector (`edb-otelcol`) as a dependency. WEM 1.6.0 is released with `acp-host-agent` 1.2.0, which depends on `edb-otelcol` 0.158.0-1edb2. Upgrade the host agent on every cluster node to get the changes in [Host agent 1.2.0](#host-agent-120). Managing FlowServer jobs requires 1.2.0 on the coordinator. See [Upgrading the host agent](../installing/upgrading#upgrading-the-host-agents).

!!! Warning "Update scripts and settings before you upgrade"
    WEM 1.6.0 removes the compatibility links and the configuration fallback that WEM 1.5 kept for the previous file locations. It also moves several settings out of `wem.conf` and into the console, and a value that you saved in the 1.5 console takes priority over the one in `wem.conf`. Check your runtime settings after you upgrade. See [Changes](#changes).

### Highlights

- **Live query plan and process monitoring:** Watch the execution plan of a running query as it executes, and see the processes, disk I/O, and skew behind it. See [Viewing query plans](../queries/live-query-plan).
- **FlowServer jobs management:** Create, start, stop, and remove FlowServer jobs, and review their activity, from the WEM console. See [Running FlowServer jobs](../flowserver-jobs).
- **Startup and runtime settings:** The **Settings** tab now separates the settings that need a restart from the settings you can change without one. See [Configuring WEM](../configuring).

### New features

- **Live query plan:** Select the plan icon on a running query in **Active Queries** to see its plan update every two seconds until the query ends. Each plan node shows the rows processed so far, its time, the segments reporting, and row skew across segments. The dialog also has tabs for the query text, the tables the plan reads, an on-demand `EXPLAIN` of the statement, the processes behind the query, and per-segment disk I/O. The live plan requires the `whpg_live_query_plan` extension, which you install on WarehousePG from the separate `edb-whpg<major_version>-live-query-plan` package. See [Viewing query plans](../queries/live-query-plan).
- **Process monitoring and per-query disk I/O:** The **Processes** tab lists the operating system processes behind a query and ranks slices by CPU time, memory, or disk I/O. It marks a process **No CPU progress** when it stops using CPU, which helps you find stragglers and blocked queries. **Active Queries** also gains a **Disk Activity** section and **Disk Read** and **Disk Write** columns. With the `whpg_live_query_plan` extension, the **Sessions** tab also shows each session's **OS State**, **Wait Event**, **Processes**, and **CPU Time**. See [Viewing query plans](../queries/live-query-plan) and [Monitoring and evaluating queries](../queries/query-monitor).
- **FlowServer jobs management:** The new **FlowServer** page has a **Jobs** tab, where you can create jobs from a FlowServer job YAML file, start them from a chosen offset or point in time, stop them, remove them, and see their status and progress. The **Activities** tab lists the actions requested for each job. Set the FlowServer address and how long WEM keeps finished actions in **Settings**. Managing jobs requires `acp-host-agent` 1.2.0 or later on the coordinator, and FlowServer running on the coordinator. WEM 1.6 doesn't support FlowServer on the standby or a dedicated host, so the FlowServer address in **Settings** must be `localhost`, `127.0.0.1`, or `[::1]`. See [Running FlowServer jobs](../flowserver-jobs).
- **Startup and runtime settings:** The **Settings** tab shows startup settings as read-only and groups runtime settings, such as cluster name and environment, slow query logging, the long-running query threshold, the OTel collection interval, and the AI Assistant API key and model, in a separate section. Runtime settings take effect when you save them, with no restart. See [Configuring WEM](../configuring).

### Changes

- **Compatibility links removed:** WEM 1.6 removes the compatibility measures that WEM 1.5 kept for the previous file locations. If your scripts, cron jobs, monitoring, or log tools still use an old path, switch to the new one:

    | Item | Old path | New path |
    |------|----------|----------|
    | Binary | `/usr/local/greenplum-db/wem/wem` or `/usr/edb/wem/wem` | `/usr/edb/wem/bin/wem` |
    | Log file | `/var/log/wem/wem.log` | `/var/log/edb/wem/wem.log` |
    | Configuration file | `/etc/wem/wem.conf` | `/etc/edb/wem/wem.conf` |

    WEM no longer reads `/etc/wem/wem.conf` when `/etc/edb/wem/wem.conf` is missing. The upgrade prints a `[WARN]` line for each link it removes, and names the systemd units, cron files, and `wem.conf` files that still use an old path. See [Upgrading WarehousePG Enterprise Manager](../installing/upgrading#upgrading-wem).
- **Runtime settings moved out of `wem.conf`:** `LONG_RUNNING_THRESHOLD`, `LOG_MIN_DURATION_STATEMENT`, `OTEL_COLLECTION_INTERVAL`, `WEM_CLUSTER_NAME`, `WEM_CLUSTER_ENVIRONMENT`, `ANTHROPIC_API_KEY`, `ANTHROPIC_MODEL`, `FLOWSERVER_ADDRESS`, and `FLOWSERVER_ACTIVITY_RETENTION_HOURS` are now stored in WEM and managed from **Settings**. On upgrade, WEM imports the values it finds in `wem.conf` or the environment once. If you already saved a value for a setting from the WEM 1.5 console, WEM keeps that saved value and ignores the one in `wem.conf`, even when the two differ. In WEM 1.5, values saved from the console didn't take effect, so a setting might have been running with its `wem.conf` value. After you upgrade, check every runtime setting in **Management** > **Settings**. After the import, changes to these parameters in `wem.conf` or the environment have no effect. See [Configuring WEM](../configuring) and [Configuration parameters](../reference/configuration#runtime-settings).
- **ppc64le packages:** WEM 1.6 includes ppc64le packages for RHEL 8, RHEL 9, and RHEL 10. WEM 1.5 offered ppc64le as a pilot.
- **Activity tabs renamed:** The **Activity** tab on the **Backups** page is now **Activities**, like the tab on the new **FlowServer** page.
- **Known issue removed:** WEM can now show the plan of a query while it runs. See [Viewing query plans](../queries/live-query-plan).

### Bug fixes

- Fixed a partitioned table with mixed storage being listed more than once on the **Database Objects** page.
- Fixed the **Active Queries** tooltip on the cluster overview not matching how the panel filters queries. The top-row tiles are now the same height.
- Fixed the AI Assistant model setting not being applied during remote upgrades.
- Fixed the **HBA Editor** failing with `no approved agent polling "coordinator-tasks"` when an approved host agent has a task queue override that lists several queues.

## Host agent 1.2.0

Host agent 1.2.0 is released with WEM 1.6.0 as a separate package. It's installed on every cluster node, and it installs `edb-otelcol` 0.158.0-1edb2 as a dependency.

### New features

- **FlowServer jobs management:** The host agent on the coordinator now connects to FlowServer and runs the actions that WEM requests: listing jobs, reading job progress, and creating, starting, stopping, and removing jobs. You don't need `flowcli`, a `sudo` helper, or any change to `sudoers`. A host agent older than 1.2.0 can't run these actions, and WEM reports that the agent doesn't support FlowServer. See [Running FlowServer jobs](../flowserver-jobs).

### Changes

- **Host agent settings moved to `wem.conf`:** The host agent now reads the settings that connect it to WEM, `WEM_CONNECT_ADDRESS`, `WEM_TASK_QUEUES`, and `WEM_DATABASE`, from `/etc/edb/acp-host-agent/wem.conf`. The common settings stay in `acp-host-agent.conf`. The upgrade moves your existing values and keeps them. Update any scripts that edit these settings. See [Host agent configuration](../reference/host-agent-config).

### Bug fixes

- Fixed a host agent that started while WEM was unreachable and then kept running without any segment information, even after WEM came back. Tasks that need the data directory, such as backups, failed until you restarted the agent, with errors such as `no segment found for this task queue in the segments cache` or `COORDINATOR_DATA_DIRECTORY must be set to locate the backup history database`. The agent now saves its segment cache only after an approved agent registers successfully.
- Fixed the backup helper hiding the real cause when it can't resolve the WarehousePG data directory. It now reports the data directory problem.
- Fixed the host agent log omitting the cause of a failed registration with WEM.
