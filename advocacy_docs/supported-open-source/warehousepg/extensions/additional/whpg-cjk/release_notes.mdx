The whpg-cjk documentation describes the latest version, including minor releases and patches. These release notes cover what's new in each release.

## 1.1.0

Release date: November 18, 2026

`whpg-cjk` 1.1.0 includes improvements and bug fixes.

!!!warning Rebuild your indexes after upgrading

Some text is analyzed differently from 1.0.0, so you must rebuild existing indexes after the upgrade. See [Upgrading whpg-cjk](installing.mdx#upgrading-whpg-cjk) for the steps. Don't drop and re-create the extension to upgrade.
!!!

### Changes

-   `ts_headline` now returns the original document text instead of the normalized text, and no longer highlights trailing punctuation.
-   Long Korean text without spaces is now analyzed in linear time instead of cubic time. You can now cancel long analyses, including when you close a cursor before its end.
-   Long Chinese runs without a safe cut point are now split at word boundaries instead of at arbitrary characters.
-   Hyphenated words that contain CJK characters are no longer indexed twice. Hashtags such as `#서울-부산` and compounds such as `KTX-서비스` are now analyzed correctly.
-   In Japanese, a suffix or dependent noun that is also an adjectival noun, such as 好き in 寿司好き, is now indexed on its own. Formal nouns, suffixes, and counters are still dropped.
-   `CREATE EXTENSION` no longer fails in `EUC_KR` databases. Analysis still requires UTF8. User dictionaries can start with a UTF-8 byte order mark (BOM).
-   `cjk_normalize()` now raises the same encoding error as the other functions in non-UTF8 databases, and maps control characters other than tab, line feed, and carriage return to spaces.
-   `cjk_segment()` no longer returns Unicode whitespace tokens. `cjk_analyze()` now shows the same analysis that the index uses.
-   `cjk_dict_status().loaded_dict` is no longer truncated at 1023 bytes.

## 1.0.0

### Changes

-   First release of `whpg_cjk`. It provides full text search for Korean, Japanese, and Chinese, based on morphological analysis rather than N-gram splitting.
