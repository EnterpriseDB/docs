## Summary

mongo_fdw built the `mongodb://` connection URI by string-formatting option values with no percent-encoding, so URI metacharacters (`@ : / ? # & =`) in an option value were parsed as URI structure rather than data. A non-superuser with `USAGE` on the foreign server can set `username`/`password` in their own user mapping; an `@` (or other metacharacter) in those values introduces a second authority component and can re-point the connection to an attacker-controlled host, enabling connection redirection, credential capture, and man-in-the-middle. Server-level options (address, database, replica set) are injectable in the same way.

## Remediation/fixes

| Product | VRMF | Remediation/First Fix |
|---------|------|-----------------------|
| mongo_fdw | ≤ v3.0 / REL-5_5_3 | Pending release. Fix staged in commit `ecd340f` (Jira FDW-753): the URI is built through libmongoc's builder API — host/database/replica-set/read-preference are validated for URI metacharacters, and credentials are set via `mongoc_uri_set_username`/`_password`/`_auth_source`, which percent-encode automatically. |

!!! Note Update
This advisory is a DRAFT prepared for PSIRT review. Rating note: an earlier internal triage proposed CVSS 8.5 (High) on the premise that a low-privileged user could trigger a TLS downgrade via `authentication_database`. That premise was disproved — `authentication_database`, `replica_set`, and `ssl` are server-level options (settable only by the server owner/superuser), and username/password land in the URI userinfo before the `@`, so an injected `&ssl=false` is not parsed as a query parameter. The plain non-superuser vector is connection redirection (scored above, 5.4). The high-confidentiality TLS-downgrade path requires server-owner privilege and a shared server, and is bounded at approximately 6.3 (`CVSS:3.1/AV:N/AC:H/PR:L/UI:N/S:C/C:H/I:N/A:N`). The 8.5 rating is retired.
