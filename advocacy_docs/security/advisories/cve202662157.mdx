## Summary

mongo_fdw builds a 12-byte MongoDB ObjectId from user-supplied `_id` values using libbson helpers that read a fixed size without bounds checking: `bson_oid_init_from_data()` copies 12 bytes from a bytea `_id`, and `bson_oid_init_from_string()` reads 24 characters for name-typed values and the `$oid` field during JSON-to-BSON conversion. A value shorter than the expected size causes a read past the end of the input, which can crash the backend and fold adjacent heap bytes into the query. The issue is reachable at query time by any user who can supply an `_id` value or predicate; it does not cross a privilege boundary.

## Affected products and versions

* Affected Versions: All versions up to and including v3.0 (REL-5_5_3).

## Remediation/fixes

| Product | VRMF | Remediation/First Fix |
|---------|------|-----------------------|
| mongo_fdw | ≤ v3.0 / REL-5_5_3 | Pending release. Fixed in commit `5d48478` (Jira FDW-753, patch `v333-0002`): `bsonOidFromString()` requires a valid 24-character hexadecimal ObjectId (`bson_oid_is_valid()`), and the bytea `_id` path requires exactly 12 bytes. |

!!! Note Update
This advisory is a DRAFT prepared for PSIRT review. The fix (commit `5d48478`, FDW-753 patch `v333-0002`) has been reviewed and confirmed (12-byte bytea check + `bson_oid_is_valid()` gate, with a regression test); the earlier traceability gap is resolved. This remains a borderline case — PSIRT should confirm whether a CVE is warranted. Assign a CVE ID and set the first-fix release version before publication.
