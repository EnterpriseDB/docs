## Summary

mysql_fdw builds string literals for queries sent to the remote MySQL server with an escaping routine that is not character-set aware. When the connection uses a multi-byte character set such as GBK, SJIS or Big5 and MySQL's default backslash escaping is in effect, a crafted value whose trailing byte is 0x5C absorbs the escaping backslash and leaves the following quote unescaped. The routine handles every pushed-down string constant, including ordinary WHERE-clause literals, so an authenticated user with only SELECT on a foreign table can break out of the literal and run arbitrary SQL on the remote MySQL server with the credentials of the user mapping.

## Affected products and versions

* Affected Product: MySQL Foreign Data Wrapper (mysql_fdw)
* Affected Versions: mysql_fdw 2.9.3 and earlier, on all supported PostgreSQL and EDB Postgres Advanced Server versions

## Remediation/fixes

Impacted users must upgrade to mysql_fdw TBD-MYSQL-FDW-FIXED or later. From mysql_fdw TBD-MYSQL-FDW-FIXED, mysql_fdw forces NO_BACKSLASH_ESCAPES into the session sql_mode and escapes string literals by doubling single quotes.

| Product | VRMF | Remediation/First Fix |
|---------|------|-----------------------|
| mysql_fdw | 2.9.3 and earlier | Update to mysql_fdw TBD-MYSQL-FDW-FIXED or later |

## Mitigation

Until you can upgrade, reduce exposure as follows:

* Avoid GBK, SJIS and Big5 as the character set for mysql_fdw connections.
* Grant the MySQL account used in user mappings only the privileges the foreign tables need.
