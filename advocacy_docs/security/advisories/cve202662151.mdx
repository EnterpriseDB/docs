## Summary

mysql_fdw constructs remote SQL string literals with a byte-level escaping routine that is not character-set aware. When the connection uses a multi-byte character set such as GBK, SJIS, or Big5 — and MySQL's default backslash-escaping is in effect — a crafted value whose trailing byte is `0x5C` consumes the backslash the escaper emits, leaving the following quote unescaped. Because the escaper is used for any pushed-down string constant (including ordinary `WHERE`-clause literals), an authenticated user with only `SELECT` on a foreign table can break out of the literal and execute arbitrary SQL on the remote MySQL server under the mapped credentials.

## Affected products and versions

* Affected Product: MySQL Foreign Data Wrapper (mysql_fdw)
* Affected Versions: All versions up to and including REL-2_9_3, on all supported PostgreSQL major versions.

## Remediation/fixes

| Product | VRMF | Remediation/First Fix |
|---------|------|-----------------------|
| mysql_fdw | ≤ REL-2_9_3 | Pending release. Fixed in commit `8d01880` (Jira FDW-754/759, patch `v4444-0003`; reviewed 2026-07-13): `option.c` forces `NO_BACKSLASH_ESCAPES` into the effective `sql_mode` and `mysql_deparse_string_literal()` doubles single quotes only. |
