## Summary

WarehousePG (WHPG) 6.27.1 through 6.27.6 and 7.2.1 through 7.6.0 are affected by a missing authorization vulnerability (CWE-862) in the built-in cluster expansion functions gp_expand_lock_catalog() and gp_expand_bump_version(). Any authenticated database role can run them, and neither checks privileges. A low-privileged user can call gp_expand_lock_catalog() inside an open transaction to block all catalog changes across the cluster for every user, superusers included, until that transaction ends, which in practice requires a superuser to terminate the session. Blocked changes include DDL, temporary table creation, GRANT and CREATE ROLE. The same user can call gp_expand_bump_version() repeatedly. Each call disconnects sessions that hold temporary tables, with a FATAL error on their next catalog change, and makes every other session rebuild its segment connections.

## Remediation/fixes

Impacted users must upgrade to a fixed version of WarehousePG.

| Product | VRMF | Remediation/First Fix |
|---------|------|-----------------------|
| WarehousePG | 6.27.1 through 6.27.6 | Update to WarehousePG 6.27.7 or later |
| WarehousePG | 7.2.1 through 7.6.0 | Update to WarehousePG 7.6.1 or later |

!!! Warning Immediate mitigation for existing clusters
Until you can upgrade, apply the following as a superuser in every connectable database (all user databases, `postgres`, and `template1`, so that new databases inherit the change). The statements apply to both WarehousePG 6 and 7:

```sql
REVOKE EXECUTE ON FUNCTION gp_expand_lock_catalog() FROM public;
REVOKE EXECUTE ON FUNCTION gp_expand_bump_version() FROM public;
```

The `gpexpand` utility runs as a superuser and is not affected by this change. This is a stopgap, not a replacement for upgrading: it must be applied in every database and does not protect databases created afterward unless it was also run against `template1`.
