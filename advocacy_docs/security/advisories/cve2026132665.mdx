## Summary

The pem.deploy_job_template() function does not check that the caller can access the servers, groups and agents it deploys a job template to. When PEM teams are used to separate access, a user with the scheduled tasks role (pem_manage_schedule_task) can deploy and schedule SQL or shell job steps on agents that belong to other teams.

## Vulnerability details

CVE-ID: [CVE-2026-132665](https://nvd.nist.gov/vuln/detail/CVE-2026-132665)

CVSS Base Score: 5.8 Medium

CVSS Temporal Score: Undefined

CVSS Environmental Score: Undefined

CVSS Vector: CVSS:4.0/AV:N/AC:L/AT:P/PR:L/UI:N/VC:N/VI:L/VA:N/SC:H/SI:H/SA:H

## Affected products and versions

* Affected Product: Postgres Enterprise Manager (PEM)
* Affected Versions: PEM 10.6.0 and later versions prior to PEM 10.6.1

## Remediation/fixes

Impacted users must upgrade to PEM 10.6.1 or later. From PEM 10.6.1, PEM checks team access for every server, group and agent a template is deployed to.

| Product | VRMF | Remediation/First Fix |
|---------|------|-----------------------|
| PEM | PEM 10.6.0 and later versions prior to PEM 10.6.1 | Update to PEM 10.6.1 or later |

## Mitigation

Until you can upgrade, reduce exposure as follows:

* Grant the pem_manage_schedule_task role only to trusted users.
* Keep batch (shell) job steps disabled on agents that do not need them.
