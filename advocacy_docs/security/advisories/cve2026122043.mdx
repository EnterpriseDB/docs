## Summary

repmgr does not escape node metadata before running event notification commands through the shell. When `event_notification_command` is configured, repmgr substitutes the `%a` (node name), `%c` (connection string) and `%d` (details) placeholders into the command and runs it with the shell. `%a` and `%c` are inserted without escaping, and `%d` escapes only double quotes, so shell command substitution still works inside the double quotes the documentation recommends. The `%a` placeholder of `failover_validation_command` has the same flaw.

The node name and connection string come from node records in the `repmgr.nodes` table. An attacker with the credentials of a non-superuser repmgr database user can write a crafted node record and run OS commands, as the operating system user that runs repmgr or repmgrd (usually `postgres`), on other cluster nodes that process an event using these placeholders.

The issue is a privilege escalation only in deployments where the repmgr database user is not a superuser. When it is a superuser, as in the repmgr quick start and in clusters deployed with Trusted Postgres Architect, the attacker gains no new capability, because a superuser can already run OS commands. Upgrading is still recommended.

Deployments that do not set `event_notification_command`, or whose commands do not use `%a`, `%c` or `%d`, and that do not use `%a` in `failover_validation_command`, are not affected.

## Affected products and versions

* Affected Product: repmgr, including repmgrd
* Affected Versions: repmgr 4.0.0 through 5.5.0 with an `event_notification_command` that uses `%a`, `%c` or `%d`, or a `failover_validation_command` that uses `%a`
* Not Affected: repmgr deployments that do not use these placeholders

## Remediation/fixes

Impacted users must upgrade to a fixed version of repmgr. Starting with repmgr 5.5.1, repmgr single-quotes every substituted node name, connection string and details value before running the command, so the value reaches the script as a single literal argument.

| Product | VRMF | Remediation/First Fix |
|---------|------|-----------------------|
| repmgr | 4.0.0 through 5.5.0 | Update to repmgr 5.5.1 or later |

After upgrading, you must remove any quotes you placed around `%a`, `%c` or `%d` in `event_notification_command`, and around `%a` in `failover_validation_command`. repmgr 5.5.1 quotes these values itself. A placeholder left inside double quotes, as earlier documentation recommended (for example `"%d"`), is still open to command injection.

## Mitigation

Until you can upgrade, reduce exposure by:

* Removing `%a`, `%c` and `%d` from `event_notification_command`, and `%a` from `failover_validation_command`. Pass `%n` (the numeric node ID) instead and look up other details inside the script.
* Restricting the repmgr database user's credentials to the cluster hosts, and restricting `pg_hba.conf` so that user can connect only from them.
