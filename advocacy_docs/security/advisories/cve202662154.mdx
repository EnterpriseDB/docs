## Summary

During `IMPORT FOREIGN SCHEMA`, mysql_fdw spliced values controlled by the remote MySQL server verbatim into locally-executed `CREATE FOREIGN TABLE` DDL: the `COLUMN_DEFAULT` metadata was emitted directly into the `DEFAULT` clause, and the generated ENUM placeholder type name was interpolated into the DDL. A hostile or compromised MySQL server (or a man-in-the-middle) that returns crafted `information_schema` metadata could therefore execute attacker-chosen DDL/DCL in the victim's local PostgreSQL session when the victim runs `IMPORT FOREIGN SCHEMA`. This is a distinct trust boundary from injection into the remote server: the attacker is the remote server, and execution occurs locally.

## Affected products and versions

* Affected Product: MySQL Foreign Data Wrapper (mysql_fdw)
* Affected Versions: All versions up to and including REL-2_9_3.

## Remediation/fixes

| Product | VRMF | Remediation/First Fix |
|---------|------|-----------------------|
| mysql_fdw | ≤ REL-2_9_3 | Pending release. Fixed in commit `8d01880` (Jira FDW-754/759, patch `v4444-0003`; reviewed 2026-07-13): `COLUMN_DEFAULT` emitted via `quote_literal_cstr()`; the ENUM placeholder type name quoted via `quote_identifier()` / `quote_literal_cstr()`. |

!!! Note Update
This advisory is a DRAFT prepared for PSIRT review. `UI:R` reflects that the victim must run `IMPORT FOREIGN SCHEMA` against the malicious server; `AC:H` reflects that the attacker must control the remote server or the connection.
