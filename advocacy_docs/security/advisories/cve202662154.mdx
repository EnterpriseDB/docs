## Summary

During IMPORT FOREIGN SCHEMA, mysql_fdw copies column metadata returned by the remote MySQL server into the CREATE FOREIGN TABLE statements it runs locally without quoting it. The COLUMN_DEFAULT value is placed directly in the DEFAULT clause, and the name of the generated ENUM type is inserted unquoted. A malicious or compromised MySQL server, or an attacker who can tamper with the connection, can return crafted information_schema metadata and run arbitrary SQL in the local PostgreSQL session of the user who runs IMPORT FOREIGN SCHEMA.

## Affected products and versions

* Affected Product: MySQL Foreign Data Wrapper (mysql_fdw)
* Affected Versions: mysql_fdw 2.9.3 and earlier, on all supported PostgreSQL and EDB Postgres Advanced Server versions

## Remediation/fixes

Impacted users must upgrade to mysql_fdw TBD-MYSQL-FDW-FIXED or later. From mysql_fdw TBD-MYSQL-FDW-FIXED, mysql_fdw quotes these values before building the statements.

| Product | VRMF | Remediation/First Fix |
|---------|------|-----------------------|
| mysql_fdw | 2.9.3 and earlier | Update to mysql_fdw TBD-MYSQL-FDW-FIXED or later |

## Mitigation

Until you can upgrade, reduce exposure as follows:

* Run IMPORT FOREIGN SCHEMA only against trusted MySQL servers, over TLS, as a role with no more privileges than it needs.
