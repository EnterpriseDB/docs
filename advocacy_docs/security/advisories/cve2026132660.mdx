## Summary

Several SECURITY DEFINER functions in the pem schema of the PEM backend database are owned by a superuser but do not set a safe search_path. Any PEM user who can connect to the PEM backend database can create objects that these functions use in place of the intended ones, and so run arbitrary SQL with superuser privileges. Temporary objects can be used for this on every supported PostgreSQL version, and objects in the public schema on PostgreSQL 14 backends and backends upgraded from PostgreSQL 14.

## Affected products and versions

* Affected Product: Postgres Enterprise Manager (PEM)
* Affected Versions: PEM 7.6.0 and later versions prior to PEM 10.6.1

## Remediation/fixes

Impacted users must upgrade to PEM 10.6.1 or later. From PEM 10.6.1, these functions run with a fixed search_path.

| Product | VRMF | Remediation/First Fix |
|---------|------|-----------------------|
| PEM | PEM 7.6.0 and later versions prior to PEM 10.6.1 | Update to PEM 10.6.1 or later |

PEM 9.8 is end of life and will not receive a fix. PEM 9.x users must upgrade to PEM 10.6.1 or later.

## Mitigation

Until you can upgrade, reduce exposure as follows:

* Limit which hosts can connect to the PEM backend database in pg_hba.conf.
* Run REVOKE CREATE ON SCHEMA public FROM PUBLIC in the PEM backend database. This closes the public-schema path but not the temporary-object path, so it does not replace upgrading.
