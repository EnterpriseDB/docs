## Summary

hdfs_fdw builds string literals for IN and = ANY(array) clauses pushed down to the remote Hive or Spark server without escaping single quotes. An authenticated user with only SELECT on a foreign table can supply a crafted array value that breaks out of the literal and changes the HiveQL query, which then runs on the remote server with the foreign server's credentials.

The same release fixes two lower-severity issues: the JDBC connection string, including the trustStorePassword value, was written to logs, and credentials stayed in memory in cleartext after the connection was established.

## Affected products and versions

* Affected Product: HDFS Foreign Data Wrapper (hdfs_fdw)
* Affected Versions: hdfs_fdw 2.3.3 and earlier, on all supported PostgreSQL and EDB Postgres Advanced Server versions

## Remediation/fixes

Impacted users must upgrade to hdfs_fdw 2.4.0 or later. From hdfs_fdw 2.4.0, hdfs_fdw escapes single quotes in these literals, masks trustStorePassword in logs and clears credentials from memory after connecting.

| Product | VRMF | Remediation/First Fix |
|---------|------|-----------------------|
| hdfs_fdw | 2.3.3 and earlier | Update to hdfs_fdw 2.4.0 or later |

## Mitigation

Until you can upgrade, reduce exposure as follows:

* Grant the Hive or Spark account used by the foreign server only the privileges the foreign tables need.
* Restrict access to the PostgreSQL server logs. The log_remote_sql option writes remote SQL, including literal values, to the server log.
