## Summary

hdfs_fdw built IN-clause string literals in `hdfs_deparse_string()` without escaping single quotes. A crafted array value could break out of the HiveQL string literal and alter the query pushed down to the remote Hive/Spark server. An authenticated PostgreSQL user with only `SELECT` on a foreign table can supply such a predicate; the injected HiveQL then executes with the foreign server's credentials — a privilege the user does not otherwise hold. The same fix addresses two lower-severity issues: the JDBC connection string (including `trustStorePassword`) was written to logs, and credentials were left un-zeroed in memory after connection.

## Remediation/fixes

| Product | VRMF | Remediation/First Fix |
|---------|------|-----------------------|
| hdfs_fdw | ≤ v2.3.3 | Pending release. Fixed in commit `657029b` (Jira FDW-755, patch `v22-0002`; reviewed 2026-07-13): single-quote doubling in `hdfs_deparse_string()`; `trustStorePassword` redacted in the C DEBUG3 log and in the JDBC client output; credentials zeroed after connection. |

!!! Note Update
This advisory is a DRAFT prepared for PSIRT review. The HiveQL injection is the primary, CVE-worthy issue. The bundled credential-exposure items are lower severity: log exposure of `trustStorePassword` (CWE-532) and cleartext credentials in memory (CWE-316); they are documented here rather than separately scored. Note the Hive username/password are transmitted separately and were not part of the logged connection string.
