## Summary

The row-level security policies on pem.job and pem.jobstep that apply to PEM agents do not limit an agent to its own jobs. An attacker who controls one monitored host, and so its PEM agent certificate, can create, change or delete jobs for every other agent, including the agent on the PEM server. Agents run SQL job steps with the database credentials of the server they monitor, and shell job steps where batch jobs are enabled, so compromising one monitored host can give superuser SQL access to every monitored database and to the PEM backend.

## Affected products and versions

* Affected Product: Postgres Enterprise Manager (PEM)
* Affected Versions: PEM 7.3.0 and later versions prior to PEM 10.6.1

## Remediation/fixes

Impacted users must upgrade to PEM 10.6.1 or later. From PEM 10.6.1, PEM agents can no longer create jobs or change job definitions or job steps.

| Product | VRMF | Remediation/First Fix |
|---------|------|-----------------------|
| PEM | PEM 7.3.0 and later versions prior to PEM 10.6.1 | Update to PEM 10.6.1 or later |

PEM 9.8 is end of life and will not receive a fix. PEM 9.x users must upgrade to PEM 10.6.1 or later.

## Mitigation

Until you can upgrade, reduce exposure as follows:

* Protect the PEM agent certificate and key on every monitored host, and limit root access to monitored hosts to trusted administrators.
* Keep batch (shell) job steps disabled on agents that do not need them.
