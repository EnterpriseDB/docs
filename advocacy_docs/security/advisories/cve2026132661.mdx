## Summary

Multi-factor authentication (MFA) is not enforced on the PEM web application's own routes. An attacker who knows the password of a user who has enrolled a second factor can skip the second factor and call PEM's pages and APIs directly, with that user's permissions. A similar issue in pgAdmin 4 was assigned CVE-2024-4215.

## Vulnerability details

CVE-ID: [CVE-2026-132661](https://nvd.nist.gov/vuln/detail/CVE-2026-132661)

CVSS Base Score: 7.6 High

CVSS Temporal Score: Undefined

CVSS Environmental Score: Undefined

CVSS Vector: CVSS:4.0/AV:N/AC:L/AT:P/PR:L/UI:N/VC:H/VI:H/VA:N/SC:L/SI:L/SA:N

## Affected products and versions

* Affected Product: Postgres Enterprise Manager (PEM)
* Affected Versions: PEM 8.2.0 and later versions prior to PEM 10.6.1

## Remediation/fixes

Impacted users must upgrade to PEM 10.6.1 or later. From PEM 10.6.1, every authenticated PEM route requires a completed MFA check.

| Product | VRMF | Remediation/First Fix |
|---------|------|-----------------------|
| PEM | PEM 8.2.0 and later versions prior to PEM 10.6.1 | Update to PEM 10.6.1 or later |

PEM 9.8 is end of life and will not receive a fix. PEM 9.x users must upgrade to PEM 10.6.1 or later.

## Mitigation

Until you can upgrade, reduce exposure as follows:

* Limit network access to the PEM web interface to trusted networks.
* Require strong, unique passwords for PEM users until you upgrade.
