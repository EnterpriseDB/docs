## Summary

The pem_agent role, which every PEM agent login inherits, is a member of the PostgreSQL pg_read_server_files and pg_write_server_files roles on the PEM backend database. An attacker who controls any monitored host, and so its PEM agent certificate, can read and write files on the PEM server host as the postgres operating system user. This includes the PEM certificate authority key, which lets the attacker issue certificates for other agents and act as them.

## Affected products and versions

* Affected Product: Postgres Enterprise Manager (PEM)
* Affected Versions: PEM 10.5.0 and later versions prior to PEM 10.6.1

## Remediation/fixes

Impacted users must upgrade to PEM 10.6.1 or later. From PEM 10.6.1, PEM agents no longer hold these roles.

| Product | VRMF | Remediation/First Fix |
|---------|------|-----------------------|
| PEM | PEM 10.5.0 and later versions prior to PEM 10.6.1 | Update to PEM 10.6.1 or later |

Upgrading removes the file access but does not undo earlier use of it. If you suspect a monitored host was compromised, reissue the PEM certificate authority and all PEM agent certificates after upgrading.

## Mitigation

Until you can upgrade, reduce exposure as follows:

* Protect the PEM agent certificate and key on every monitored host, and limit root access to monitored hosts to trusted administrators.
