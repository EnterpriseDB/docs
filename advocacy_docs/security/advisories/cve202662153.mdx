## Summary

mysql_fdw inserts several values into statements sent to the remote MySQL server without escaping them: the dbname and table_name options in ANALYZE, the remote schema name and the LIMIT TO and EXCEPT table names in IMPORT FOREIGN SCHEMA, and the sql_mode option in the SET sql_mode command. A user who can create or alter foreign tables or foreign servers, or run IMPORT FOREIGN SCHEMA, can break out of the string literal and run arbitrary SQL on the remote MySQL server with the credentials of the user mapping.

## Affected products and versions

* Affected Product: MySQL Foreign Data Wrapper (mysql_fdw)
* Affected Versions: mysql_fdw 2.9.3 and earlier, on all supported PostgreSQL and EDB Postgres Advanced Server versions

## Remediation/fixes

Impacted users must upgrade to mysql_fdw 2.10.0 or later. From mysql_fdw 2.10.0, mysql_fdw escapes these names and accepts only letters, digits, underscores and commas in sql_mode.

| Product | VRMF | Remediation/First Fix |
|---------|------|-----------------------|
| mysql_fdw | 2.9.3 and earlier | Update to mysql_fdw 2.10.0 or later |

## Mitigation

Until you can upgrade, reduce exposure as follows:

* Limit who can create or alter mysql_fdw foreign tables and foreign servers.
* Grant the MySQL account used in user mappings only the privileges the foreign tables need.
