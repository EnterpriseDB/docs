## Summary

mysql_fdw interpolated several values into statements sent to the remote MySQL server without escaping. `mysql_deparse_analyze()` inserted the `dbname`/`table_name` option values, `mysqlImportForeignSchema()` inserted the remote schema name and `LIMIT TO`/`EXCEPT` table names, and the `sql_mode` option was spliced into a `SET sql_mode` command with no validation. A user with the privilege to define or alter the relevant objects (`CREATE`/`ALTER FOREIGN TABLE`, `IMPORT FOREIGN SCHEMA`, or `ALTER SERVER`) could break out of the string literal and execute arbitrary SQL on the remote MySQL server under the mapped credentials.

## Affected products and versions

* Affected Product: MySQL Foreign Data Wrapper (mysql_fdw)
* Affected Versions: All versions up to and including REL-2_9_3.

## Remediation/fixes

| Product | VRMF | Remediation/First Fix |
|---------|------|-----------------------|
| mysql_fdw | ≤ REL-2_9_3 | Pending release. Fixed in commit `8d01880` (Jira FDW-754/759, patch `v4444-0003`; reviewed 2026-07-13): `dbname`/`relname`, `remote_schema`, and table names routed through `mysql_deparse_string_literal()`; `sql_mode` whitelisted in the validator to letters, digits, underscores, and commas. |

!!! Note Update
This advisory is a DRAFT prepared for PSIRT review. Tracked separately from the mysql_fdw multibyte-charset SQL injection advisory: distinct root cause (missing escaping at call sites / unvalidated `sql_mode` vs. a charset-unsafe escaper), distinct fix, and different reachability (this issue requires DDL/owner privilege, hence `PR:H`).
