## Summary

mysql_fdw accepted several security-sensitive connection options from non-superusers able to create or alter a foreign server. The `init_command` option is passed to `MYSQL_INIT_COMMAND` and executed as arbitrary SQL on the remote server at every connection (and reconnect); on a shared server this runs under another user's mapped credentials (a confused-deputy privilege escalation). The `mysql_default_file` and `ssl_key`/`ssl_cert`/`ssl_ca`/`ssl_capath` options name files read from the PostgreSQL server host, providing a server-side arbitrary file-read and connection-redirection primitive. A role granted only `USAGE ON FOREIGN DATA WRAPPER mysql_fdw` can exploit these.

* Affected Versions: All versions up to and including REL-2_9_3.

## Remediation/fixes

| Product | VRMF | Remediation/First Fix |
|---------|------|-----------------------|
| mysql_fdw | ≤ REL-2_9_3 | Pending release. Fixed in commit `cad96fe` (Jira FDW-754, patch `v4444-0004`; reviewed 2026-07-13): `mysql_fdw_validator()` rejects `init_command`, `mysql_default_file`, and `ssl_key`/`ssl_cert`/`ssl_ca`/`ssl_capath` when set by a non-superuser (`ssl_cipher` intentionally excluded). |

!!! Note Update
This advisory is a DRAFT prepared for PSIRT review. A single CVE covers both the code-execution facet (`init_command`; CWE-269/CWE-250) and the file-read facet (`mysql_default_file`, `ssl_*`; CWE-73/CWE-200) — shared root cause and single fix. The conservative single-scope CVSS variant is 6.5 (`S:U`); the scored 8.0 uses `S:C` for the confused-deputy crossing.
