## Summary

In EDB Postgres Extended Server and EDB Postgres Advanced Server versions 15 through 18 with Transparent Data Encryption (TDE) enabled, the key used to encrypt temporary files was incompletely initialized. The code applied sizeof() to a pointer to the key buffer rather than to the buffer itself, so only 8 of the intended 32 bytes were filled from a secure random source and the remaining 24 bytes kept whatever was already in memory. This reduces the guaranteed randomness of the temporary-file key from 256 bits to 64 bits. Exploiting this requires local read access to the server's temporary-file directory, and those files normally exist only while the server is running; they persist only after a crash and are removed at the next server start. Permanent data files and WAL are not affected.

## Affected products and versions

* Affected Products: EDB Postgres Extended Server, EDB Postgres Advanced Server
* Affected Versions: 15.x before 15.20, 16.x before 16.16, 17.x before 17.12, and 18.x before 18.7, with TDE enabled
* Not Affected: Servers without TDE enabled; versions before 15, which do not include TDE

## Remediation/fixes

Impacted users must upgrade to a fixed version and restart the server. Temporary files written after the restart use a fully random key. No re-encryption of existing data is needed, because relation files and WAL are encrypted with the data key, which is not affected.

## Mitigation

There is no configuration workaround. Until you can upgrade, reduce exposure by restricting operating system access to the data directory and to any locations listed in `temp_tablespaces`, so that only the database service account can read temporary files.
