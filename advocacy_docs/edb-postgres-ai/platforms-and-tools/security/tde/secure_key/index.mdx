TDE generates a data encryption key for every cluster, and you must choose how to protect that key.

## Data encryption key

The key for transparent data encryption (the data key) is generated by `initdb` and stored in a file `pg_encryption/key.bin` under the data directory. This file contains several keys that are used for different purposes at runtime. The data key is a single sequence of random bytes in the file.

If you don't perform any further action, this file contains the key in plaintext, which isn't secure. Anyone with access to the encrypted data directory has access to the plaintext key, which defeats the purpose of encryption.

## Choose a mechanism to protect the key

To secure the data encryption key, you must specify a wrap and an unwrap command that provides TDE with a data encryption protection mechanism, either as [initdb options](../reference/initdb_tde_options/) or as environment variables. You can set this parameter only at server start.

See [Protecting the data encryption key](../about/how/#protecting-the-data-encryption-key) to compare your options before choosing one:

- [Protect the data key with a passphrase](passphrase). A wrapping key is derived from the passphrase and used to encrypt the data key.

- [Protect the data key with a wrapping key stored in a key management system](key_store) or key store. This second key is also called the key-wrapping key or master key.

- You can also choose to [disable the data encryption key wrapping](disabling_key). Only do this for test environments, as it leaves the TDE key unprotected. If you chose to leave your key unwrapped, you can add protection later, see [Protecting an existing key](../key_maintenance/protecting_existing_key).

Each option's page shows the exact wrap and unwrap commands to use for that mechanism, both as environment variables and as `initdb` command-line arguments.
