TDE generates a data encryption key for every cluster, and you must choose how to protect that key and how to provide it to TDE.

## Data encryption key

The key for transparent data encryption (the data key) is generated by `initdb` and stored in a file `pg_encryption/key.bin` under the data directory. This file contains several keys that are used for different purposes at runtime. The data key is a single sequence of random bytes in the file.

If you don't perform any further action, this file contains the key in plaintext, which isn't secure. Anyone with access to the encrypted data directory has access to the plaintext key, which defeats the purpose of encryption.

## Step 1: Choose a mechanism to protect the key

To secure the data encryption key, you must specify a wrap and an unwrap command that provides TDE with a data encryption protection mechanism. You can set this parameter only at server start.

Choose one of the following mechanisms:

- [Protect the data key with a passphrase](passphrase). A wrapping key is derived from the passphrase and used to encrypt the data key.

- [Protect the data key with a wrapping key stored in a key management system](key_store) or key store. This second key is also called the *key-wrapping key* or *master key*.

- You can also choose to [disable the data encryption key wrapping](disabling_key). Only do this for test environments, as it leaves the TDE key unprotected.

Each option's page shows the exact wrap and unwrap commands to use for that mechanism.

## Step 2: Provide your wrap and unwrap commands to TDE

Whichever mechanism you choose, TDE wires the resulting wrap and unwrap commands into the server the same way. The configuration of these commands is left to the user, which allows you to tailor the setup to local requirements and integrate with existing key management software or similar. 

!!!note 
The `wrap` and `unwrap` commands are assumed to run with the current working directory set to the data directory of the Postgres server. Changing the working directory at run time can lead to unexpected results.
!!!

When you initialize a server with TDE, the `initdb` command adds the `data_encryption_key_unwrap_command` parameter in the `postgresql.conf` configuration file. The string specified in `data_encryption_key_unwrap_command` can then unwrap (decrypt) the data encryption key.

Both commands must contain the placeholder `%p`, which TDE replaces with the path to the key file. TDE runs the commands from the data directory, so this path can be relative to it.

- The wrap command receives the plaintext key on standard input and must write the wrapped key to the file path given by `%p`.
- The unwrap command must read the wrapped key from the file path given by `%p` and write the decrypted key to standard output.

You have the following options for providing the commands to TDE:

- Configure the wrapping and unwrapping commands as environment variables before creating the database, so TDE can fall back on those variables when initializing a server. See [Using a passphrase](passphrase/#via-environment-variable) or [Using a key store](key_store) for examples.

- Provide the wrapping and unwrapping commands directly on the command line when initializing a server, with the `--key-wrap-command=<command>` and `--key-unwrap-command=<command>` options. See [Using a passphrase](passphrase/#via-command-argument) or [Using a key store](key_store) for examples.

- Disable protection of your data encryption key with `--no-key-wrap`. Doing so leaves your key unprotected, so EDB recommends this practice only for testing purposes. See [Disabling the key wrapping](disabling_key) for details.
