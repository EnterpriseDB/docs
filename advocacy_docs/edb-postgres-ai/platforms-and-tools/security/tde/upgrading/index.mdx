Transparent Data Encryption (TDE) encrypts data as it's written, so you can only enable it when you create a database cluster. You can't turn it on for data that already exists, so migrating an existing database to TDE means copying its data into a new, TDE-enabled cluster.

TDE is built into Enterprise Postgres (Oracle Compatible) and Enterprise Postgres, so there's no separate package or extension to install. Use [pg_upgrade](https://www.postgresql.org/docs/current/pgupgrade.html) with additional TDE arguments to perform this copy, along with other upgrading and migrating operations, on Enterprise Postgres (Oracle Compatible), formerly EDB Postgres Advanced Server, and Enterprise Postgres, formerly EDB Postgres Extended Server, clusters.

To create a new TDE-enabled database server instead, see [Enabling TDE on self-managed environments](../self-managed/).

## Supported use cases

This table provides an overview of supported use cases.

| Use case                                                      | Source database server                                                   | Target database server                                                          |
|----------------------------------------------------------------|------------------------------------------------------------------------------|-----------------------------------------------------------------------------------|
| Perform a minor upgrade and add encryption                    | Unencrypted Enterprise Postgres (a given major version, earlier minor version) | Encrypted Enterprise Postgres (same major version, later minor version) |
| Perform a major upgrade and add encryption                    | Unencrypted Enterprise Postgres (a given major version)           | Encrypted Enterprise Postgres (a later major version)                   |
| Perform a major upgrade on an encrypted database               | Encrypted Enterprise Postgres (Oracle Compatible) (a given major version)            | Encrypted Enterprise Postgres (Oracle Compatible) (a later major version)                   |
| Change the Postgres distribution and add encryption           | Unencrypted PostgreSQL (a given major version)                              | Encrypted Enterprise Postgres (Oracle Compatible) (same major version)                      |
| Maintain the Postgres distribution and add encryption         | Unencrypted Enterprise Postgres (Oracle Compatible) (a given major version)           | Encrypted Enterprise Postgres (Oracle Compatible) (same major version)                      |
| Maintain the Postgres distribution and rotate encryption keys | Encrypted Enterprise Postgres (Oracle Compatible) (a given major version)             | Encrypted Enterprise Postgres (Oracle Compatible) (same major version) with new encryption keys |

## Before you begin

-   Enabling TDE always involves choosing how to protect the generated data encryption key. See [Protecting the data encryption key](../about/how/#protecting-the-data-encryption-key) to compare your options, then follow [Configuring the data encryption key](../secure_key) to implement your choice.

-   Review the [initdb TDE options](../reference/initdb_tde_options/) to ensure you have all information required for initializing a TDE-enabled database cluster.

-   Review [Limitations](../reference/limitations/) to understand limitations and changes in the handling of PostgreSQL utilities when you enable TDE.

-   Perform a backup of the source database server.

## Migrating data (for existing instances)

If you want to migrate data and objects from an existing database server, use pg_upgrade to copy data from an existing instance. Before you begin, follow [Initializing a server](../self-managed/#initializing-a-server) to create, start, and verify the new, TDE-enabled target server, then stop it again before performing the upgrade.

1.  Stop both the source and the new (target) server:

    ```shell
    <bin_directory>/pg_ctl -D <source_data_directory> stop
    <bin_directory>/pg_ctl -D <target_data_directory> stop
    ```

1.  Use `pg_upgrade` with the `--copy-by-block` option to copy data from the source server to the new, encrypted server:

    ```shell
    <bin_directory>/pg_upgrade -b <source_bin_directory> -B <target_bin_directory> \
      -d <source_data_directory> -D <target_data_directory> --copy-by-block
    ```

    Include other [TDE pg_upgrade options](../reference/pg_upgrade_arguments/) as required. If you want to reuse the data encryption key from the existing cluster instead of generating a new one, initialize the target server with the [`--copy-key-from=<file>` option](../reference/initdb_tde_options/#option---copy-key-fromfile) instead of a fresh `initdb --data-encryption`.

1.  Start the new, encrypted database server:

    ```shell
    <bin_directory>/pg_ctl -D <target_data_directory> start
    ```

1.  Connect to the encrypted database server and ensure the data was transferred.

1.  Perform any required cleanup operations, such as running `vacuumdb --all --analyze-in-stages` and removing the old cluster's data files with the script `pg_upgrade` generated.

See [Enabling TDE on an existing Enterprise Postgres (Oracle Compatible) database cluster](enabling_tde_epas/) or [Upgrading a PostgreSQL database server to Enterprise Postgres while enabling TDE](postgres_to_extended/) for complete worked examples with real commands and output.
