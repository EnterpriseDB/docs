# Choose your migration path

For end-to-end instructions on how to perform each type of database migration, see:

- [AWS RDS PostgreSQL or AWS RDS Aurora (PostgreSQL compatible) database to an HM-managed database](https://www.enterprisedb.com/docs/edb-postgres-ai/1.4/hybrid-manager/using_hybrid_manager/migration/migration_guides/aws_rds_pg_to_hm_managed/)

- [Oracle database to an HM-managed database](https://www.enterprisedb.com/docs/edb-postgres-ai/1.4/hybrid-manager/using_hybrid_manager/migration/migration_guides/oracle_to_hm_managed/)

- [Self-managed Postgres database to a different self-managed Postgres database](https://www.enterprisedb.com/docs/edb-postgres-ai/1.4/hybrid-manager/using_hybrid_manager/migration/migration_guides/self_managed_pg_to_self_managed_pg/)

- [Self-managed Postgres database to an HM-managed database](https://www.enterprisedb.com/docs/edb-postgres-ai/1.4/hybrid-manager/using_hybrid_manager/migration/migration_guides/self_managed_pg_to_hm_managed/)

Other Postgres sources, such as EDB Postgres AI Cloud Service (formerly BigAnimal), are also supported and follow the same self-managed Postgres migration path. In general, any self-managed Postgres database is a valid migration source, regardless of where or how it's hosted. For the full list of supported sources and destinations, see [Supported databases and operating systems](https://www.enterprisedb.com/docs/edb-postgres-ai/1.4/hybrid-manager/using_hybrid_manager/migration/supported_versions/).
