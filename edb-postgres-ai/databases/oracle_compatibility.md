# Oracle support

If you are migrating from Oracle, or your application was built using Oracle-specific syntax, compatibility with Oracle is a prerequisite for your Postgres database.

Only EDB Postgres Advanced Server supports Oracle features and syntax, among others:

- [dblink\_ora functions and procedures](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/01_dblink_ora_functions_and_procedures/)

- [Partitioning commands compatible with Oracle databases](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/04_partitioning_commands_compatible_with_oracle_databases/)

- [Built-in Oracle packages](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_bip_guide/03_built-in_packages/)

- [Oracle catalog views](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_cat_views/oracle_compatible_views/62_dba_users/)

- [Oracle-compatible SQL commands](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_sql/)

- [Oracle-compatible configuration parameters](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/summary_oracle_config_parameters/)

- [Oracle MERGE](https://www.enterprisedb.com/docs/epas/latest/reference/oracle_compatibility_reference/epas_compat_sql/65a_merge/)

- [Oracle data types](https://www.enterprisedb.com/docs/epas/latest/reference/sql_reference/02_data_types/)

- [Oracle keywords](https://www.enterprisedb.com/docs/epas/latest/reference/application_programmer_reference/stored_procedural_language_reference/17_advanced_server_keywords/#edb-postgres-advanced-server-keywords)
