title: Enabling the endpoint
navTitle: Enabling the endpoint
description: Turn on the MCP endpoint and confirm it's serving.
---

The AIDB package installs the `edb-endpoints` binary into the Postgres `bindir`. To enable the endpoint:

1. Make sure `aidb` is in `shared_preload_libraries`. AIDB's other background workers already need this. See [Configuring AIDB](../install/configure#configuring-shared_preload_libraries).

1. In `postgresql.conf`, turn the endpoint on:

   ```ini
   edb.endpoints_mcp_enabled = on
   ```

1. If the database you want to serve isn't `postgres`, also set `edb.endpoints_mcp_database` to the name of the database where you ran `CREATE EXTENSION aidb`:

   ```ini
   edb.endpoints_mcp_database = '<database with AIDB>'
   ```

   The endpoint connects to this one database for every call. It serves only one database per Postgres instance at a time. Pointing `edb.endpoints_mcp_database` at a different database and reloading switches which one is served, it doesn't add a second one. Serving more than one database at once needs a separate Postgres instance, each running its own endpoint.

1. Restart Postgres. `edb.endpoints_mcp_enabled` is a postmaster parameter, so a reload isn't enough.

1. Check that the endpoint is up. By default it listens on `127.0.0.1:8765`:

   ```shell
   curl -fsS http://127.0.0.1:8765/health
   curl -fsS http://127.0.0.1:8765/ready
   ```

   Both return HTTP 200.

Every other parameter has a working default. See [Configuring the endpoint](configuring-the-endpoint) for the full list.
