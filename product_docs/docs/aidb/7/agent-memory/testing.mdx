The repository separates fast client tests from tests that need a running AIDB database.

From the `python/` directory, install the development dependencies and run the unit suite:

```shell
poetry install
poetry run pytest
```

## Database tests

No DSN or runtime is built into the tests. Use a dedicated test database with AIDB and the deployment's chosen memory runtime already running:

```shell
export AIDB_TEST_DSN="postgresql://test_user:password@localhost:5432/aidb_test"

# Validate connectivity and the installed SQL contract.
poetry run pytest tests/integration -m integration
```

The end-to-end workflow also initializes test namespaces, so it needs the runtime identifier and initialization JSON for that environment:

```shell
export AIDB_TEST_RUNTIME="<configured-runtime-name>"
export AIDB_TEST_RUNTIME_CONFIG='<runtime-initialization-json>'

poetry run pytest tests/e2e -m e2e
```

The test covers `namespace_init`, `memory_add`, `memory_search`, `memory_list`, and precise `memory_delete` through both clients. It polls search because memory processing is asynchronous. Change the default 120-second limit with `AIDB_TEST_TIMEOUT` or `--aidb-timeout`.

For all test arguments and individual test commands, see the repository's `python/tests/README.md`.
