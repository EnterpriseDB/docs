Agent memory is a durable, Postgres-native memory layer for AI agents, built into the AIDB extension. Memories are ordinary Postgres objects that you create and query with SQL, so they stay in your database with secure, local storage and controlled access.

Without memory, each new conversation starts from nothing, and users have to repeat their preferences, history, and context. Agent memory gives an agent a durable memory of past conversations that it can search later. Memories live next to your application data, are protected by your existing Postgres roles and grants, and are available to any agent that can reach the database.

## How agent memory works

1. Add - Your application or agent sends conversation turns to agent memory for a specific *actor*, such as a user. Agent memory records the turns as an event.
2. Distill - In the background, AIDB processes each event and distills it into discrete memories, such as "prefers dark mode" or "wants a window seat". Because processing is asynchronous, a newly added fact might not appear in search results immediately.
3. Search - Later, the agent searches the actor's memories by meaning, not by keyword, and receives the best matches first.
4. Manage - Operators can list memories and delete them, individually or by session, agent, or actor. Deletion accepts a reason that is recorded for auditing.

## Key features

- Per-actor memory - Memories belong to an actor, and you scope searches by actor ID.
- Session and agent scoping - Narrow searches and deletions to a single session or agent.
- Namespaces - Keep memory configuration and data separate for each application or workload. See [Scoping memory with namespaces](namespaces).
- Safe retries - An idempotency key lets the database recognize a retried event instead of storing it twice.
- Auditable deletion - Deletion accepts a reason that is recorded for auditing, which supports erasure requests and data retention policies.
- SQL first - Add, search, list, and delete memories with the `aidb_memory` SQL functions. See [Managing memories](memory-operations).

## Key concepts

| Term                | Meaning                                                                                                                                                                                                                  |
|---------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Actor               | The person or system that memories are about, identified by an actor ID such as `user_42`.                                                                                                                               |
| Turn                | A single message in a conversation, with a role (for example, user or assistant) and content.                                                                                                                            |
| Memory              | A fact distilled from one or more turns and stored for later search.                                                                                                                                                     |
| Namespace           | A named scope that separates the memory configuration and data of one application or workload from another.                                                                                                              |
| Operator            | The person or deployment code responsible for configuring AIDB, namespaces, and database permissions.                                                                                                                    |

## Using agent memory with agents and tools

AIDB agents use agent memory natively. Agent memory operations are available as native tools that let an agent add and search memories, the same way it calls any other native tool, without you writing SQL for it:

| Tool            | Read-only | Description                                                                                  |
|-----------------|-----------|----------------------------------------------------------------------------------------------|
| `memory_add`    | No        | Teaches agent memory from a conversation or event, so the agent can recall it later.         |
| `memory_search` | Yes       | Finds the memories most relevant to a natural-language query.                                |

To make these tools available to an agent, list them in the agent's `tools`. See [Native tools](../tools/native-tools) and [Creating agents](../agents/creating-agents).

Listing and deleting memories are available only through the `aidb_memory` SQL functions, not as tools.

Agent memory has no separate MCP package. Applications that aren't AIDB agents use the `aidb_memory` SQL functions directly. See [Managing memories](memory-operations).
