Separate memory configuration and data for an application or workload with a namespace. A namespace holds the models, Agent Memory Server, and storage schema that every call naming it uses. An operator creates a namespace once with `aidb_memory.init`. See [Configuring agent memory](configuring#initializing-a-namespace).

## Understanding what a namespace holds

A namespace stores three groups of settings, which you supply to `aidb_memory.init`:

| Setting            | What it holds                                                         |
|--------------------|-----------------------------------------------------------------------|
| `model_spec`       | The registered embedding model and LLM that agent memory uses.        |
| `agentmemory_spec` | The memory runtime and how to reach the Agent Memory Server.          |
| `storage_spec`     | The storage schema and the names of the memories and entities tables. |

## Choosing a namespace

Choose a namespace for every `aidb_memory` call. Create one namespace per agent domain, environment, or tenant boundary, and keep the names environment-specific. Use the same namespace for related agent workflows.

```sql
SELECT *
FROM aidb_memory.search(
  query     => 'discount missing after renewal',
  namespace => 'helpdesk_namespace',
  actor_id  => 'alice'
);
```

## Listing namespaces

List namespaces by querying the `aidb_memory.namespaces` view directly. There's no dedicated list function:

```sql
SELECT name, state FROM aidb_memory.namespaces;
```

The view returns each namespace's `id`, `name`, `agentmemory_spec`, `model_spec`, `storage_spec`, `state`, `created_at`, and `updated_at`. The state is `ACTIVE` or `INACTIVE`. See the [SQL reference](../reference/agent-memory#aidb_memorynamespaces).

AIDB creates a `pg_agents` namespace at install. It has no `model_spec.llm`.
