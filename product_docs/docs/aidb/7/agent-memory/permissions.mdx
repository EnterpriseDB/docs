---
title: Granting permissions for agent memory
navTitle: Granting permissions
description: Grant the PostgreSQL permissions that agent memory operations need.
---

Grant the PostgreSQL roles that use agent memory only the access they need. The role that runs the Agent Memory Server and the roles that call the `aidb_memory` functions need different access.

## Granting access to the Agent Memory Server

Grant the Agent Memory Server's role read and write access to the storage schema and its tables. See [Preparing the storage schema](configuring#preparing-the-storage-schema) for the statements.

## Granting access to application roles

Roles that are members of the `aidb_users` role can call the `aidb_memory` functions. No additional grants are required. For how AIDB manages access to its functions, see [Manage user access with the aidb_users role](../install/configure#manage-user-access-with-the-aidb_users-role).

Keep application roles separate from the roles that manage storage schemas.

## Isolating actors

Agent memory enforces isolation between actors only through the filters that the caller or agent passes, such as `actor_id`. Always pass `actor_id` in your application's calls to `aidb_memory` functions, and use `agent_id` and `session_id` to narrow results further. Row-level security managed by Agent Governance is planned for a future release.

Deletion is intended for correction, retention, privacy, and compliance workflows. See [Deleting memories](memory-operations#deleting-memories).

## Reading sessions

Read sessions with the session functions. The `aidb_users` role can't read the `aidb_memory.sessions` view directly. See [Using session memory](session-memory).
