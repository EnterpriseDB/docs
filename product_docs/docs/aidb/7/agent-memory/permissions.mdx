---
title: Granting permissions for agent memory
navTitle: Granting permissions
description: Grant the PostgreSQL permissions that agent memory operations need.
---

Grant the PostgreSQL roles that use agent memory only the access they need. The role that runs the Agent Memory Server and the roles that call the `aidb_memory` functions need different access.

## Granting access to the Agent Memory Server

Grant the Agent Memory Server's role read and write access to the storage schema and its tables. See [Preparing the storage schema](configuring#preparing-the-storage-schema) for the statements.

## Granting access to application roles

Grant each role that calls the `aidb_memory` functions access to the AIDB extension, the storage schema, and the storage objects. For how AIDB manages access to its functions, see [Manage user access with the aidb_users role](../install/configure#manage-user-access-with-the-aidb_users-role).

Keep application roles separate from the roles that manage storage schemas, and give each role only the access it needs.

## Restricting administrative operations

Treat listing and deletion as administrative operations. Deletion is intended for correction, retention, privacy, and compliance workflows. See [Listing memories](memory-operations#listing-memories) and [Deleting memories](memory-operations#deleting-memories).

## Reading sessions

Read sessions with the session functions. The `aidb_users` role can't read the `aidb_memory.sessions` view directly. See [Using session memory](session-memory).
