To use agent memory, install AIDB on your Postgres instance and pull the EDB Agent Memory Server image. Agent memory comes with the AIDB extension, so you don't install it separately. The server is a Docker container that EDB provides. It builds memories from the conversations that your agents send and stores them in your database. Agent memory has no dependency on Hybrid Manager.

This page covers installing both components. To set up and run them, see [Configuring agent memory](configuring). To learn how the database and the server work together, see [Understanding agent memory](overview#architecture).

## Prerequisites

- A running Postgres database. AIDB 7 includes agent memory and supports EDB Postgres Advanced Server, EDB Postgres Extended Server, and PostgreSQL, version 14 and later. AIDB also supports EDB Postgres Distributed (PGD) clusters without any extra configuration.
- Permission to create schemas and roles in the database where AIDB is installed.
- Docker on the host where you run the Agent Memory Server container.
- An EDB subscription token, to pull the server image from the EDB container registry.

## Installing AIDB

Install AIDB by following the instructions in [Installing AIDB](../install). Agent memory comes with the AIDB extension, so there's no separate extension to install.

## Installing the Agent Memory Server

On the host where Docker runs, log in to the EDB container registry and pull the Agent Memory Server image. Use your EDB subscription token to authenticate:

```shell
export EDB_SUBSCRIPTION_TOKEN=<your-token>
echo "$EDB_SUBSCRIPTION_TOKEN" | docker login docker.enterprisedb.com \
  --username <username> \
  --password-stdin
docker pull docker.enterprisedb.com/edb-agentmemory-server:latest
```

You run the container later, after you prepare the storage schema. See [Running the Agent Memory Server](configuring#running-the-agent-memory-server).
