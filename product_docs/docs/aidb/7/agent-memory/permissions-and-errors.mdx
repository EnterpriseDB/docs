The client authenticates with the PostgreSQL role described by its DSN or borrowed connection. That role determines what the client can access — passing a connection object instead of a DSN doesn't reduce its database privileges.

Grant application roles only the AIDB operations they need. Namespace initialization and listing, memory listing, and deletion are operator-oriented operations and should be exposed only to trusted code.

## Exception hierarchy

All client database exceptions inherit from `AIDBError`:

| Exception | Meaning |
| --- | --- |
| `AIDBConnectionError` | Connection, authentication, pool, or server availability failure |
| `AIDBConfigurationError` | Missing extension or invalid configuration |
| `AIDBSpecMismatchError` | Namespace exists with a different runtime specification |
| `AIDBNamespaceNotFoundError` | Requested namespace doesn't exist |
| `AIDBPermissionError` | PostgreSQL role lacks permission for the operation |
| `AIDBQueryError` | A database operation failed for another query-related reason |

```python
from edb_agentmemory import AIDBError, AIDBPermissionError

try:
    client.memory_delete(
        "user_42",
        all_for_actor=True,
        reason="Erasure request #182",
    )
except AIDBPermissionError:
    # Report an authorization failure without retrying it.
    raise
except AIDBError as exc:
    # Apply the application's logging or retry policy.
    print(f"memory operation failed: {exc}")
```

Client-side argument errors, such as supplying two deletion targets, raise `ValueError` before any SQL is sent.

See [Exceptions](reference/exceptions) for the full reference.
