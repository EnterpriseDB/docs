AIDB runs on WarehousePG 7. This page covers how to install it and how AIDB on WarehousePG differs from AIDB on PostgreSQL. Everything not listed here works the same as on PostgreSQL.

**There are some limitations when running AIDB on WarehousePG. See [Unsupported Features](#unsupported-features) section below. Most notably, pipeline auto-processing is not yet supported. Pipelines can be used, but must be executed manually.**


## Requirements

- WarehousePG 7 on RHEL 8 or RHEL 9, x86/64. WarehousePG 6 isn't supported.
- pgvector `edb-whpg7-pgvector` version `0.7.4-3` or later. With earlier versions, semantic knowledge base search can return fewer results than requested.
- For volumes: `edb-whpg7-pgfs`.
- For semantic knowledge base query history: `pg_stat_statements` in `shared_preload_libraries`.

## Installing AIDB on WarehousePG

1. Set up the EDB `gpsupp` repository on every host in the cluster. See [Installing WarehousePG](/warehousepg/current/install_guide/install_whpg).

1. On the coordinator, install the packages on every host. `all_hosts` is a file that lists the coordinator and segment host names:

   ```bash
   gpssh -f all_hosts -e 'sudo dnf install -y edb-whpg7-pgvector edb-whpg7-aidb'
   ```

   To use volumes, also install `edb-whpg7-pgfs`.

1. Add `aidb` to `shared_preload_libraries` on every instance. Include the libraries that are already listed:

   ```bash
   gpconfig -c shared_preload_libraries -v 'aidb'
   ```

   To use semantic knowledge base query history, add `pg_stat_statements` too, for example `-v 'aidb,pg_stat_statements'`.

1. To read local file system paths with volumes, set `pgfs.allowed_local_fs_paths` on every instance:

   ```bash
   gpconfig -c pgfs.allowed_local_fs_paths -v "'/data/files'"
   ```

1. Restart the cluster:

   ```bash
   gpstop -ar
   ```

1. Connect to the coordinator and create the extensions:

   ```sql
   CREATE EXTENSION aidb CASCADE;
   CREATE EXTENSION pgfs;  -- only for volumes
   ```

Then continue with [Configuring AIDB](../install/configure), starting at user access.

## Supported features

These features work on WarehousePG:

- Models, credentials, and the model and text functions: embedding, chunking, parsing HTML and PDF, summarizing, OCR, text generation, and reranking.
- Pipelines with any step type, in these execution modes:
  - `Disabled`, run with `aidb.run_pipeline()`, over any source.
  - `Background`, over a volume source.
- Knowledge bases built from pipelines, and retrieval with `aidb.retrieve_key()` and `aidb.retrieve_text()`.
- Volumes.
- The pipeline error log, including `aidb.requeue_pipeline_errors()`.
- Semantic knowledge bases: crawl, search, aliases, relationships and join routes, comments and curation, query history, the audit log, and `Live` and `Background` processing.
- Agent Hub: agents, purposes, plugins, and conversations. Agent memory isn't supported.
- Purposes. A governed statement runs as the purpose's role.
- The Tools Hub: SQL tools, MCP tools, and native tools.
- The MCP endpoint. It runs on the coordinator.

## Unsupported features

These features fail with an error that ends in `is not supported on WarehousePG`:

| Feature | Behavior |
|---------|----------|
| `Live` or `Background` processing of a pipeline over a table | `aidb.create_pipeline()` and `aidb.update_pipeline()` refuse it. Use `Disabled` and `aidb.run_pipeline()`. |
| A Large Object (`aidb.lo`) column as a pipeline source | Refused when you create or run the pipeline. |
| Agent memory: `aidb_memory.*`, the `memory_add` and `memory_search` tools, `aidb.agent_session_source = 'memory'`, and `aidb.agent_memory_enable_worker = on` | Refused. |
| OTel export and storage: `aidb.otel_client` other than `noop`, `aidb.otel_exporter_enabled = on`, `aidb.otel_cleaner_enabled = on`, `aidb_otel.store_*`, `aidb_otel.ingest_*`, and `aidb.run_otel_retention_cleanup()` | Refused. |
| Purpose decision records | Not recorded. Purposes are still enforced. |
| Query history while `pg_stat_statements.track` is `all` | `aidb.import_query_history()` refuses it. Set `pg_stat_statements.track` to `top`. |

AIDB refuses the unsupported settings when you set them with `SET`, `ALTER ROLE`, or `ALTER DATABASE`. If you set them in `postgresql.conf`, AIDB logs them once at startup and treats them as off.

The SQL objects of unsupported features stay installed.

## Configuring settings

- Set AIDB settings persistently with `ALTER ROLE ... SET`, `ALTER DATABASE ... SET`, or `gpconfig`. `postgresql.conf` and `ALTER SYSTEM` change only the coordinator, not the segments.
- A session-level `SET` reaches the segments for the settings that functions on the segments read: egress allowlists, insecure egress and TLS, secret policies, thread limits, the model cache size, and the download and llama.cpp log settings. For settings that only superusers can change, this works only in a superuser session.

!!!important Egress allowlists and secret policies
Set the [egress allowlists](../install/configure#network-egress) and secret policies on every instance with `gpconfig`, or with `ALTER ROLE` or `ALTER DATABASE ... SET`. If you set them only in the coordinator's `postgresql.conf`, the segments enforce them for superusers but not for other roles. A check as a superuser doesn't show what other roles get.
!!!

## Background workers

- AIDB background workers run on the coordinator only.
- The agent memory worker and the OTel exporter and cleaner workers never start.
- A pipeline worker connects as the pipeline's owner role. That role needs the `LOGIN` attribute.

## Using AIDB functions in queries

### Retrieval and other set-returning functions in a join

You can't join `aidb.retrieve_key()` or `aidb.retrieve_text()` directly with a table, or use them in `CREATE TABLE AS` or `INSERT ... SELECT`. The error names the workaround. Read the results in a subquery first:

```sql
SELECT r->>'key', d.content
FROM jsonb_array_elements((SELECT jsonb_agg(t) FROM aidb.retrieve_key('my_kb', 'query', 5) t)) r
JOIN docs d ON d.id::text = r->>'key';
```

Other AIDB set-returning functions, such as `aidb.get_error_logs()` and `aidb.semantic_kb_search()`, fail in a join with `function cannot execute on a QE slice`. Use the same subquery pattern.

### Functions that read AIDB configuration

You can't call functions that read AIDB's own configuration, such as `aidb.run_pipeline()` and `aidb.delete_pipeline()`, once per row of a table. Build the list first:

```sql
SELECT aidb.run_pipeline(n) FROM unnest(ARRAY(SELECT name FROM aidb.pipelines)) n;
```

### Model and text functions per row

Model and text functions, such as `aidb.encode_text()` and `aidb.chunk_text()`, run per row on the segment hosts:

- Each segment process that runs a local model loads its own copy. Memory use grows with the number of segments. To limit it, see [`aidb.max_model_cache_size`](../install/configure#aidbmax_model_cache_size).
- Calls to remote models go out from the segment hosts. Allow the segment hosts to reach the model endpoints.

## Semantic knowledge bases

- A partitioned table appears once, as its parent table. Its partitions are left out. `ATTACH PARTITION` and `DETACH PARTITION` are picked up at the next `aidb.refresh_semantic_kb()`.
- Query history includes only statements that run through the coordinator.
- A `NOT VALID` foreign key is treated as a validated one when relationships are discovered.
- While a knowledge base refreshes or imports query history, DDL in any schema that a knowledge base covers waits until it finishes. A slow embedding endpoint makes the wait longer.

## Deleting an agent that's in use

On WarehousePG, `aidb.delete_agent()` doesn't wait for a running `aidb.agent_converse()` for the same agent:

- The delete runs if it would run without the conversation: when the agent has no earlier history, or with `force => true`. The running conversation's history isn't counted.
- When the conversation finishes, it fails with `the agent was deleted while the conversation ran`. Its transaction is rolled back, including its action log entries. The work it did, including model calls, is lost.

Before you delete an agent, stop the clients and applications that converse with it.

## Other differences

- The catalog health tools, such as `analyze_db_health`, report the coordinator's statistics only. They don't include work done on the segments.
- The MCP endpoint refuses connections that `pg_hba.conf` admits without a password, such as `trust` or `peer`.
