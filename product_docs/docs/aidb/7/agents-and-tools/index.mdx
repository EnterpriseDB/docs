An **agent** is a named, reusable configuration — instructions, a model, and a set of tools it's allowed to call — that AIDB runs through a ReAct-style reasoning loop: the model thinks, optionally calls one or more tools, observes the results, and repeats until it has an answer. A **tool** is anything an agent can invoke by name: a built-in AIDB operation, a custom parameterized SQL query you register, or an operation imported from an external MCP server.

!!!note
This is a distinct, in-database capability, not [Agent Factory](/edb-postgres-ai/latest/hybrid-manager/ai-factory/) — EDB's separate platform for building and hosting AI agents. AIDB's agents run entirely as SQL function calls inside your Postgres database, with no dependency on Agent Factory or any other external service. Nothing stops the two from being used together, but this section covers AIDB's own agents.
!!!

Both are ordinary Postgres objects, created and queried with SQL:

```sql
-- Register an agent that can query the database
SELECT aidb.create_agent(
    name         => 'db_helper',
    instructions => 'You are a helpful assistant that answers questions about this database.',
    model        => 'my_gpt',
    tools        => ARRAY['run_sql_query']
);

-- Have a conversation with it
SELECT * FROM aidb.agent_converse('db_helper', 'How many rows are in the orders table?');
```

## Why tool calling matters here

An agent's tool calls are only as reliable as the model backing it. AIDB's `openai_responses` and `anthropic_messages` providers emit real, provider-native tool-call requests; every other provider (including `openai_completions`, `gemini`, and the rest) still works with agents, but falls back to a prompt-injected simulation of tool calling. See [Tool calling and structured output](../reference/models#tool-calling-and-structured-output) and [OpenAI Responses API](../integrating-models/external-model-connections#openai-responses-api) for the difference. `t5_local` can't back an agent at all — it has no instruction-following ability.
