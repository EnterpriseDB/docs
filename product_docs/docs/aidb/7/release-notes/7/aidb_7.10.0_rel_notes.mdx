Released: 25 Nov 2026

AIDB 7.10.0 lets MCP clients call your AIDB agents as tools, and `pg_dump` now includes AIDB's configuration and history tables so a restored database keeps its pipelines, knowledge bases, agents, and memory.

This release also separates the configuration of different AIDB users. Pipelines, agents, SQL tools, and agent plugins have an owner role, and only roles that can `SET ROLE` to that owner can change them. Review [Upgrading from 7.9.0](#upgrading-from-790) before you upgrade.

AIDB 7.10.0 includes the following enhancements, changes, and bug fixes:

| Type        | Description |
| ----------- | ----------- |
| Enhancement | Agents as MCP tools: The MCP server lists AIDB agents as tools after the catalog tools, for members of `aidb_users`, and a `tools/call` on one runs `aidb.agent_converse()` as the caller and returns the answer and a `conversation_id` to continue the conversation. The new `aidb.get_mcp_agents()` function provides the listing. See [Calling agents as tools](../../mcp-endpoint/connecting-a-client#calling-agents-as-tools). |
| Enhancement | Retries and rate limits for remote models: AIDB retries remote model requests after HTTP `429`, HTTP `503`, or a failed connection, and waits longer before each retry. An optional rate limit caps the requests per second to each model host. Set the defaults with the new `aidb.model_*` settings, or per model in its config. See [Remote model requests](../../install/configure#remote-model-requests) and [Retries and rate limits](../../integrating-models/remote-models#retries-and-rate-limits). |
| Enhancement | AWS IAM authentication: A model can sign its requests with the PostgreSQL server's AWS credentials instead of an API key. A member of `aidb_admins` creates the credential with `aidb.create_aws_credential()`, and the model adds `aidb.aws_default_credentials()` to its config. See [AWS IAM authentication](../../integrating-models/remote-models#aws-iam-authentication). |
| Enhancement | System certificate authorities: AIDB trusts the certificate authorities installed on the server's operating system, along with its built-in roots. Endpoints that use a private certificate authority work without `ca_path`. Failed requests show a short reason, such as `DNS lookup failed` or `certificate not trusted`. See [Certificates and connection errors](../../install/configure#certificates-and-connection-errors). |
| Enhancement | Model context window: Set `context_window` in a model's config to the model's context window, in tokens. Agents that use the model then compact their history based on that size instead of a fixed 16,000 characters. See [Context window](../../integrating-models/remote-models#context-window). |
| Enhancement | Compaction keeps the newest tool result: When an agent compacts its history, it keeps the most recent model response, its tool calls, and their results. A result that's too large is cut in the prompt and ends with `...(truncated, N bytes total)`. The summary request also includes the agent's instructions. See [Context length](../../agents/conversing-with-agents#context-length). |
| Enhancement | `if_exists` for delete functions: `aidb.delete_pipeline()`, `aidb.delete_semantic_kb()`, `aidb.delete_semantic_alias()`, `aidb.delete_purpose()`, `aidb.delete_agent()`, `aidb.delete_agent_plugin()`, `aidb.delete_tool()`, `aidb.delete_model()`, and `aidb.delete_credential()` take a new `if_exists` argument. When it's `true` and the object doesn't exist, the function raises a notice instead of an error. |
| Enhancement | Dump and restore: `pg_dump` now includes AIDB's configuration and history tables, so a restored database keeps its pipelines, knowledge bases, agents, MCP servers, semantic knowledge bases, and agent memory. Caches, metrics, and telemetry stay out of the dump. See [Backing up and restoring AIDB](../../install/backup-and-restore) and [Upgrading from 7.9.0](#upgrading-from-790). |
| Enhancement | Debian 13 and RHEL 10: AIDB packages are available for Debian 13 and RHEL 10, for Postgres 15 to 18. These packages aren't FIPS builds. See [Supported platforms](../../compatibility#supported-platforms). |
| Enhancement | Group role owners: A role that can `SET ROLE` to a pipeline's owner role, including through a group role, can update and delete the pipeline. Before, only the owner role itself or a superuser could. See [Pipeline ownership](../../data-pipelines/reference#pipeline-ownership). |
| Change      | Encode memo: `aidb.encode_text()`, `aidb.encode_text_query()`, `aidb.encode_image()`, `aidb.encode_text_batch()`, and `aidb.encode_text_query_batch()` are now `STABLE`, and each place a single-input encode call appears in a query reuses its last result, so a vector search over a sequential scan calls the model once instead of once per row. The new `aidb.encode_memo` setting, on by default and settable by any role, turns the reuse off. See [Encode memo](../../install/configure#aidbencode_memo) and [Upgrading from 7.9.0](#upgrading-from-790). |
| Change      | Encode functions return `vector`: `aidb.encode_text()`, `aidb.encode_text_query()`, `aidb.encode_image()`, `aidb.encode_text_batch()`, and `aidb.encode_text_query_batch()` return pgvector's `vector` type instead of `real[]`. You no longer need a `::vector` cast. See [Upgrading from 7.9.0](#upgrading-from-790). |
| Change      | Function volatility: Many read-only AIDB functions are now marked `STABLE` or `IMMUTABLE` instead of `VOLATILE`. |
| Change      | Owner-only pipeline changes: Only a role that can `SET ROLE` to a pipeline's owner role can create, run, update, or delete the pipeline, or change its steps, knowledge base, and runtime state. A direct `UPDATE` or `DELETE` by another role affects no rows. On Postgres 16 and later, a role granted the owner role `WITH SET FALSE` no longer qualifies. See [Pipeline ownership](../../data-pipelines/reference#pipeline-ownership). |
| Change      | Owner-only agents, SQL tools, and plugins: `aidb.agents`, `aidb.sql_tool_registry`, and `aidb.agent_plugins_registry` have a new `owner_role` column. Only a role that can `SET ROLE` to the owner can update or delete the object. `aidb_users` can no longer write to the `aidb.agent_plugins`, `aidb.agent_tasks`, and `aidb.conversation_log` views. See [`aidb.agents`](../../reference/agents#aidbagents) and [Upgrading from 7.9.0](#upgrading-from-790). |
| Change      | Tool name conflicts: An MCP tool can no longer have the name of a SQL tool. `aidb.import_mcp_tools()` and `aidb.refresh_mcp_tools()` refuse it, and a name that's both a SQL tool and an MCP tool isn't run. See [Upgrading from 7.9.0](#upgrading-from-790). |
| Change      | Shared MCP headers: Tools of an MCP server registered with stored headers can be called only by the owner, members of the owner role, members of `aidb_admins`, and superusers, unless the server is shared. `aidb.import_mcp_tools()` takes a new `share` argument, `aidb.mcp_registry` has a new `shared` column, and `aidb.set_mcp_shared()` changes sharing later. See [`aidb.set_mcp_shared`](../../reference/tools#aidbset_mcp_shared). |
| Change      | Agent task visibility: `aidb.agent_tasks` shows only the tasks that the session user started. Members of `aidb_governance` and `aidb_admins`, and superusers, still see all tasks. See [`aidb.agent_tasks`](../../reference/agents#aidbagent_tasks). |
| Change      | Agent self-update: An agent that calls `update_agent` on itself can keep or remove tools, but can't add tools, directly or through plugins. See [`aidb.update_agent`](../../reference/agents#aidbupdate_agent). |
| Change      | Read-only `execute_sql`: when a role's `default_transaction_read_only` resolves to `on`, the MCP endpoint runs each `execute_sql` statement inside a `BEGIN READ ONLY` block, so `DO` or `CALL` commits, `ALTER ROLE`, and `PREPARE TRANSACTION` can no longer write. Read-only roles can no longer run `VACUUM`, `CONCURRENTLY` commands, or committing procedures through `execute_sql`. The setting guards against accidental writes and isn't a security boundary, so limit the role with grants. See [Configuring read-only roles](../../mcp-endpoint/configuring-agent-roles#configuring-read-only-roles) and [Upgrading from 7.9.0](#upgrading-from-790). |
| Change      | Volume privileges: AIDB volume functions check the same privileges as SQL on the volume's foreign table. Reading or listing a volume needs `SELECT`, writing needs `INSERT`, and deleting a file needs `SELECT` and `DELETE`. Each also needs `USAGE` on the volume's schema. Grants on the `pgfs.v_foreign_table_options` and `pgfs.v_server_options` views are no longer needed. See [Volume privileges](../../external-data-sources#volume-privileges). |
| Change      | Plaintext HTTP: With `aidb.allow_insecure_egress` set to `on`, AIDB allows plaintext `http://` requests to any host, not only to loopback and private addresses. The egress allowlist still applies. The same rule applies to `aidb.agent_memory_server_address`. See [Network egress](../../install/configure#network-egress). |
| Change      | SQL tool placeholders: `aidb.create_sql_tool()` rejects a statement with a positional placeholder such as `$1`. Tools use `${name}`. A tool that fails with `$name`, `:name`, or `{{name}}` gets a hint that shows the `${name}` form. See [`aidb.create_sql_tool`](../../reference/tools#aidbcreate_sql_tool). |
| Change      | llama.cpp agent compaction: Agents that use a `llamacpp_generate` model compact their history based on the model's `n_ctx` setting. With the default `n_ctx` of 4096, they compact a little earlier than before. |
| Change      | Orphaned pipelines: A pipeline whose owner role someone renamed or dropped now stops processing, and a superuser or an `aidb_admins` member can disable or delete it. Switching it to `Live` or `Background` fails with an error that names the role and how to recover. See [Recovering a pipeline with a renamed or dropped owner role](../../data-pipelines/troubleshooting#recovering-a-pipeline-with-a-renamed-or-dropped-owner-role) and [Upgrading from 7.9.0](#upgrading-from-790). |
| Bug fix     | Stalled model requests: A `statement_timeout` or query cancel now ends a call waiting on a chat model whose provider never answers, for the OpenAI Responses, Anthropic Messages, Gemini, and chat completions providers. Previously the backend waited until the provider replied. See [Budgets and limits](../../agents/conversing-with-agents#budgets-and-limits). |
| Bug fix     | `max_iterations` above 21: The agent loop now allows up to `max_iterations` + 4 rounds, or 25, whichever is larger. Before, it always stopped after 25 rounds. See [Budgets and limits](../../agents/conversing-with-agents#budgets-and-limits). |
| Bug fix     | Agent time budget: An agent's `timeout_seconds` now limits each model request, compaction, and delegate call. A delegate gets the earlier of its own deadline and its parent's. A tool that hasn't started when the time runs out is skipped. See [Timeout](../../agents/conversing-with-agents#timeout). |
| Bug fix     | Config helpers in SQL functions: `aidb.chunk_text()`, `aidb.parse_html()`, `aidb.parse_pdf()`, `aidb.parse_document()`, `aidb.pdf_to_image()`, `aidb.perform_ocr()`, `aidb.summarize_text()`, `aidb.generate_text()`, and `aidb.generate_text_batch()` accept their options as `JSONB` or `TEXT`. A config helper such as `aidb.chunk_text_config()` no longer needs a `::json` cast. See [Functions reference](../../reference/functions). |
| Bug fix     | Pipeline triggers without table ownership: A pipeline owner that doesn't own the source table can switch a `Live` or `Background` pipeline to another mode and delete it. |
| Bug fix     | Strict MCP servers: When AIDB imports or calls MCP tools, it sends `Accept: application/json, text/event-stream` and runs the MCP `initialize` handshake. Servers that answered `406` or required a session now work. |
| Bug fix     | Co-installing packages: The Postgres, EDB Postgres Advanced Server, and EDB Postgres Extended packages of AIDB can be installed on the same host. |

## Upgrading from 7.9.0

-   **Encode functions return `vector`.** The upgrade stops if a view, column default, or `BEGIN ATOMIC` function depends on `aidb.encode_text()`, `aidb.encode_text_query()`, `aidb.encode_image()`, `aidb.encode_text_batch()`, or `aidb.encode_text_query_batch()`. The error names each object. Save their definitions, drop them, run `ALTER EXTENSION aidb UPDATE` again, then recreate them. Where a definition treats the result as an array, use `vector_dims()` instead of `cardinality()` or `array_length()`, or cast with `::real[]`. Don't use `DROP EXTENSION` or `DROP ... CASCADE`. The upgrade doesn't check PL/pgSQL functions and application SQL, so check them yourself.
-   **Read-only roles can't run some commands through `execute_sql`.** Roles whose `default_transaction_read_only` resolves to `on`, including every role when it's set server-wide or with `ALTER DATABASE`, can no longer run `VACUUM`, `CREATE INDEX CONCURRENTLY`, `REINDEX CONCURRENTLY`, or procedures that commit. Run those as a read-write role. Read-only roles also need `EXECUTE` on `pg_catalog.pg_export_snapshot()`, which `PUBLIC` holds by default. If you revoked it, grant it back to `PUBLIC` or to the agent role. See [Configuring read-only roles](../../mcp-endpoint/configuring-agent-roles#configuring-read-only-roles).
-   **On WarehousePG, the coordinator needs access to your models.** An encode call with constant arguments, such as the query side of `ORDER BY embedding <=> aidb.encode_text_query('my_model', 'my query')`, now runs once on the coordinator before the coordinator dispatches the query to the segments. The coordinator needs network egress and credentials for that model, and its AIDB settings apply to the call. Calls with a column argument still run on the segments.
-   **A restore can fail to load agent memory.** `ALTER EXTENSION aidb UPDATE` prints a warning if the built-in `pg_agents` memory namespace has an ID other than 1, which can happen on a database that called `aidb_memory.init()` on AIDB 7.6.0 and was then upgraded through 7.7.0. Dump such a database with `--exclude-table-data='aidb_memory.*'` and contact [EDB Support](https://support.enterprisedb.com) to move agent memory over. See [Handling the agent memory warning when updating the extension](../../install/backup-and-restore#handling-the-agent-memory-warning-when-updating-the-extension).
-   **A pipeline whose owner role is gone stops processing.** On 7.9.0, a pipeline kept processing through its `Live` trigger and `Background` worker after someone renamed its owner role. After the upgrade, its `Live` trigger raises an error, so `INSERT`, `UPDATE`, and `DELETE` statements on the source table fail, and its `Background` worker stops. Before you run `ALTER EXTENSION aidb UPDATE`, find pipelines whose owner role doesn't exist:

    ```sql
    SELECT name, owner_role, auto_processing
    FROM aidb.pipelines
    WHERE owner_role NOT IN (SELECT rolname FROM pg_catalog.pg_roles);
    __OUTPUT__
        name     | owner_role | auto_processing
    -------------+------------+-----------------
     my_pipeline | alice      | Background
    (1 row)
    ```

    For each one, rename the owner role back, or disable or delete the pipeline. See [Recovering a pipeline with a renamed or dropped owner role](../../data-pipelines/troubleshooting#recovering-a-pipeline-with-a-renamed-or-dropped-owner-role).
-   **Renaming an MCP server's owner role leaves the server without an owner.** AIDB now stores the owner in `aidb.mcp_registry.owner` as a role name instead of an OID, so the owner no longer follows a rename. Once someone renames or drops the owner role, no role can refresh or delete the server until a role with that name exists again, for example after you rename the role back. The upgrade sets the owner of a server whose owner role was already dropped to `unknown (OID=n)`, which names no role. To remove such a server, a superuser can run `DELETE FROM aidb.mcp_registry WHERE name = '<server>'`, then register it again with `aidb.import_mcp_tools()` if it's still needed. See [MCP tools](../../tools/mcp-tools#authentication).
-   **Existing agents, SQL tools, and agent plugins are owned by `aidb_users`.** Every member of `aidb_users` can still change them. To restrict one to a role, a superuser runs `UPDATE aidb.agents SET owner_role = '<role>' WHERE name = '<name>'`, or the same on `aidb.sql_tool_registry` or `aidb.agent_plugins_registry`.
-   **MCP servers with stored headers stop being shared.** Servers registered with `headers`, `headers_env`, or `headers_k8s_secret` become unshared, so other members of `aidb_users` can no longer call their tools. To share one, the owner runs `SELECT aidb.set_mcp_shared('<server>', true)`. Servers without headers stay shared.
-   **Tools that are both a SQL tool and an MCP tool no longer run.** The upgrade warns with their names. Delete the SQL tool with `aidb.delete_tool()`, or exclude the tool from its MCP server with `tool_filter` and `aidb.import_mcp_tools()`.
-   **Volume access needs table privileges.** A role that uses a volume it doesn't own, such as a pipeline owner role, needs `USAGE` on the volume's schema and `SELECT`, `INSERT`, or `DELETE` on the volume, depending on the operation. For example: `GRANT SELECT ON my_volume TO pipeline_owner`. See [Volume privileges](../../external-data-sources#volume-privileges).
-   **Pipeline owners need the `SET ROLE` right.** On Postgres 16 and later, a role granted a pipeline's owner role `WITH SET FALSE` can no longer create, change, or delete that role's pipelines. Grant it `WITH SET TRUE` instead.
-   **Custom grants on delete functions are lost.** The upgrade drops and recreates the nine `delete_*` functions that take `if_exists`. Grants to `aidb_users` and `aidb_governance` are restored. Re-run any other `GRANT EXECUTE` on these functions.
-   **Agent tasks from before the upgrade** that AIDB can't link to a user are visible only to members of `aidb_governance` and `aidb_admins`, and superusers.
