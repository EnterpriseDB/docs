The `edbctl disaster-recovery` command manages disaster recovery (DR) operations for HM-internal database clusters. Use it to create restore ObjectStore custom resources, prepare cluster configurations for DR bootstrap, and turn off streaming to a location that is permanently lost. You can also use the `edbctl dr` alias for this command.

## Commands

`edbctl disaster-recovery` command has the following options:

-   [edbctl disaster-recovery create-restore-objectstores](#edbctl-disaster-recovery-create-restore-objectstores) — Create the restore ObjectStore CRs for disaster recovery, for the HM-internal database clusters.
-   [edbctl disaster-recovery prepare-cluster-configs](#edbctl-disaster-recovery-prepare-cluster-configs) — Prepare cluster configs for disaster recovery, for the HM-internal database clusters.
-   [edbctl disaster-recovery set-location-streaming](#edbctl-disaster-recovery-set-location-streaming) — Enable or disable streaming of remote resources to a location.

### edbctl disaster-recovery create-restore-objectstores

For each CloudNativePG (CNPG) cluster that uses the Barman plugin, creates an ObjectStore custom resource (with a name ending in `-restore`) with a transformed destination path for disaster recovery. Clusters with an inline `barmanObjectStore` config are skipped.

Only HM-internal clusters are included. Customer clusters with names starting with `p-` and the `stats-collector-db` cluster are excluded.

Run this command before running `prepare-cluster-configs`.

```
edbctl disaster-recovery create-restore-objectstores [options]
```

Where `options` are:

```
    --dry-run   Preview the ObjectStore CRs that would be created without applying them.
-y, --yes       Auto-confirm all confirmations.
-h, --help      Help for create-restore-objectstores.
```

These examples show how to create restore ObjectStore CRs:

```
edbctl dr create-restore-objectstores
edbctl dr create-restore-objectstores --dry-run
```

### edbctl disaster-recovery prepare-cluster-configs

Downloads CNPG Cluster custom resources from the current Kubernetes context and prepares modified configurations for disaster recovery bootstrap. Original configs are saved as backups, and new configs are written with recovery bootstrap settings.

This command does not apply any changes to the cluster. Run `create-restore-objectstores` first to create the restore ObjectStore CRs before running this command.

Only HM-internal clusters are included. Customer clusters with names starting with `p-` and the `stats-collector-db` cluster are excluded.

```
edbctl disaster-recovery prepare-cluster-configs --old-backup-id <backup-id> [options]
```

Where `options` are:

```
    --old-backup-id string   The backup ID from the old system (required).
-o, --output-dir string      Base output directory for generated configs (default ".").
-h, --help                   Help for prepare-cluster-configs.
```

This example shows how to prepare cluster configs for disaster recovery:

```
edbctl dr prepare-cluster-configs --old-backup-id abc123
```

### edbctl disaster-recovery set-location-streaming

Enables or disables streaming of remote resources, such as cluster resources, backups, and beacon apps, to a location's agent. While streaming is disabled, changes to the location's resources are skipped and deletions complete without reaching the agent. Use it when a location is permanently lost, so that its resources can be cleaned up. Operational traffic, such as SQL queries, is unaffected.

This command requires Hybrid Manager 2026.11 or later. Unlike the other `disaster-recovery` commands, it calls the Hybrid Manager API, so it uses your edbctl credential rather than the Kubernetes context.

Only the streaming setting is changed. The location's display name and tags are kept. A managed location is shared by every project, so changing it affects all of them and requires organization-level permission.

```
edbctl disaster-recovery set-location-streaming --id <location-id> (--enable | --disable) [--project <project-name>] [options]
```

Where `options` are:

```
-i, --id string           Location ID (required).
    --enable              Enable streaming of remote resources.
    --disable             Disable streaming of remote resources.
-P, --project string      Project name (optional). Narrows the location lookup. When omitted, the location is looked up across all the projects you can access. Not needed for managed locations, which don't belong to any project.
-c, --credential string   The credential that you created via the `credential create` command. The default is fetched from `context_credential`.
-y, --yes                 Auto-confirm all confirmations.
-h, --help                Help for set-location-streaming.
```

These examples show how to disable and re-enable streaming to a location:

```
edbctl dr set-location-streaming --id loc-abc123 --disable
edbctl dr set-location-streaming --id loc-abc123 --enable
edbctl dr set-location-streaming --project "My Project" --id loc-abc123 --disable
```
