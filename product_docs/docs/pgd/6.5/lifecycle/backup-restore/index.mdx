Back up your EDB Postgres Distributed (PGD) cluster to protect your data, to create new clusters from existing data, such as QA or development instances, or to move data into or out of PGD. Restore from a backup for disaster recovery, for example if you lose all nodes in the cluster or if significant, uncorrectable data corruption affects multiple nodes as a result of application error or a security breach. If you lose only some of your nodes, clone new nodes directly from the remaining nodes instead. In a distributed, highly available system like PGD, cloning is the best way to replace them.

* [Performing physical backups](physical) &mdash; Physical backups copy the files of a node's Postgres instance, including all of its databases. Back up a node, restore a cluster from the backup, and recover to a point in time.

* [Backing up and restoring with pg_dump](pg_dump) &mdash; Export the contents of a database with `pg_dump`, then restore it to create new clusters from existing data or to move data into or out of PGD.
