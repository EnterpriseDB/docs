Use audit reports to hand the activity recorded for an `aidb` database to an auditor, or to keep a copy outside the application. An audit report is a CSV file. When the application exports one, it records the file's SHA-256 hash, so anyone with access to the same application can later check that the file they hold is the one that was exported, byte for byte.

Audit reports are available for `aidb` databases only. HM and Loki sources don't offer them.

## Exporting an audit report

You need the Administrator role to export. Other users don't see the export button.

1. Open the cluster and go to the [Activity](./sessions_list) page. Set the filters to the activity you want in the report: date range, agents, identifier, activity type, and decision status. The report covers what the filters select, not just the rows shown on the current page.

   To export a single session, connection, conversation, or trace, open it instead and use the button on the [session page](./session_detail).

2. Select Export Audit Report. The dialog repeats the selection the report will cover: Instance, Activity, Date, Agents, Identifier, Activity Type, and Status. To change it, close the dialog and adjust the filters.

3. Leave Include Sensitive Content off unless the auditor needs the raw query text and user inputs. When it's off, those fields are left out of the file and the report says so.

4. Select Export. The browser downloads the file, and a notice confirms Audit report exported successfully with a Verify this report link.

Keep the file as it was downloaded. Opening it in a spreadsheet and saving it again changes the bytes, and verification will then fail.

### What the file contains

The file is UTF-8 CSV with a byte order mark. The first row is a metadata record (`record_type` is `metadata`) that identifies the export: its `export_id`, the instance, who exported it, when, the selection filters, whether sensitive content was included, the retention settings of the source database at export time, and the range of recorded activity the database held. Each following row is one activity record with the same columns the Activity page shows. The last column of the metadata row, `checksum_sha256`, holds the hash of the file with that column zeroed, so the file can also be checked offline.

The application stores only a receipt of each export: the export identifier, the hash, the file size, the record count, who exported it, and when. It doesn't keep a copy of the report.

## Verifying an audit report

Any signed-in user can verify a report, whatever their role.

1. Open the cluster menu in the header and select Verify audit report, or follow the Verify this report link after an export. The page is also at `/verify`.
2. Drop the CSV file on the page or select it. The file must be a CSV of at most 50 MB.

The page then shows one of these results:

- File Verified — The file's hash matches the receipt. The page shows the receipt's details: Exported By (name, email, and identity-provider subject of the user who exported it), Timestamp, Scope & Filters (instance, time range, agents, identifier, activity types, decisions), Record Count, and Sensitive Content (Included or Excluded). Compare them with what you expected the report to cover.
- Verification Failed, with the reason:
  - The file's hash does not match the original record — The file was altered, re-saved, truncated, or is a different export than the receipt describes.
  - No trusted audit record was found for this export — The application has no receipt for this `export_id`. Check that you're using the Agent Governance installation that created the report; receipts aren't shared between installations.
  - Choose an original Governance CSV audit report — The file isn't an audit report from this application, or its metadata row is incomplete.
  - The file exceeds the upload size limit, or Verification is busy — Try again with a smaller export, or later.

Verification compares the whole file with the receipt. It doesn't inspect the rows, so it can't tell which rows changed, only that the file differs.
