The Dashboard is the first page you see when you open a cluster. It summarizes the cluster's agent activity and links to the detailed views.

## Opening a dashboard

Select a cluster card on the home page to open its Dashboard, or use Search clusters... to filter the list first. The home page lists every cluster across all configured instances. Each cluster card shows the cluster name and, for HM and Loki clusters, its status and project; a Postgres database running `aidb` shows the tag Postgres (aidb_otel).

If no instances are configured yet, the home page shows No instances configured yet with a Configure Instances button. If an instance can't be reached, the page shows Could not load clusters from followed by the instance name. See [Connecting an aidb database](./connecting_aidb) and [Connecting Hybrid Manager or Loki](./connecting_data_sources).

## Moving around a cluster

Use the sidebar on the left inside a cluster to move between pages. It lists:

- Dashboard — This overview.
- Activity — Every session, connection, conversation, or trace recorded for the cluster. See [Browsing activity](./sessions_list).
- Agents — The registered agents, their permissions, and their denial profile. Available for `aidb` databases only. See [Reviewing agents](./agents).

The breadcrumb at the top of each page starts with Governance, which returns you to the home page, as does the instance name at the top of the sidebar. The button at the bottom of the sidebar switches between light and dark mode. On narrow screens, select Open navigation to show the sidebar.

## Reading the dashboard for an aidb database

Read these cards to see the activity and governance decisions for an `aidb` database at a glance:

| Card                   | What it counts                                                                                     |
|------------------------|----------------------------------------------------------------------------------------------------|
| Groups Observed    | Sessions, connections, and traces recorded in `aidb_otel`.                                         |
| Total Spans        | Units of work traced — every span `aidb` recorded.                                                 |
| Approved Decisions | Governance decisions that allowed the agent's action, with their share of all decisions.          |
| Denied Decisions   | Governance decisions that blocked the agent's action, with their share of all decisions.          |

The counts cover all telemetry currently stored in the database; rows removed by retention no longer count. If the chart value `bff.governanceDecisionsEnabled` is `false`, the decision cards show a dash.

Below the cards:

- Recent Activity — The latest sessions, connections, and traces, with their type, identifier, purpose, decisions, and number of spans. Select an identifier to open it. See [Inspecting a session](./session_detail).
- Top Agents — Up to six agents with the most steps, with their approved and denied counts. Select an agent to open Activity filtered to that agent.

## Reading the dashboard for an HM or Loki source

Read these cards to see the session activity for an HM or Loki source at a glance:

| Card                  | What it counts                                           |
|-----------------------|----------------------------------------------------------|
| Sessions Observed | Airman MCP sessions recorded in the Postgres logs.       |
| Recorded Steps    | Postgres log records that belong to those sessions.      |
| Errors            | Statements that recorded an error, including denials.    |
| Denied Queries    | Statements the database refused with an access denial.   |

Below the cards, Recent Activity lists the most recently active sessions, and Top Purposes lists the five purposes with the most steps. Select a purpose to open Activity filtered to it.

If the dashboard can't load, it shows Failed to load dashboard with a Retry button.
