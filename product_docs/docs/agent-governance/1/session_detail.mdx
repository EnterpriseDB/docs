Use the session page to see what an agent did in one session, connection, conversation, or trace, step by step. Open it by selecting an identifier on the [**Activity**](./sessions_list) page or in **Recent Activity** on the [**Dashboard**](./dashboard). The breadcrumb shows **Governance › Activity ›** followed by the identifier; select **Activity** to go back to the list.

The page has a context card at the top and two tabs: **Reconstruction** and **Participating Agents**.

## Reading the context card

The context card summarizes where the activity came from.

| Source            | Fields                                                                                                                              |
|-------------------|-------------------------------------------------------------------------------------------------------------------------------------|
| `aidb` database   | The identifier, **Started**, **User Context**, **Resolved From**, **OBO Principal**, **Duration**, **Declared Purpose**, and **Database**. |
| HM or Loki source | **Session ID**, **Started**, **Database Role**, **Declared Purpose**, **Database**, **PostgreSQL Connection ID**, and **Application Name**. |

## Stepping through the reconstruction

The **Reconstruction** tab lists the steps on the left and shows the selected step's details on the right.

### Step list for an aidb database

The list shows only **governed steps** — the steps `aidb` recorded a governance decision for — with a count such as "4 governed steps of 37 spans". Each step shows its verdict (**Approved**, **Denied**, or **Escalated**), the reason, and the time.

Use **Search steps...** to find a step, and the **Approved**, **Escalated**, and **Denied** chips to show or hide steps by verdict. Long sessions load in pages; select **Load more steps** to read further.

### Step list for an HM or Loki source

The list shows every SQL statement the agent executed. Use the **Recorded**, **Error**, and **Denied** chips to show or hide statements by outcome.

### Step details

For the selected step, **Step Details** shows its name, start and end time, and duration, and:

- **Decision** — For an `aidb` database, whether the action was **Allowed**, **Denied**, or **Escalated**, and when.
- **SQL** or **Drafted SQL** — For an HM or Loki source, **SQL** is the statement that ran. For an `aidb` database, **Drafted SQL** is the statement the agent submitted with the step, whatever the decision. Select **Copy query** to copy it.
- **Execution Stats** — **Duration**, **Busy Time**, and **Idle Time**.
- For a denied or escalated step: **Denial Reason**, **OBO Principal**, **Role**, and **Decision ID**. Use the decision ID to find the same decision in `aidb`, or with **Find by decision id** on the **Activity** page.
- For an HM or Loki source, the Postgres log fields: **SQLSTATE**, **Severity**, **Message**, **Detail**, **Database Role**, **Database**, **Declared Purpose**, **PostgreSQL Connection ID**, **PostgreSQL PID**, **Query ID**, and **Application Name**.

## Reviewing participating agents

The **Participating Agents** tab lists the agents that took part.

- For an `aidb` database, it shows each agent's steps, decisions, and when it was first and last seen, ten per page.
- For an HM or Loki source, it shows each agent's purpose and steps. Use **Search by agent or purpose** to filter the list.

## When the session doesn't load

If the session can't be read, the page shows **Failed to load session**, or one of the connection messages described in [Connecting an aidb database — Troubleshooting](./connecting_aidb#troubleshooting), with a **Retry** button. If some stored records can't be decoded, the step list says how many were skipped.

For an `aidb` database, retention can remove steps from a session over time; see [Retention and missing data](./connecting_aidb#retention-and-missing-data).
