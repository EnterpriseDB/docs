Use the session page to see what an agent did in one session, connection, conversation, or trace, step by step. Open it by selecting an identifier on the [Activity](./sessions_list) page or in Recent Activity on the [Dashboard](./dashboard). The breadcrumb shows Governance › Activity › followed by the identifier; select Activity to go back to the list.

The page has a context card at the top and two tabs: Reconstruction and Participating Agents.

## Reading the context card

Read the context card to see where the activity came from.

| Source            | Fields                                                                                                                              |
|-------------------|-------------------------------------------------------------------------------------------------------------------------------------|
| `aidb` database   | The identifier, Started, User Context, Resolved From, OBO Principal, Duration, Declared Purpose, and Database. |
| Hybrid Manager (HM) or Loki source | Session ID, Started, Database Role, Declared Purpose, Database, PostgreSQL Connection ID, and Application Name. |

## Stepping through the reconstruction

Use the Reconstruction tab to step through the session. It lists the steps on the left and shows the selected step's details on the right.

### Reading the step list for an aidb database

Review the governed steps, which are the steps `aidb` recorded a governance decision for. The list shows only these steps, with a count such as "4 governed steps of 37 spans". Each step shows:

- Its verdict: Approved, Denied, or Escalated
- The reason
- The time

Use Search steps... to find a step, and the Approved, Escalated, and Denied chips to show or hide steps by verdict. Long sessions load in pages. Select Load more steps to read further.

### Reading the step list for an HM or Loki source

Review the list of every SQL statement the agent executed. Use the Recorded, Error, and Denied chips to show or hide statements by outcome.

### Reading step details

Select a step to open Step Details, which shows the step's name, start time, end time, and duration. Then review the following details:

- Check the Decision for an `aidb` database: Allowed, Denied, or Escalated, and when it was made.

- Review the statement, and select Copy query to copy it:
  - For an `aidb` database, Drafted SQL is the statement the agent submitted with the step, whatever the decision.
  - For an HM or Loki source, SQL is the statement that ran.

- Review Execution Stats: Duration, Busy Time, and Idle Time.

- For a denied or escalated step, review these fields:
  - Denial Reason
  - OBO Principal
  - Role
  - Decision ID. Use it to find the same decision in `aidb`, or with Find by decision id on the Activity page.

- For an `aidb` database running 7.9.0 or later, review Referenced Database Objects: the tables, views, and other objects the statement named.
  - The list can be cut short. When it is, the page says how many names were left out.
  - The list doesn't single out the object a denial was about, so it isn't a complete access audit.

- For an `aidb` database running 7.9.0 or later, check the PostgreSQL refusal details when PostgreSQL itself refused the statement for lack of privileges:
  - Denial Class
  - Denial Message
  - SQLSTATE

  A statement that governance blocked before it reached the database has none of these three, because there was no database error. On older `aidb` versions, the referenced objects and refusal details aren't shown.

- For an HM or Loki source, review the Postgres log fields: SQLSTATE, Severity, Message, Detail, Database Role, Database, Declared Purpose, PostgreSQL Connection ID, PostgreSQL PID, Query ID, and Application Name.

## Reviewing participating agents

Open the Participating Agents tab to see the agents that took part.

- For an `aidb` database, review each agent's steps, decisions, and when it was first and last seen. The list shows ten agents per page.
- For an HM or Loki source, review each agent's purpose and steps. Use Search by agent or purpose to filter the list.

## Troubleshooting a session that doesn't load

Select Retry if the session can't be read. The page shows Failed to load session, or one of the connection messages described in [Troubleshooting](./connecting_aidb#troubleshooting) on the Connecting an aidb database page, with a Retry button. If some stored records can't be decoded, the step list says how many were skipped.

Check your retention settings if steps are missing from an `aidb` session. Retention can remove steps from a session over time. See [Handling retention and missing data](./connecting_aidb#handling-retention-and-missing-data).
