`ivfplus` supports `WHERE`-clause filtering and hybrid search alongside full-text search, using the same SQL patterns as any other pgvector-compatible index.

## Filtering

A `WHERE` clause on an `ivfplus`-indexed table works like any other index scan:

```sql
SELECT * FROM items WHERE category_id = 123 ORDER BY embedding <-> '[3,1,2]' LIMIT 5;
```

Filtering is applied after the index scan, as with pgvector's `ivfflat`, so a selective filter can return fewer than `LIMIT` rows.

To improve performance on filtered queries, consider using a partial index:

```sql
CREATE INDEX ON items USING ivfplus (embedding vector_l2_ops) WHERE (category_id = 123);
```

or widen `probes` (see [Tuning and sizing](tuning#choosing-probes)).

## Hybrid search

Compose hybrid search at the SQL level exactly as with pgvector — this doesn't depend on the access method, so pgvector's own hybrid search examples apply unchanged. Merge the full-text and `ivfplus` result sets with Reciprocal Rank Fusion or a cross-encoder:

```sql
SELECT id, content FROM items, plainto_tsquery('hello search') query
WHERE textsearch @@ query ORDER BY ts_rank_cd(textsearch, query) DESC LIMIT 5;
```
