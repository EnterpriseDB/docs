Install Vector Plus from an EDB package repository.

## Supported versions and platforms

Packaged: Postgres 14, 15, 16, 17, 18 on all three variants:

| Variant  | Server package the extension depends on |
|----------|-----------------------------------------|
| postgres | `postgresql-<V>`                        |
| extended | `edb-postgresextended<V>-server`        |
| advanced | `edb-as<V>-server`                      |

| Distro               | Version       | Architectures                | Package type |
|----------------------|---------------|------------------------------|--------------|
| EL (RHEL/Rocky/Alma) | 8             | amd64, ppc64le, s390x        | rpm          |
| EL (RHEL/Rocky/Alma) | 9             | amd64, arm64, ppc64le, s390x | rpm          |
| SLES                 | 15SP7         | amd64, ppc64le, s390x        | rpm          |
| Debian               | 11 (bullseye) | amd64                        | deb          |
| Debian               | 12 (bookworm) | amd64, arm64                 | deb          |
| Ubuntu               | 22.04 (jammy) | amd64                        | deb          |
| Ubuntu               | 24.04 (noble) | amd64                        | deb          |

## Installing from an EDB repository

### Configuring the repository

Replace `EDB_SUBSCRIPTION_TOKEN` with your EDB repository token (EDB Account → repository token) and `EDB_REPOSITORY` per the table below.

```shell
# RPM platforms (EL, SLES)
curl -1sLf "https://downloads.enterprisedb.com/$EDB_SUBSCRIPTION_TOKEN/$EDB_REPOSITORY/setup.rpm.sh" | sudo -E bash

# DEB platforms (Debian, Ubuntu)
curl -1sLf "https://downloads.enterprisedb.com/$EDB_SUBSCRIPTION_TOKEN/$EDB_REPOSITORY/setup.deb.sh" | sudo -E bash
```

| `EDB_REPOSITORY` | Who                                                                                                     | Contains                                  |
|-------------------|-----------------------------------------------------------------------------------------------------------|-------------------------------------------|
| `enterprise`      | Customers with an EDB Postgres Advanced Server (EPAS) / EDB Postgres Extended Server (PGE) subscription | Released packages, all three variants      |
| `standard`        | Customers on a Standard subscription                                                                     | Released packages                          |
| `community360`    | Community 360 subscribers                                                                                | Released packages (community PostgreSQL)   |
| `edb`             | IBM-bound platforms                                                                                       | The s390x channel                          |

On s390x, use `edb` in place of `enterprise`. Customer and field installs use `enterprise` (or `standard`/`community360` to match the subscription), which carry release-maturity packages only.

### Installing the package

Install Vector Plus, which also installs pgvector as a dependency:

```shell
sudo dnf install -y edb-<variant><V>-vectorplus # EL
sudo zypper install -y edb-<variant><V>-vectorplus # SLES
sudo apt-get install -y edb-<variant><V>-vectorplus # Debian / Ubuntu
```

Replace `<variant>` with `pg` (community PostgreSQL), `as` (EPAS), or `postgresextended` (PGE), and `<V>` with your Postgres major version — for example, `edb-pg17-vectorplus` for PostgreSQL 17.

`<V>` is the Postgres major version. The package name carries no extension-major suffix, so it's identical on RPM and DEB:

| Postgres variant                    | Package name                         | Installs under                               |
|-------------------------------------|--------------------------------------|----------------------------------------------|
| PostgreSQL                          | `edb-pg<V>-vectorplus`               | `/usr/pgsql-<V>` · `/usr/lib/postgresql/<V>` |
| EDB Postgres Extended (PGE)         | `edb-postgresextended<V>-vectorplus` | `/usr/edb/pge<V>` · `/usr/lib/edb-pge/<V>`   |
| EDB Postgres Advanced Server (EPAS) | `edb-as<V>-vectorplus`               | `/usr/edb/as<V>` · `/usr/lib/edb-as/<V>`     |

pgvector comes from the same repository and is pulled in automatically as `edb-<variant><V>-pgvector0` — it carries its own extension-major suffix, which RPM concatenates and DEB hyphenates: `edb-<variant><V>-pgvector0` on RPM, `edb-<variant><V>-pgvector-0` on DEB. On community Postgres, the DEB also declares `Provides: postgresql-<V>-vectorplus` and the RPM `Provides: vectorplus_<V>`.

If an older pgvector is already installed, installing Vector Plus doesn't upgrade it automatically — resolve the pgvector version manually before continuing.

### Enabling the extension

Enable the extension. `CASCADE` creates pgvector's `vector` type first, which `edb_vectorplus` requires:

```sql
CREATE EXTENSION edb_vectorplus CASCADE;
```

No `shared_preload_libraries` entry and no restart are needed.

## Quickstart

```sql
CREATE EXTENSION IF NOT EXISTS edb_vectorplus CASCADE; -- pulls in pgvector

CREATE TABLE items (id bigserial PRIMARY KEY, embedding vector(768));
COPY items (embedding) FROM '/path/to/embeddings.csv'; -- load BEFORE indexing

CREATE INDEX items_embedding_idx ON items
USING ivfplus (embedding vector_l2_ops) WITH (lists = 1000);

SET ivfplus.probes = 32;
SELECT id FROM items ORDER BY embedding <-> '[...]' LIMIT 10;

SELECT * FROM check_ivfplus_index_health('items_embedding_idx');
```

That's the whole interface for the common case:

| Decision | Where                                            | Default         | Start at                                    |
|----------|--------------------------------------------------|-----------------|---------------------------------------------|
| `lists`  | `WITH (...)` at build                            | 100             | rows/1000 up to 1M rows, `sqrt(rows)` above |
| `probes` | `SET ivfplus.probes`                             | 1               | `sqrt(lists)`, raise until recall suffices  |
| Opclass  | `CREATE INDEX ... USING ivfplus (col <opclass>)` | `vector_l2_ops` | Match your distance metric                  |

A few things worth knowing before you build an index:

- **`lists` isn't derived from table size.** Set to, say, 100, it stays 100 whether the table has a thousand rows or a billion. See [Tuning and sizing](tuning).
- **Index at a dimensionality that's a multiple of 4, and at most 1780.** Only those get the packed fast-scan layout; anything else falls back to a slower scan for the life of the index, and `CREATE INDEX` emits a `NOTICE` when it happens. See [Limits and fixed constants](reference#limits-and-fixed-constants).
- **Load data before `CREATE INDEX`.** The build clusters the rows that already exist at build time.
- **This is an approximate index.** Work through [Measuring recall](measuring-recall) before relying on it in production.
- **`CREATE INDEX` blocks writes on the table.** Use `CREATE INDEX CONCURRENTLY` in production.
- **Centroids are fixed for the life of the index.** Clustering happens once, at build time. A table that keeps changing drifts away from its centroids over time — new rows land in a slower append region until the index is rebuilt. `check_ivfplus_index_health()` reports this drift and recommends a `REINDEX CONCURRENTLY` when needed. See [Writes, VACUUM, and REINDEX](reference#writes-vacuum-and-reindex).
