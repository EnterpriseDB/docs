## Observability and monitoring

- The **Monitoring Overview** section now has its own dedicated dashboard area, including new tiles that display the total counts of high and medium severity alerts. <!-- JIRA: UPM-139553 -->
- Fixed an issue whereby monitoring queries pinned the `search_path` to `edb_internals`, which could cause failures when invoking `edb_wait_states` and `edb_stat_monitor` functions. <!-- JIRA: UPM-139869 — FLAG: ticket status is "Blocked / On Hold" (In Progress category) with no fixVersion set to HM 1.4.5 as of this audit. - Fixed an issue whereby an unhandled exception occurred on the **Recommendations** tab when a value of infinity was encountered. <!-- JIRA: UPM-140209 -->

## Migrations

- Added support for migrating Postgres large objects (`pg_largeobject`) for **Schema and Data** migrations. Since logical decoding can't capture large object writes, DMS now copies large object content separately during the Schema Finalization stage; enable it with the `LO_SNAPSHOT_ENABLED` parameter. 
<!-- JIRA: NEEDS KEY — backported from HM 2026.9.0 --><!-- LINK TBD: terminology.mdx#large-object-lo-migration not yet backported to the 1.4 tree -->
- Added support for optionally migrating a source cluster's roles, object ownership, privileges, and row-level security policies during schema migration to a self-managed Postgres destination, so your applications keep working with the same authorization model after cutover. See Migrating roles, ownership, and privileges.
