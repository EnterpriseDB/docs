## HM platform

- Fixed an issue whereby the bootstrap bundle for several Kubernetes flavors, including Nutanix NKP, applied an AppArmor annotation to the `prometheus-operator` deployment even on worker nodes that don't run AppArmor, which caused new pods to fail to schedule after an install or upgrade. <!-- JIRA: UPM-140351 — Done, fixVersion HM 1.4.5, label fixed-in-hm:v2026.11.0-alpha.4+appl. -->

## HM console

- Fixed an issue whereby a cluster's **Resource Usage** card appeared on the **Overview** page even when the `dbaas` scenario wasn't enabled. <!-- JIRA: UPM-139958 — Done, fixVersion HM 1.4.5 confirmed by audit. -->

## Observability and monitoring

- The **Monitoring Overview** section now has its own dedicated dashboard area, including new tiles that display the total counts of high and medium severity alerts. <!-- JIRA: UPM-139553 -->
- Fixed an issue whereby an unhandled exception occurred on the **Recommendations** tab when a value of infinity was encountered. <!-- JIRA: UPM-140209 -->

## Migrations

- Added support for migrating [Postgres large objects](/edb-postgres-ai/current/hybrid-manager/using_hybrid_manager/migration/terminology/#large-object-lo-migration) (`pg_largeobject`) for **Schema and Data** migrations. Since logical decoding can't capture large object writes, the Data Migration Service (DMS) now copies large object content separately during the **Schema Finalization** stage; enable it with the `LO_SNAPSHOT_ENABLED` parameter.
- Added support for optionally migrating a source cluster's roles, object ownership, privileges, and row-level security policies during schema migration to a self-managed Postgres destination, so your applications keep working with the same authorization model after cutover. See [Migrating roles, ownership, and privileges](/edb-postgres-ai/current/hybrid-manager/using_hybrid_manager/migration/schema_migration/migrating_roles_and_privileges/).
