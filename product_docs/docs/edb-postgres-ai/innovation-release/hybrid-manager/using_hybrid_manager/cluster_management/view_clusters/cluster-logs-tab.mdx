The **Logs** tab for a cluster in Hybrid Manager (HM) displays log entries collected from the cluster's pods, so you can trace events, warnings, and errors while debugging. You can filter the entries by service, pod, time range, and the structured fields of each entry.

## What the tab displays by default

By default, the **Logs** tab displays Postgres logs only. If you're looking for entries that aren't there, change the **Service Name** menu:

-   **Postgres** &mdash; logs from the Postgres database itself. This is the default.

-   **Beacon Agent** &mdash; logs from the [EDB Postgres AI agent](../../monitoring/mon_ext_dbs/mon_with_agent), which collects monitoring data and pushes it to HM. Select this when you're investigating data collection problems, such as missing metrics or gaps in monitoring data, rather than database problems.

When filtering by log field, **Severity** is the error severity reported by Postgres itself (`INFO`, `LOG`, `WARNING`, `ERROR`, `FATAL`, or `PANIC`), while **Level** is the log level recorded by the collector. Filter on **Severity** when you want the database's own assessment of an event.

## Availability

Log collection isn't available for every cluster type:

-   For HM-managed clusters, logs are collected by default.

-   For external self-managed clusters, the EDB Postgres AI agent must have log collection enabled. If this tab is empty for a self-managed cluster, check that `general.metrics.push.include_logs` is `true` and that `logs.disabled` is `false` for the relevant node. See [Fine-tuning monitoring data collection](../../monitoring/mon_ext_dbs/mon_with_agent/configure_agent/fine_tune_monitoring.mdx).

-   For external CSP-managed databases, such as AWS RDS, logs aren't collected and this tab has no data. See [Metrics support scope](../../monitoring/monitoring_console/support_scope.mdx).

## Retention and refresh

Log entries are retained for 30 days by default, so the time range you select can't reach further back than that. The tab refreshes every 10 seconds. See [Metrics refresh intervals](../../monitoring/monitoring_console/metrics_latency.mdx).

## Querying logs beyond this tab

HM collects logs into Loki. For queries this tab can't express, such as searching across several clusters at once, use [Grafana's Explore option](../../monitoring/monitoring_grafana/grafana_explore.mdx) to query Loki directly.
