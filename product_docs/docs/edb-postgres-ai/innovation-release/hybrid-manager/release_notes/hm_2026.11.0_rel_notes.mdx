!!!warning Every Postgres cluster restarts during this upgrade
This release bumps the Barman Cloud Plugin, which restarts every Postgres cluster in your estate as part of applying the HM upgrade — not on your own database maintenance schedule. If you manage a large estate and rely on scheduling platform and Postgres upgrades independently, plan for this before you upgrade.
!!!

This Innovation Release includes features and enhancements.

**Release date:** 12 Nov 2026

!!!important What to know before you upgrade to HM 2026.11

-   **The `edb-system` namespace.** Starting with HM 2026.11, the following components use the `edb-system` namespace instead of `default`:

    -   The Beacon server resources: your clusters, backups and backup schedules, locations, AI pipelines, and automations, plus the certificates and secrets that Beacon creates for each cluster.
    -   The app catalog: the OSS Library `PackageRepository` and the packages that it lists.
    -   The install secrets, such as `edb-object-storage`.

    The HM upgrade command automatically copies the Beacon server resources to `edb-system` and removes the old copies from `default`. It also automatically moves the `edb-object-storage` secret. You create the other install secrets, such as `hm-portal-bootstrap`, `langflow-secret`, and the `db-*` secrets, in `edb-system` before you upgrade. If you have scripts, monitoring, or `kubectl` commands that read these resources in `default`, update them to use `edb-system`.

-   **OSS Library apps.** The upgrade doesn't move OSS Library apps that you installed before it. They keep running, and EDB recommends that you delete and recreate them, preferably before the upgrade. See [Choose when to recreate OSS Library apps](/edb-postgres-ai/current/hybrid-manager/using_hybrid_manager/upgrading_hm/2026.10.1_to_2026.11/#choose-when-to-recreate-oss-library-apps).

-   **Brief database-management downtime.** While the pre-upgrade job copies your resources, the Beacon server is stopped, so you can't manage databases from the HM console or the API until HM 2026.11 is deployed — your Postgres clusters keep running and serving connections the whole time. The time depends on the number of backups that you have. See [What to expect during the upgrade](/edb-postgres-ai/current/hybrid-manager/using_hybrid_manager/upgrading_hm/2026.10.1_to_2026.11/#what-to-expect-during-the-upgrade).

For the full upgrade procedure, see [Upgrading from 2026.10.1 to 2026.11](/edb-postgres-ai/current/hybrid-manager/using_hybrid_manager/upgrading_hm/2026.10.1_to_2026.11/).
!!!
