This Innovation Release includes features and enhancements.

**Release date:** 12 Nov 2026

!!!important Before you upgrade to HM 2026.11
This release moves several components to the `edb-system` namespace, removes the `migration` scenario (deleting Migration Portal data), and briefly pauses database management during the upgrade. See [Upgrade considerations](#upgrade-considerations) before you begin.
!!!

!!!info Release cadence

HM now follows a dual release strategy: LTS and Innovation Releases. For details on this model, see [Hybrid Manager (HM) dual release strategy](/edb-postgres-ai/current/hybrid-manager/release_notes/#hybrid-manager-dual-release-strategy).

## Release highlights

-   **Metrics and alerting backend moves from Thanos to ClickHouse:** HM's monitoring and alerting now read from the ClickHouse-backed telemetry stack instead of Prometheus (Thanos) and LogQL, covering Kubernetes-based cluster metrics, bare metal infrastructure and database alerts, and log-based Postgres alerts, while preserving existing alerting behavior.

-   **HM chatbot available independently of the AI scenario:** The chatbot now has its own dedicated `chatbot` scenario, decoupled from the `ai` scenario and the inference service it previously required.

-   **Project-level resource quotas:** Platform admins can now set optional CPU, memory, and storage caps per project, enforced across cluster create, patch, scale, and autoscale operations.

-   **More disaster-recovery options:** You can now recover a control plane by installing a new HM with `spec.recoveryFrom`, restoring it from the old installation's object storage. The **Promote Replica** dialog also gains a Force Failover option for promoting a replica when the current primary is unreachable.

-   **New backup-failure alerts, extended to AWS RDS:** New alert definitions notify you when a scheduled backup fails or runs longer than expected, and existing CPU, memory, disk IOPS, connection, and rollback alerting now also covers AWS RDS instances.

## Release details

### Upgrade considerations

For the full upgrade procedure, see [Upgrading from 2026.10.1 to 2026.11](/edb-postgres-ai/current/hybrid-manager/using_hybrid_manager/upgrading_hm/2026.10.1_to_2026.11/). Here are some important considerations before you upgrade:

-   **The `edb-system` namespace.** Starting with HM 2026.11, the following components use the `edb-system` namespace instead of `default`:

    -   The Beacon server resources: your clusters, backups and backup schedules, locations, AI pipelines, and automations, plus the certificates and secrets that Beacon creates for each cluster.
    -   The app catalog: the OSS Library `PackageRepository` and the packages that it lists.
    -   The install secrets, such as `edb-object-storage`.

    The HM upgrade command automatically copies the Beacon server resources to `edb-system` and removes the old copies from `default`. It also automatically moves the `edb-object-storage` secret. You create the other install secrets, such as `hm-portal-bootstrap`, `langflow-secret`, and the `db-*` secrets, in `edb-system` before you upgrade. If you have scripts, monitoring, or `kubectl` commands that read these resources in `default`, update them to use `edb-system`.

-   **OSS Library apps.** The upgrade doesn't move OSS Library apps that you installed before it. They keep running, and EDB recommends that you delete and recreate them, preferably before the upgrade. See [Choose when to recreate OSS Library apps](/edb-postgres-ai/current/hybrid-manager/using_hybrid_manager/upgrading_hm/2026.10.1_to_2026.11/#choose-when-to-recreate-oss-library-apps).

-   **Brief database-management downtime.** While the pre-upgrade job copies your resources, the Beacon server is stopped, so you can't manage databases from the HM console or the API until HM 2026.11 is deployed — your Postgres clusters keep running and serving connections the whole time. The time depends on the number of backups that you have. See [What to expect during the upgrade](/edb-postgres-ai/current/hybrid-manager/using_hybrid_manager/upgrading_hm/2026.10.1_to_2026.11/#what-to-expect-during-the-upgrade).
