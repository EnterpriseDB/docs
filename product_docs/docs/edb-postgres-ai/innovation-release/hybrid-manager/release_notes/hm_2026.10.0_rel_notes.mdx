## Release highlights

-   **ClickHouse-backed observability stack:** Query Diagnostics (Query Stats, List Queries, Query Executed, Query Latency, and Wait States) now reads from ClickHouse instead of Postgres, with the `pg_stat_ch` extension automatically enabled for supported PSR and PGD clusters and Kubernetes events now ingested into ClickHouse through the OpenTelemetry collector. If you're upgrading from a release that used the `edb_stat_monitor` extension, you need to manually drop the extension after the upgrade.

-   **Plan for a restart with the latest Barman Cloud Plugin:** The Barman Cloud Plugin is updated to version 0.15.0, bringing significantly faster restore times for compressed backups. Applying this update triggers a restart of your Postgres clusters.

!!!note Postgres refers to all distributions supported by EDB

-   PostgreSQL
-   EDB Enterprise Postgres - formerly, EDB Postgres Extended Server (PGE)
-   EDB Enterprise Postgres (Oracle Compatible) - formerly, EDB Postgres Advanced Server (EPAS)
!!!

### Observability and monitoring

| Type | Description | Jira |
| ---- | ----------- | ---- |
| Enhancement | Added support for automatically enabling the `pg_stat_ch` extension for PSR and PGD clusters when it's available in the Postgres image, allowing supported clusters to collect additional query statistics. | UPM-119583 |
| Enhancement | Query diagnostics, including wait state statistics, now run on a ClickHouse-backed data path for improved performance and scalability. This enables richer wait-event sampling and more detailed query-diagnostics charts and drill-downs. | UPM-119586 |
| Enhancement | Added support for ingesting Kubernetes events into ClickHouse through the OpenTelemetry collector. Log entries in `otel_logs` are now tagged with a `log_source` resource attribute (`k8s_event` or `k8s_pod`) so you can distinguish and query or alert on Kubernetes events separately from pod logs. | UPM-139520 |
| Change | Migrated query diagnostics and alerting to a ClickHouse-backed observability stack. Query Diagnostics, including the Query Stats, List Queries, Query Executed, Query Latency, and Wait States views, now reads from ClickHouse instead of Postgres, improving the performance, reliability, and scalability of query and wait diagnostics data. Query statistics, query text, and wait state data now reach the platform through OTLP ingestion of `pg_stat_ch` and `edb_wait_states` data, replacing the previous stats-collector pipeline; as a result, the stats-collector service and its associated database are no longer deployed as part of Hybrid Manager. If you're upgrading from a release that used the `edb_stat_monitor` extension, you need to manually drop the extension after the upgrade. Configuration and security recommendations are now generated by an in-process daemon instead of scheduled Kubernetes jobs running the legacy URM tool, improving reliability and maintainability without changing how recommendations appear in the health report. Alerting and recording rule management for metrics and logging has been consolidated into a single new `upm-ruler` component, replacing the separate Thanos Ruler and Loki Ruler components; these alerting components are disabled by default in the observability scenario and can be enabled by setting the component's `enabled` configuration parameter to `true`. Additionally, on a federation secondary cluster, ClickHouse, Keeper, and the ClickHouse operator workloads are no longer deployed by default, reducing idle resource usage — set `componentsParameters.upm-clickhouse.enableOnSecondary` to `true` to run the full ClickHouse stack on a secondary. | UPM-125640, UPM-119581, UPM-121433, UPM-121434, UPM-125658, UPM-125659, UPM-125972, UPM-139517, UPM-139787, UPM-139813 |
| Change | Removed the query latency chart from the **Monitoring** overview. Query latency data is still available in **Query Diagnostics**. | UPM-139714 |
| Bug fix | Fixed an issue whereby the `InternalDBPrimaryServiceUnavailable` alert fired constantly because it referenced the removed `upm-api-stats-collector` component. Alert rules and references related to this component were removed from monitoring configuration. | UPM-139968 |
| Bug fix | Fixed an issue whereby the `edb_wait_states` and query latency monitoring queries failed with a `function does not exist` error on CloudNativePG (CNPG) clusters that pin the database search path for security reasons, which caused repeated errors in database logs and loss of related metrics. | UPM-139775 |
| Bug fix | Fixed an issue whereby `fluent-bit-federated` and `thanos-query-federated` pods could crash-loop on multi-data-center deployments when the SPIFFE SVID or mTLS certificate wasn't yet available at startup. Both workloads now wait for the certificate to be present before starting. | UPM-138287 |
| Bug fix | Fixed an issue whereby ClickHouse didn't trust a custom S3 CA bundle when object storage used a private certificate authority. Previously, the certificate verification check failed during startup, causing the pod to restart continuously and never become ready. This affected air-gapped or on-premises installations using a private-CA S3-compatible object store. | UPM-139990 |

### Migrations

| Type | Description | Jira |
| ---- | ----------- | ---- |
| Bug fix | Fixed an issue in the Migration Portal schema assessment whereby reserved keywords, such as `JOIN`, used as unquoted identifiers in SELECT lists and related contexts caused syntax errors in the migrated DDL. A new repair handler, `ERH-3018`, now converts the Oracle keyword `JOIN` to the quoted lowercase name `"join"` when it's used unquoted as a name, for example, as a column, parameter type, table alias, or object type attribute. | MIG-4786 |
| Bug fix | Fixed an issue in the Migration Portal whereby `TRUNC()` date expressions using the Oracle `FM` fill-mode modifier (for example, `TRUNC(column, 'fmmm')`) generated invalid EPAS code that failed at runtime with an invalid format error. A new repair handler, `ERH-3019`, now strips the `FM` modifier during migration, producing a valid EPAS-compatible format unit. | MIG-12552 |
