## Release highlights

-   **New ClickHouse-backed observability stack:** HM now ships with an embedded ClickHouse deployment, enabled automatically as part of the observability scenario, with no separate installation or configuration required. **Query Diagnostics** (**Query Stats**, **List Queries**, **Query Executed**, **Query Latency**, and **Wait States**) now reads from ClickHouse instead of Postgres, with the `pg_stat_ch` extension automatically enabled for supported PSR and PGD clusters and Kubernetes events now ingested into ClickHouse through the OpenTelemetry collector. The `edb_stat_monitor` extension is retained for now and continues to be used internally. However, it's scheduled for removal in a future release.

-   **Barman Cloud Plugin update:** The Barman Cloud Plugin is updated to version 0.15.0, bringing significantly faster restore times for compressed backups. Because this version bump changes the plugin's sidecar image, upgrading to HM 2026.10 restarts every Postgres cluster in your estate.

-   **AI DDL repair in Migration Portal:** Migration Portal in HM can now automatically suggest a fix for a DDL object that fails schema assessment. Review the suggestion and **Accept & Reassess**, **Edit**, **Regenerate**, or **Reject** it. Requires [AI Copilot](/edb-postgres-ai/current/hybrid-manager/using_hybrid_manager/enabling_migration_copilot/) to be enabled.

!!!important HM 2026.10 ships operandSet 1.3.0
HM 2026.10 ships operand images from [operandSet](/edb-postgres-ai/current/hybrid-manager/using_hybrid_manager/image-management/custom-operand-images/) 1.3.0. If your `operandSetVersions` configuration is still pinned to an earlier operand set (for example, `1\.2\.[0-9]+` from IRs 2026.7-2026.9), add `1\.3\.[0-9]+` to the whitelist alongside it — don't replace it yet. Removing the `1\.2\.[0-9]+` pattern before every cluster has moved to a 1.3.x operand image makes those clusters' current images undiscoverable and breaks the Major/Minor upgrade dialog. Once every cluster in your estate is running a 1.3.x operand image, you can remove the old regex. See [Configure the beacon agent operand set](/edb-postgres-ai/current/hybrid-manager/install/install_guide/environment_prep/#configure-the-beacon-agent-operand-set) for details.
!!!

!!!note Query Diagnostics after this upgrade

-   **Existing HM-managed clusters:** The new operand image ships with `pg_stat_ch` available, but moving an existing cluster to it doesn't automatically create the extension. Manually run `CREATE EXTENSION IF NOT EXISTS pg_stat_ch WITH SCHEMA edb_internals;` on every database you want to monitor.
-   **Self-managed clusters** (external CloudNativePG or bare-metal installations): Require additional manual steps to install and enable `pg_stat_ch`. See [Installing and configuring pg_stat_ch](/clickhouse/latest/monitoring_postgres/#installing-and-configuring-pg_stat_ch).
-   **Query table:** Temporarily shows query text capped at 2 KB, can't be filtered by table name, and no longer shows the `new` label for recently seen queries. These will be addressed in a future release.

### Migrations

| Type | Description | Jira |
| ---- | ----------- | ---- |
| Enhancement | Added **AI DDL repair** to Migration Portal in HM. When a DDL object fails schema assessment, Migration Portal can automatically suggest a fix that you can accept, edit, regenerate, or reject. | Enhancement | Added a new repair handler, `ERH-3019`, which removes the Oracle `FM` (fill mode) modifier from the format string of a `TRUNC` date function, for example, `TRUNC(hire_date, 'fmmm')` becomes `TRUNC(hire_date, 'mm')`. Oracle ignores the `FM` modifier in `TRUNC` date format strings, but EDB Postgres Advanced Server rejects it with an `invalid format parameter` error. For a functional index, the error occurs on the first insert or index rebuild rather than when the index is created. | MIG-12552 |
