Released: 08 Oct 2026

Enhancements and other changes in Migration Portal 5.2.0 include the following:

| Type                 | Description                                                                                                                                                                                    |
|----------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Enhancement          | The EDB DDL Extractor can now append an optional report of the objects that it doesn't extract, such as unsupported object types, invalid objects, and wrapped PL/SQL, to the extracted DDL file. Use the report to estimate the manual migration work that remains. The report is off by default and doesn't change the DDL that the extractor generates. See [Using EDB DDL Extractor](/migration_portal/latest/04_mp_migrating_database/01_mp_schema_extraction/edb_ddl_extractor/#report-of-objects-that-arent-extracted). |
| Enhancement          | Added instructions for importing an offline migration while preserving Oracle object ownership. Instead of running the `<ProjectName>_ALL_OBJECTS.sql` file as a superuser, which makes the superuser the owner of every object, you can use the `$GLOBAL_OBJECTS.sql` file and the per-schema SQL files so that each schema user owns its objects. See [Import the schema into your target database](/migration_portal/latest/04_mp_migrating_database/03_mp_schema_migration/#import-the-schema-into-your-target-database). |
| Enhancement          | Added a new repair handler, ERH-3019, which removes the Oracle `FM` (fill mode) modifier from the format string of a `TRUNC` date function, for example, `TRUNC(hire_date, 'fmmm')` becomes `TRUNC(hire_date, 'mm')`. Oracle ignores the `FM` modifier in `TRUNC` date format strings, but EDB Postgres Advanced Server rejects it with an `invalid format parameter` error. For a functional index, the error occurs on the first insert or index rebuild rather than when the index is created. |
