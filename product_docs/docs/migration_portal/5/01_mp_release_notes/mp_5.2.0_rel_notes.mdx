Released: 08 Oct 2026

Enhancements, bug fixes, and other changes in Migration Portal 5.2.0 include the following:

| Type                 | Description                                                                                                                                                                                    |
|----------------------|--------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| Enhancement          | The EDB DDL Extractor can now append an optional report of the objects that it doesn't extract, such as unsupported object types, invalid objects, and wrapped PL/SQL, to the extracted DDL file. Use the report to estimate the manual migration work that remains. The report is off by default and doesn't change the DDL that the extractor generates. See [Using EDB DDL Extractor](/migration_portal/latest/04_mp_migrating_database/01_mp_schema_extraction/edb_ddl_extractor/#report-of-objects-that-arent-extracted). |
| Enhancement          | Added step-by-step instructions for importing an offline migration while preserving Oracle object ownership. Instead of running the `<ProjectName>_ALL_OBJECTS.sql` file as a superuser, which makes the superuser the owner of every object, you can use the `$GLOBAL_OBJECTS.sql` file and the per-schema SQL files so that each schema user owns its objects. See [Import the schema into your target database](/migration_portal/latest/04_mp_migrating_database/03_mp_schema_migration/#import-the-schema-into-your-target-database). |
| Bug&nbsp;fix         | Fixed an issue in which Migration Portal generated invalid functional indexes for Oracle `TRUNC` date functions that use the `FM` (fill mode) format modifier, such as `TRUNC(hire_date, 'fmmm')`. EDB Postgres Advanced Server rejects the `FM` modifier with an `invalid format parameter` error on the first insert or index rebuild. A new repair handler, ERH-3019, removes the `FM` modifier from the format string, for example, `'fmmm'` becomes `'mm'`. |
