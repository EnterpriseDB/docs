# Conflict resolution

<div id="conflict_resolution" class="registered_link"></div>

In certain situations, synchronization replication can result in data conflicts arising from the row changes that took place on different primary nodes.

Conflict resolution concerns the types of conflicts that might occur, the strategies for dealing with conflicts, and the options available for automatically resolving such conflicts.

- [Configuration parameter and table setting requirements](https://www.enterprisedb.com/docs/eprs/latest/06_mmr_operation/06_conflict_resolution/01_configuration_para_andtable_setting/): Depending on the multi-master replication system environment, you might need certain configuration settings for the conflict resolution process to operate properly.
- [Conflict types](https://www.enterprisedb.com/docs/eprs/latest/06_mmr_operation/06_conflict_resolution/02_conflict_types/): The types of conflicts can be summarized as follows:
- [Conflict detection](https://www.enterprisedb.com/docs/eprs/latest/06_mmr_operation/06_conflict_resolution/03_conflict_detection/): When synchronization replication occurs, either on demand or on a scheduled basis, each of the primary node changes is pushed to the other primary nodes. See Multi-master parallel replication for information on this process.
- [Conflict-resolution strategies](https://www.enterprisedb.com/docs/eprs/latest/06_mmr_operation/06_conflict_resolution/04_conflict_resolution_strategies/): Several built-in conflict-resolution options are available to support automatic conflict resolution. The conflict-resolution options apply to update/update and delete/delete conflicts.
- [Conflict prevention – uniqueness case](https://www.enterprisedb.com/docs/eprs/latest/06_mmr_operation/06_conflict_resolution/05_conflict_prevention_uniquness/): Since there's no automatic built-in resolution strategy for the uniqueness conflict, you can use strategies to avoid this problem. These strategies are implemented by the DBA. This discussion is based on a realm of numeric values generated by a sequence such as for a unique primary key.
- [Conflict prevention with an MMR-ready sequence](https://www.enterprisedb.com/docs/eprs/latest/06_mmr_operation/06_conflict_resolution/06_conflict_prevention_mmr_ready/): To prevent uniqueness conflicts in a multi-master replication system, you can use an MMR-ready sequence to generate unique identifiers for each row of publication tables that doesn't have an inherent, unique identifier.
- [Automatic conflict-resolution example](https://www.enterprisedb.com/docs/eprs/latest/06_mmr_operation/06_conflict_resolution/07_auto_conflict_resolution_eg/): This example shows a scenario where a transaction change originating from the first primary node is successfully applied to the second primary node but conflicts with the third primary node. The conflict is resolved automatically.
- [Custom conflict handling](https://www.enterprisedb.com/docs/eprs/latest/06_mmr_operation/06_conflict_resolution/08_custom_conflict_handling/): For update/update conflicts, custom conflict handling uses a PL/pgSQL function to resolve the conflict. If you're using EDB Postgres Advanced Server, you can use a Stored Procedure Language (SPL) function. When an update/update conflict is detected, the function is called. How you set a certain parameter in the function determines the outcome of the conflict.
- [Manual conflict resolution for the trigger-based method](https://www.enterprisedb.com/docs/eprs/latest/06_mmr_operation/06_conflict_resolution/09_manual_conflict_resolution_trigger_based_method/): See Manual Conflict Resolution for the Log-Based Method for information on manual conflict resolution for multi-master replication systems configured with the log-based method of synchronization replication.
- [Manual conflict resolution for the log-based method](https://www.enterprisedb.com/docs/eprs/latest/06_mmr_operation/06_conflict_resolution/10_manual_conflict_resolution_log_based_method/): See Manual conflict resolution for the trigger-based method for information on manual conflict resolution for multi-master replication systems configured with the trigger-based method of synchronization replication.
