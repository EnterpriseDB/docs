# EDB OCL Connector

The EDB OCL Connector provides an API similar to the Oracle Call Interface. You can use EDB's OCL Connector to compile applications that are written to use the Oracle Call Interface to interact with an EDB Postgres Advanced Server database server.

> **Note**
>
> EDB doesn't support the use of the Open Client Library with Oracle Real Application Clusters (RAC) and Oracle Exadata. These Oracle products aren't evaluated or certified with this EDB product.

- [Release notes](https://www.enterprisedb.com/docs/ocl_connector/14/01_ocl_release_notes/): The EDB OCL Connector provides an API similar to the Oracle Call Interface.
- [Product compatability](https://www.enterprisedb.com/docs/ocl_connector/14/02_supported_platforms/): The EDB OCL Connector is certified with EDB Postgres Advanced Server version 11 and later. The EDB Connector is supported on the same platforms as EDB Postgres Advanced Server. See Platform Compatibility for details.
- [libpq cross-version compatibility](https://www.enterprisedb.com/docs/ocl_connector/14/03_libpq_compatibility/): EDB OCL installation always uses the latest libpq. The different scenarios supported under libpq cross-version compatibility are as following:
- [Installing](https://www.enterprisedb.com/docs/ocl_connector/14/installing/): Select a link to access the applicable installation instructions:
  - [On Linux ppc64le](https://www.enterprisedb.com/docs/ocl_connector/14/installing/linux_ppc64le/)
  - [On Linux x86](https://www.enterprisedb.com/docs/ocl_connector/14/installing/linux_x86_64/)
  - [On Linux ARM64](https://www.enterprisedb.com/docs/ocl_connector/14/installing/linux_arm64/)
  - [On Windows](https://www.enterprisedb.com/docs/ocl_connector/14/installing/windows/)
  - +1 more
- [Open Client Library](https://www.enterprisedb.com/docs/ocl_connector/14/04_open_client_library/): The Open Client Library provides application interoperability with the Oracle Call Interface. An application that was formerly locked in can now work with either an EDB Postgres Advanced Server or an Oracle database with minimal to no changes to the application code.
  - [Forming a connection string](https://www.enterprisedb.com/docs/ocl_connector/14/04_open_client_library/02_forming_a_connection_string/)
  - [Compiling and linking a program](https://www.enterprisedb.com/docs/ocl_connector/14/04_open_client_library/03_compiling_and_linking_a_program/)
  - [Ref cursor support](https://www.enterprisedb.com/docs/ocl_connector/14/04_open_client_library/04_ref_cursor_support/)
  - [OCL function reference](https://www.enterprisedb.com/docs/ocl_connector/14/04_open_client_library/05_ocl_function_reference/)
  - +3 more
- [Generating the OCL trace](https://www.enterprisedb.com/docs/ocl_connector/14/05_generating_the_ocl_trace/): The OCL tracing option logs direct communication (queries, updates, etc.) with the backend in the specified OCIDEBUGLOG file. It also logs the functions/APIs that were invoked. The trace files are generated in the default working directory (ocilogfilename). If you append the path with a file name (directory path/ocilogfilename), then the trace files are generated at specific location.
- [Using SSL](https://www.enterprisedb.com/docs/ocl_connector/14/06_using_ssl/): EDB Postgres Advanced Server provides native support for using SSL connections to encrypt client/server communications for increased security. In OCL, it's controlled by setting the sslmode parameter to verify-full or verify-ca and providing the system with a root certificate to verify against.
- [Scram compatibility](https://www.enterprisedb.com/docs/ocl_connector/14/07_scram_compatibility/): The EDB OCL driver provides SCRAM-SHA-256 support for EDB Postgres Advanced Server version 11 and later. This support is available from EDB OCL 11.0.1 release and later.
