## Background

[Markdown](https://commonmark.org/) is a source format for rich text which has been popular for the last couple of decades for human-created content on the Web. Originally created by John Gruber, its use on sites like Reddit, Stack Overflow and GitHub introduced a great many people to its syntax, which in turn gave LLMs strong support for working with it.

EDB Docs is written in [MDX](https://mdxjs.com/), a near superset of Markdown and JSX. MDX allows rich components, and adds composition: a page or snippet can be reused in several topics.

Most LLM systems can convert a rendered HTML page to Markdown themselves, but at a cost: the full weight of the rendered page still has to be downloaded and processed, and some metadata is lost on the way. To reduce that overhead and improve fidelity, EDB Docs generates normalized Markdown for every page and serves it on request.

## Requesting Markdown from EDB Docs

The Markdown for any page under https://www.enterprisedb.com/docs/ can be retrieved in either of two ways:

- **Send an `Accept: text/markdown` header** with the request for the page's usual URL. The response is `text/markdown`.
- **Add `.md` (or `.mdx`) to the page's URL**: `https://www.enterprisedb.com/docs/pgd/latest/planning.md`. `.../planning/.md` works too, and so does `index.md` for a section's index page. The response is `text/plain`.

A Markdown request for the site's root, https://www.enterprisedb.com/docs/, returns [the llms.txt directory](#the-llmstxt-directory) instead. A URL that redirects, such as an old path or a numbered URL for a product's latest version, redirects as the HTML page does, and the redirected request returns Markdown. A URL that isn't a page gets the site's usual response.

### What each page contains

Each page begins with a YAML frontmatter block:

- `title`: the page's title.
- `description`: a short summary of the page, when it has one (about a quarter of pages do).
- `product`: the name of the product or section the page belongs to.
- `version`: the product version the page documents, on every page of a versioned product, the latest version's included. It's the precise version where the docs give one (`6.5.0`), else the version in the page's source path (`17`).
- `url`: the page's URL on the site.
- `lastModified`: when the page's source last changed, as an ISO 8601 date and time.

Next come the page's title, as a heading, and its content, normalized from MDX:

- Product names and versions written as template expressions are filled in.
- Every link is absolute. A link to another page goes to that page on the site, and an image or downloadable file to its copy on GitHub ([below](#under-the-hood)).
- Content shared between pages is included where it's used.
- Tabbed content becomes a heading per tab, notes and warnings become block quotes, and collapsible sections stay HTML `<details>` blocks.

An index page ends with links to the topics in its section, as the site shows them: grouped under the same section headings as the site's navigation, each with its description. An author can turn this off for a page, usually one whose text already links to all its topics. Every page ends with a link to the llms.txt directory.

## The llms.txt directory

https://www.enterprisedb.com/docs/llms.txt is a directory of the site's top-level content for LLM agents: each product's main topics and versions, and how to retrieve any page as Markdown. It's generated by each production build and deployed with the rest of the site, so it stays up to date with the content.

## Under the hood

This branch is an orphan branch, with no history shared with the rest of the repository. A change to `main` triggers both the site's production build and the generation of this Markdown: the Markdown for every page is generated from that commit, and this branch is replaced with the result. If generation fails, the branch keeps the previous version. Each page is one file, named for its URL: `/docs/pgd/latest/planning/` is `pgd/latest/planning.md`. A product's latest version is under `latest/` only.

A small edge function on the site's Netlify deployment serves each request from this branch, handling caching, redirects and the site's access rules. For redirects and missing pages it leaves the request to the site: a URL with no file here gets the site's usual response, and the redirected request comes back for its Markdown.

Images and other linked files aren't copied here. Each link points at the file in the commit this branch was made from, as GitHub serves it: from media.githubusercontent.com for a file stored in Git LFS, and from raw.githubusercontent.com for any other.
